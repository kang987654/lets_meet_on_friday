# scratch/lab — 실기기 없이 재현하는 실험실

실기기를 꽂지 않고 앱과 같은 조건으로 모델을 돌린다. 2026-08-12 Galaxy S25 Ultra 검증에서
나온 결함들을 여기서 재현·판정했다.

## 준비 (한 번)

```bash
./gradlew :app:testDebugUnitTest --tests '*PromptFixtureExport*'
```

앱의 **실제** 시스템 지시와 전사 지시를 `fixtures/` 로 내보낸다. 이걸 안 돌리면 실험이 낡은
손 사본으로 돌아 앱과 다른 것을 측정한다 — 실제로 그런 상태였다(사본이 0.8.6 시절에 멈춰
`search_memory` 트리거가 없었다).

확인:

```bash
../.venv/Scripts/python.exe device_fixture.py
```

## fixtures/

| `system_instruction.txt` | 앱의 실제 시스템 지시 | `PromptFixtureExportTest` |
| `tools.txt` | 선언하는 툴 5종 | 같음 |
| `turn_reminder.txt` | 사용자 턴 앞에 붙는 툴 지침 | 같음 |
| `transcribe_system.txt`, `transcribe_user.txt` | 전사 프롬프트 | 같음 |
| `voice_input_tts.wav` | 한국어 3.4초 (16kHz mono 16bit) | Windows SAPI 합성 |
| `voice_silence.wav` | 무음 2초 | 생성 |

기기를 다시 꽂게 되면 `bash pull_device_state.sh` 한 번으로 DB·녹음·logcat 을 갱신한다.

> `voice_input.wav`(실제 녹음)는 세션 중 USB 가 빠져 회수하지 못했다. TTS 합성본은 배선과
> 프롬프트 검증에 충분하지만 **사람 목소리의 전사 정확도는 이것으로 알 수 없다.**
>
> 픽스처에는 사용자의 실제 대화(비밀번호 포함)가 들어 있다. `scratch/` 는 `.gitignore`
> 대상이며 이 디렉터리 밖으로 내보내지 않는다.

## 하네스

- `kosmos_lab.py` — 엔진을 한 번 올리고 여러 조건을 돌린다.
  - `Lab.run(...)` 대화를 새로 만들어 한 번 (앱의 재생성 경로)
  - `Lab.conversation(...)` 한 대화에 여러 번 (앱 기본 경로, ADR-010)
  - `audio=True` 오디오 백엔드, `max_num_tokens=` KV 용량
  - 시스템 지시 기본값은 **픽스처**, 없으면 손 사본으로 폴백
- `device_fixture.py` — DB → `L.Message` 목록. `mode="terse"` 는 어시스턴트 답변만 대체해
  **모방과 길이를 분리**한다. `before=` 로 재현할 질문 직전까지 자른다.

## 주의

**파이썬은 0.15.0, 앱 AAR 은 0.14.0 이다.** 프롬프트·모델 성향 실험에는 무방하지만 런타임
버그 재현에서는 이 차이 자체가 가설이다 — exp15 가 정확히 그 경우다.

`from __future__ import annotations` 를 넣지 말 것. 타입 힌트가 문자열이 되어
`tool_from_function` 의 스키마 생성이 전부 string 폴백으로 떨어진다(실측).

## exp25·exp26 — 툴 왕복 비용과 예산 검증 (ADR-020)

`exp25_tool_roundtrip_cost.py` 가 **문제**를, `exp26_budget_after_fix.py` 가 **고친 뒤**를 잰다.

exp25 의 결론은 두 줄이다.

- **레버는 툴 결과 하나다.** 히스토리 0개에서도 위키 5000자 한 번에 4,103 으로 넘었다(7 초과).
  히스토리 15개로 줄여도 4,830 이라 축소로는 풀리지 않는다.
- **`GENERATION_HEADROOM = 768` 은 충분했다.** 툴 결과를 뺀 왕복 증가는 62~83 토큰뿐이다.

exp26 은 실전 조건(`max_num_tokens=4096`)에서 같은 왕복을 **실제로 돌린다.** 오류가 나면 그것이
판정이고, 8192 로도 함께 돌려 얼마나 남는지를 본다 — 4096 만 쓰면 초과 시 오류가 나서 "얼마나
부족한가" 를 알 수 없다. 대조군(예전 5000자 상한)을 같은 프리필에서 함께 돌리는 것이 핵심이다:
프리필이 동일한데 결과만 바꿔 초과가 재현되면 원인이 툴 결과에 귀속된다.

두 스크립트의 상수는 `Constants.kt` 를 손으로 옮긴 것이다. 어긋나면 실험이 무의미해지므로
예산을 바꿀 때 exp26 머리의 상수 블록도 함께 본다.

## exp33 — 에피소드 기억 실현성 (2026-08-15)

설계 원칙 "세션은 UX 가 아니라 저장 개념" (에피소드 자동 분절 → oneShot 요약 문서 → 검색 회수)
의 미지수 3개를 실기기 픽스처로 판정했다.

| 단계 | 결과 |
|---|---|
| ① 분절 (시간 간격 30분) | 79개 메시지 → **에피소드 9개**, 전부 주제 일관 (육안 판정) |
| ② 요약 (oneShot, 제목/태그/요약) | **형식 준수 9/9**, 제목 품질 양호 |
| ③ 회수 (모델 검색어 확장 + 바이그램 매칭) | **recall@1 = 16/16** (바꿔 말하기 포함) |

주의해서 읽을 것:
- 코퍼스가 9문서라 recall@3 은 무의미하다(상위 3 = 전체의 1/3) — 의미 있는 숫자는 @1.
- 질문 셋은 내용을 아는 사람이 만들었다. 바꿔 말하기(자물쇠↔비밀번호, 환각↔지어냄)를
  섞어 완화했지만, 실사용 질문 분포와는 다르다.
- 그래도 판정에는 충분하다: **임베딩 없이(FTS 대용 바이그램 + 모델 양끝 정규화) 이 규모에서
  회수가 성립한다** — C3(임베딩) 게이트 유지, C′ 설계 진행 가능.

모델 확장의 실제 기여 예: "자물쇠 번호" → 확장에 "비밀번호" 포함 → 요약 문서와 매칭.
"지어내서 답한 적" → "환각 현상" 생성 → 환각 지적 에피소드 회수.
