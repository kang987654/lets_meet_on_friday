## 1. Product Overview

**Local Friday**는 Android 스마트폰에서 로컬 LLM을 사용하여 동작하는
오프라인 우선 개인 AI 비서 앱이다.

사용자의 일정, 메모, 문서, 음성, 이미지를 외부 서버로 전송하지 않고
기기 내에서 처리한다. 대화 기반으로 개인 비서처럼 동작하며,
쓰기 작업은 반드시 사용자 승인을 거친다.

**핵심 차별점**

| 차별점 | 설명 |
|---|---|
| 완전 오프라인 처리 | v0(MVP) 기본 기능은 네트워크 없이 동작 |
| 질문 단위 검색 | v1부터 세션 전체가 아닌 특정 질문에만 검색 허용 |
| 승인 기반 쓰기 | 캘린더 저장 등 쓰기 작업은 사용자 확인 후 실행 |
| 5계층 로컬 메모리 | v0에서 Profile / Conversation / 필수 Audit을 시작하고 v1에서 Task / Knowledge / 전체 Audit으로 확장 |
| 모델 교체 가능 구조 | 특정 모델에 종속되지 않는 추상화 설계 |
| Android 우선 + 확장 가능 | Android v0 이후 Windows 확장 고려 구조 |

## 2. Problem Statement

### 현재 문제

클라우드 기반 AI 비서는 다음 문제를 가지고 있다.

**개인정보 유출 위험**  
사용자가 일정, 메모, 문서, 음성을 입력하면
해당 데이터가 외부 API 서버로 전송된다.
고급 사용자는 이를 인지하고 있으나 대안이 없다.

**분절된 비서 경험**  
검색 / 실행 / 기억이 별개의 앱과 서비스로 분리되어 있다.
"오늘 일정 요약하고 내일 병원 예약 잡아줘"와 같은
연속 작업을 하나의 인터페이스에서 처리할 수 없다.

**통제권 부재**  
AI가 어떤 작업을 수행하는지 사용자가 확인하거나
거부할 수 있는 구조가 없다.
실행 이력도 기록되지 않는다.

**오프라인 환경 미지원**  
네트워크 없이는 대부분의 AI 기능이 작동하지 않는다.

## 3. Target Users

### 1차 사용자 (v0 MVP)

- **대상**: 본인 1인 사용자
- **기기**: Samsung Galaxy S25 Ultra
- **특성**:
  - 로컬 실행 환경을 선호하는 기술 이해도 높은 사용자
  - 외부 API로의 개인정보 전송을 최소화하고자 함
  - AI를 실용적인 보조 도구로 활용하고자 함
  - APK 직접 설치(sideload) 방식에 거부감 없음

### 향후 사용자 (v2 이후)

- Windows PC 사용자 (동일 메모리 구조 공유 목적)
- 개인정보 보호에 민감한 전문직 사용자

## 4. User Pain Points

| # | Pain Point | 발생 상황 | 현재 해결 방법의 한계 |
|---|---|---|---|
| P1 | 개인 데이터가 외부로 전송됨 | AI 비서에 일정/메모/문서 입력 시 | 클라우드 AI는 구조적으로 해결 불가 |
| P2 | 맥락을 기억하지 못함 | 세션이 끊기면 이전 대화 내용 소실 | 대부분의 앱은 세션 내 기억만 지원 |
| P3 | 검색/일정/메모가 분리됨 | 복합 작업 시 앱을 여러 개 전환 | 통합 인터페이스 앱 없음 |
| P4 | AI가 무엇을 실행하는지 모름 | 일정 생성, 파일 접근 등 | 실행 이력 없음, 취소 불가 |
| P5 | 네트워크 없으면 AI 사용 불가 | 이동 중, 오프라인 환경 | 로컬 실행 앱이 없거나 불편함 |
| P6 | 음성 입력이 채팅과 분리됨 | 손을 사용하기 어려운 상황 | STT 앱과 AI 앱이 별개 |

## 5. Goals

### 제품 목표

**G1. 오프라인 우선 개인 AI 비서 구현**  
기본 기능은 네트워크 없이 동작해야 한다.  
v1 검색 기능만 사용자가 명시적으로 허용한 질문에 한해 네트워크를 사용한다.

**G2. 개인정보를 기기 밖으로 내보내지 않음**  
기본 설정에서 모든 처리는 로컬에서 완결된다.  
v1 검색은 사용자가 명시적으로 허용한 질문에만 외부 검색을 허용한다.

**G3. 사용자 승인 기반 실행**  
캘린더 쓰기 등 외부 영향을 주는 작업은
반드시 사용자가 확인하고 승인한 후 실행된다.

**G4. 개인 맥락을 기억하는 비서 경험**  
v0에서는 프로필, 대화, 필수 감사 이벤트를 로컬에 저장한다.  
v1에서는 작업, 지식, 전체 감사 로그까지 확장하여
다음 대화에서 이전 맥락을 활용할 수 있다.

**G5. 확장 가능한 구조**  
모델 교체, Windows 앱 확장, 추가 도구 연동이
최소한의 변경으로 가능한 구조를 갖춘다.

### v0(MVP) 목표

- Galaxy S25 Ultra에서 APK sideload 방식으로 구동 가능
- 로컬 모델 기반 텍스트 채팅 응답 가능
- Push-to-talk 음성 입력 후 동일 채팅 흐름으로 처리 가능
- 스크린샷 / 문서 이미지 기반 질의응답 가능
- 캘린더 조회 및 일정 생성 초안 → 사용자 승인 → 저장 가능
- 메모 / 문서 이미지 요약 가능
- Profile / Conversation 중심의 로컬 메모리 저장 가능
- 승인 / 오류 / 모델 실행 / 도구 호출 등 필수 감사 이벤트 저장 가능

> 주의:
> v0에서 "문서 요약"은 PDF/DOC 파일 자체를 직접 파싱하는 기능이 아니라,
> 사용자가 첨부한 문서 스크린샷 또는 문서 이미지에 대한 요약 기능을 의미한다.
> 문서 파일 직접 파싱 및 구조 분석은 v1 이후 또는 별도 확장 범위로 본다.

## 6. Non-Goals

v0(MVP)에서 명시적으로 구현하지 않는 항목이다.  
이 목록은 범위 논쟁을 방지하기 위한 확정 결정이다.

| 제외 항목 | 이유 |
|---|---|
| 항상 듣기 (Always-on STT) | 배터리/개인정보 문제, v0 과잉 설계 |
| 완전 자율 실행 | 사용자 승인 없는 쓰기 실행은 정책 위반 |
| 세션 단위 검색 허용 | v1에서도 질문 단위 ON만 허용 — 정책 결정 사항 |
| 클라우드 동기화 | 오프라인 우선 원칙 위반 |
| Windows 앱 구현 | v2 범위 |
| 영상(Video) 직접 입력 | v0 범위 초과 |
| 다중 사용자 계정 | 1인 사용자 대상 v0 |
| 데이터 삭제 기능 | v0에서 기본 금지, 추후 검토 |
| 클라우드 GPT / Claude 연동 | v0에서 미사용, 향후 선택 옵션 |
| 벡터 DB 기반 로컬 RAG | v2 이후 |
| 실시간 스트리밍 응답 | v0에서는 구현하지 않음. 인터페이스만 확장 가능하게 두고 v1에서 구현 |
| 음성 출력 (TTS) | v0 범위 초과 |
| 문서 파일 직접 파싱 기반 요약 | v0 범위 초과 |

## 7. Core Features

### F1. 로컬 채팅 (v0 MVP)

**목적**: 텍스트 기반 개인 AI 비서 응답 제공

**사용 시나리오**
- 사용자가 메시지를 입력한다
- 최근 대화와 관련 메모리를 결합하여 로컬 모델이 응답을 생성한다
- 응답과 대화 내용이 로컬에 저장된다

**입력**: 텍스트, 선택적 이미지 첨부  
**출력**: 비서 응답 텍스트, 선택적 액션 카드

**정책**
- 외부 API 호출 없음
- 빈 입력 전송 불가
- 동일 요청 중복 전송 차단 (in-flight 상태 관리)

---

### F2. Push-to-Talk 음성 입력 (v0 MVP)

**목적**: 음성을 텍스트로 변환 후 채팅과 동일한 흐름으로 처리

**사용 시나리오**
- 우하단 FAB 버튼을 탭하여 녹음 시작
- 음성 인식 결과 텍스트를 확인
- 전송 또는 취소를 선택
- 전송 시 일반 채팅 메시지와 동일하게 처리

**입력**: 마이크 스트림  
**출력**: 변환된 텍스트 → 채팅 입력으로 전달

**정책**
- 오프라인 STT 우선 처리
- STT 실패 시 텍스트 직접 입력으로 fallback
- 마이크 권한 미허용 시 권한 요청 → 거부 시 텍스트 입력 안내
- transcript는 자동 전송하지 않고 사용자 확인 후 전송

---

### F3. 이미지 입력 (v0 MVP)

**목적**: 스크린샷 / 문서 이미지 기반 질의응답 및 요약

**사용 시나리오**
- 첨부 버튼으로 갤러리 또는 카메라에서 이미지 선택
- 이미지 프리뷰 확인 후 질문 입력
- 멀티모달 응답 수신 (요약 / 설명 / 할 일 추출)

**입력**: 이미지 URI + 질문 텍스트  
**출력**: 이미지 기반 요약 / 설명 / 액션 아이템

**제한 사항**
- 지원 형식: JPEG, PNG, WEBP
- 최대 파일 크기: 10MB
- 장축 최대 1024px로 자동 리사이즈 처리
- 형식 오류 / 크기 초과 시 명확한 오류 메시지 제공

**정책**
- v0에서 이미지 질의응답의 표준 진입점은 별도 이미지 입력 흐름이다
- `SendChatMessage`의 이미지 필드는 내부 통합 DTO 호환용으로만 유지할 수 있다

---

### F4. 캘린더 조회 (v0 MVP)

**목적**: 로컬 캘린더 일정 읽기 및 AI 요약

**사용 시나리오**
- 일정 탭 진입 시 오늘 / 이번 주 일정 자동 조회
- AI가 일정 목록을 자연어로 요약하여 표시

**입력**: 날짜 범위  
**출력**: 일정 목록 + 요약 텍스트

**정책**
- 캘린더 읽기는 자동 허용 (승인 불필요)
- 캘린더 쓰기는 승인 필요 (F5 참조)
- 권한 미허용 시 안내 카드 표시 + 설정 이동 버튼 제공
- 일정 요약은 구조화 JSON이 아니라 plain text 응답으로 충분하다

---

### F5. 일정 초안 생성 및 승인 (v0 MVP)

**목적**: 자연어 요청을 캘린더 일정 초안으로 변환하고
사용자 승인 후 저장

**사용 시나리오**
- 사용자: "내일 오후 3시 병원 일정 잡아줘"
- AI가 제목 / 시작 시간 / 종료 시간 / 메모를 담은 초안 생성
- 승인 바텀시트에서 내용 확인
- 승인 시 캘린더에 저장 / 거부 시 취소

**입력**: 자연어 일정 요청  
**출력**: 일정 초안 카드 (제목, 시작, 종료, 메모)

**정책**
- AI는 초안만 생성하고 저장하지 않는다
- 저장은 반드시 사용자 승인 후 실행된다
- 승인 / 거부 결과는 감사 로그에 기록된다
- 시간 정보 누락 시 내부 처리 상 validation 성격의 실패가 가능하다
- 그러나 사용자 대화 UX에서는 단순 오류 메시지보다 재확인 질문으로 유도하는 것을 기본 정책으로 한다
- 중복 일정 감지는 기본적으로 **경고**이며, v0에서는 사용자 확인 우선이다

---

### F6. 메모리 관리 — v0 기초 / v1 확장

**목적**: 개인화된 비서 경험을 위한 로컬 메모리 저장 및 조회

**5계층 구조**

| 계층 | 저장 내용 | 저장 시점 |
|---|---|---|
| Profile Memory | 사용자 정보, 응답 스타일 선호, 보안 설정 | v0: 앱 최초 실행, 설정 변경 시 |
| Conversation Memory | 세션별 대화 기록 (역할, 내용, 입력 유형, 시간) | v0: 매 대화 후 자동 저장 |
| Task Memory | 진행 중 작업, 보류된 요청 | v1: 작업 생성 / 완료 시 |
| Knowledge Memory | 사용자 메모, 요약된 문서 내용, 태그 | v1: 요약 / 메모 저장 시 |
| Audit Memory | 모델 실행, 도구 호출, 승인 / 거부, 검색 사용 이력 | v0: 모델 실행 / 도구 호출 / 승인 / 거부 / 오류 필수 기록, v1: 검색 / export / import / 발열 포함 전체 확장 |

**저장 방식**: JSON (설정, 프로필) + SQLite (대화, 작업, 지식, 감사)

**정책**
- 메모리는 전량 로컬 저장
- v0에서는 Profile / Conversation과 필수 Audit 이벤트를 우선 구현한다
- v0 필수 Audit 이벤트는 최소한 `MODEL_RUN`, `TOOL_CALL`, `APPROVAL_GRANTED`, `APPROVAL_REJECTED`, `ERROR`를 포함한다
- v1에서 Task / Knowledge / 전체 Audit Memory를 확장 구현한다
- v0에서 데이터 삭제 기능 미제공

---

### F7. 질문 단위 웹 검색 (v1)

**목적**: 특정 질문에 한해서만 웹 검색 보강 허용

**사용 시나리오**
- 사용자가 채팅 입력창의 검색 토글을 ON으로 설정한다
- 앱이 검색 전 확인 문구와 검색 쿼리 미리보기를 표시한다
- 사용자가 토글 ON을 확정하면 해당 질문에 대한 검색 승인으로 간주한다
- 해당 질문 전송 시에만 웹 검색 실행
- 응답에 로컬 답변 + 검색 보강 결과를 구분하여 표시
- 다음 질문에서는 토글이 자동으로 OFF로 초기화

**정책**
- 기본값: 검색 OFF
- 검색 ON은 질문 단위로만 허용 (세션 단위 전체 ON 불가)
- 토글 ON 확정 자체를 사용자 승인으로 간주하며, 전송 시 별도 승인 다이얼로그는 표시하지 않는다
- 검색 쿼리에 개인 일정, 이름, 메모 등 민감 정보가 포함될 수 있으면 사용자에게 검색 전 확인을 요구한다
- 사용자 대화 전문, 일정 전문, 메모 전문을 그대로 검색 요청에 포함하지 않는다
- 검색 사용 여부는 반드시 Audit Memory에 기록
- 검색 실패 시 로컬 응답만 유지하고 '웹 검색 보강 실패' 안내

---

### F8. Export / Import (v1)

**목적**: 메모리 및 설정 백업 및 기기 간 이동

**사용 시나리오**
- 메모리 화면에서 export 선택
- JSON + SQLite 묶음 파일로 저장
- import 시 manifest 버전 검증 후 복원

**정책**
- v1에서 export 파일 암호화 없음 (의도적 결정)
- import 파일 형식 / 스키마 버전 불일치 시 명확한 오류 안내
- export 파일에 개인정보가 포함됨을 UI에서 명시

---

### F9. 공유 인텐트 수신 (v1)

**목적**: 외부 앱에서 전달된 텍스트 / 이미지를 비서 입력으로 처리

**사용 시나리오**
- 브라우저 / 갤러리 등에서 Local Friday로 공유
- 공유된 내용이 채팅 입력으로 연결
- 요약 / 정리 / 질의응답 흐름으로 처리

**정책**
- 공유 수신 직후 자동 전송하지 않는다
- 사용자가 내용을 확인한 뒤 전송해야 한다
- 원본 앱 데이터 전문을 그대로 로그에 남기지 않는다

## 8. User Flow

### 8-1. 전체 앱 진입 흐름

```text
앱 실행
  │
  ├─ 모델 파일 존재 확인
  │    ├─ 없음 → 설정 화면으로 이동 + 모델 경로 안내
  │    └─ 있음 → 모델 로드 (백그라운드)
  │
  ├─ 로컬 프로필 확인
  │    ├─ 최초 실행 → 로컬 프로필 생성
  │    └─ 기존 → 프로필 로드
  │
  └─ 메인 채팅 화면 표시
```

### 8-2. 텍스트 채팅 흐름

```text
사용자 텍스트 입력
  │
  ├─ 빈 입력 → 전송 차단
  ├─ 중복 전송 → 차단 (in-flight 상태)
  │
  └─ 정상 입력
       │
       ├─ 검색 토글 ON? (v1)
       │    ├─ YES → 검색 전 확인 문구 / 쿼리 미리보기 표시
       │    │        → 사용자가 ON 확정 시 해당 질문 검색 승인
       │    │        → 검색 포함 처리
       │    └─ NO  → 로컬 처리만
       │
       ├─ 관련 메모리 조회
       │    ├─ v0: 최근 대화 5턴
       │    └─ v1: 최근 대화 5턴 + Knowledge 최근 3개
       │
       ├─ 로컬 모델 추론
       │
       ├─ 응답 유형 판단
       │    ├─ 일반 텍스트 → 화면 표시
       │    └─ 액션 초안 (캘린더 등) → 승인 바텀시트 표시
       │
       ├─ Conversation Memory 저장
       └─ Audit Memory 기록
```

### 8-2-1. 세션 ID 정책

- v0에서는 하나의 활성 채팅 세션을 유지한다
- 앱 프로세스 재생성, 화면 회전, 일시적 백그라운드 전환 시에도 현재 세션 ID는 복원 가능해야 한다
- 사용자가 명시적으로 "새 대화 시작"을 선택하기 전까지는 동일 세션으로 이어진다
- Conversation Memory 저장은 항상 sessionId를 포함한다

> 이 정책은 대화 맥락 유지와 최근 5턴 조회 기준을 안정화하기 위한 것이다.

### 8-3. 음성 입력 흐름

```text
FAB 탭
  │
  ├─ 마이크 권한 확인
  │    ├─ 없음 → 권한 요청 다이얼로그
  │    │         ├─ 허용 → 녹음 시작
  │    │         └─ 거부 → 텍스트 입력 안내
  │    └─ 있음 → 녹음 시작
  │
  ├─ 음성 인식 (오프라인 우선)
  │    ├─ 성공 → 인식 텍스트 확인 화면
  │    │         ├─ 전송 → 채팅 흐름으로 연결
  │    │         └─ 취소 → 오버레이 닫기
  │    └─ 실패 → 오류 안내 + 텍스트 직접 입력 유도
  │
  └─ 무음 입력 → 재시도 안내
```

### 8-4. 일정 초안 생성 및 승인 흐름

```text
"내일 3시 병원" 입력
  │
  ├─ 일정 생성 의도 감지
  ├─ 제목 / 시작 / 종료 / 메모 초안 생성
  │
  ├─ 시간 정보 불완전?
  │    ├─ UseCase 레벨: 초안 생성 불가로 판단하고 validation 성격의 실패를 반환
  │    └─ 대화 UX 레벨: 사용자에게 재확인 질문
  │         ("몇 시로 잡을까요?", "얼마나 걸리는 일정인가요?")
  │
  └─ 승인 바텀시트 표시
       ├─ 승인 → 캘린더 저장 실행 + Audit 기록
       └─ 거부 → 취소 + Audit 기록
```

> 설명:
> 내부 계약 또는 UseCase 단위에서는 시간 정보 누락을 validation 실패로 다룰 수 있다.
> 다만 사용자 대화 경험에서는 단순 오류 메시지 대신 재확인 질문으로 변환하는 것이 기본 UX 정책이다.

### 8-5. 이미지 입력 흐름

```text
첨부 버튼 탭
  │
  ├─ 갤러리 / 카메라 선택
  ├─ 이미지 선택
  │
  ├─ 유효성 검사
  │    ├─ 지원 형식 아님 → 오류 토스트 + 첨부 취소
  │    ├─ 10MB 초과 → 오류 토스트 + 첨부 취소
  │    └─ 정상 → 프리뷰 표시
  │
  ├─ 질문 입력 후 전송
  └─ 멀티모달 추론 → 응답 표시
```

### 8-6. 권한 거부 분기

```text
기능 진입 시 권한 확인
  │
  ├─ 허용됨 → 기능 실행
  └─ 거부됨
       ├─ 첫 거부 → 권한 요청 다이얼로그 표시
       │             ├─ 허용 → 기능 실행
       │             └─ 거부 → 해당 기능 비활성 + 설정 이동 버튼 표시
       └─ 영구 거부 → "설정에서 권한을 허용해주세요" 안내
```

## 9. Non-Functional Requirements

### NFR1. 오프라인 우선

- 텍스트 채팅, 음성 입력, 이미지 입력, 캘린더 조회,
  v0 메모리 저장 / 조회는 네트워크 없이 완전히 동작해야 한다
- v1에서 네트워크는 사용자가 명시적으로 검색을 ON으로 확정한
  질문에 한해서만 사용된다

### NFR2. 응답 성능

- 텍스트 응답: 응답 생성 성공 또는 오류 상태가 UI에 명확히 표시되어야 한다
- 이미지 입력 응답: 성공 시 응답이 화면에 표시되고 대화 기록에 저장되어야 한다
- 모델 로드: 백그라운드에서 처리, UI 블로킹 금지

### NFR3. 발열 및 배터리

- 연속 추론 시 기기 온도 모니터링 (`TemperatureProvider`)
- 43°C 이상: 경고 메시지 표시 + 15ms Token Delay 부여 (Soft Mitigation)
- 48°C 이상: UI 주황색 경고 배너 표시 + 50ms Token Delay 부여 (Graceful Degradation) 및 Hard Halt 지양
- 연속 5회 추론 후 짧은 쿨다운 적용

### NFR4. 개인정보 보호

- 기본 상태에서 어떠한 데이터도 외부 서버로 전송되지 않는다
- v1 검색 사용 여부는 감사 로그에 반드시 기록된다
- v1 검색 전 사용자가 검색 쿼리를 확인할 수 있어야 한다
- 모든 대화 / 메모리 / 모델은 기기 로컬에 저장된다
- v1 export 파일에 개인정보 포함 사실을 UI에서 명시한다
- 공유 인텐트 수신 시 원본 데이터 전문을 그대로 로그에 남기지 않는다

### NFR5. 확장성

- 모델 인터페이스가 추상화되어 있어 다른 모델로 교체 가능
- 메모리 스키마는 Windows 확장을 고려한 공통 포맷으로 유지
- 도구(Tool) 인터페이스가 분리되어 새로운 Android 도구 추가 가능

### NFR6. 데이터 무결성

- Room DB migration 전략을 통해 앱 업데이트 시 사용자 데이터 보존
- v1 Export / Import 시 manifest 버전 검증으로 스키마 불일치 방지
- DB 쓰기 실패 시 오류 기록 및 사용자 안내
- sessionId는 프로세스 재생성 등에도 복원 가능해야 한다

## 10. Constraints

### 기술적 제약

| 제약 | 내용 |
|---|---|
| 모델 파일 크기 | Gemma 4 E4B-it INT4 기준 약 3~4GB — APK에 번들 불가, sideload 필수 |

| STT | Android 온디바이스 STT 의존 — 기기 설정에 따라 품질 차이 |

| 데이터 삭제 | v0에서 기본 금지 |
| 외부 API | v0에서 클라우드 모델 미사용 |
| 다중 사용자 | v0에서 단일 로컬 프로필만 지원 |

### 배포 제약

| 제약 | 내용 |
|---|---|
| 배포 방식 | Play Store 미등록, APK 직접 설치(sideload) |
| 대상 기기 | Galaxy S25 Ultra (Android v0 MVP) |
| 모델 배치 | sideload로 기기에 직접 복사, 앱이 경로를 기록하여 참조 |

## 11. Edge Cases

### EC1. 모델 파일 관련

| 케이스 | 처리 방법 |
|---|---|
| 앱 시작 시 모델 파일 없음 | 설정 화면으로 이동 + 파일 경로 안내 메시지 표시 |
| 모델 로드 중 앱 종료 | 다음 실행 시 재로드 시도 |
| 모델 추론 timeout | 오류 메시지 + 재시도 버튼 표시 |
| 추론 중 OOM 발생 | 오류 코드 기록 + 입력 길이 축소 권고 안내 |

### EC2. 권한 관련

| 케이스 | 처리 방법 |
|---|---|
| 캘린더 권한 거부 | 캘린더 읽기/쓰기 기능 비활성 + 설정 이동 버튼 |
| 마이크 권한 거부 | 음성 입력 비활성 + 텍스트 입력 안내 |
| 저장소 권한 거부 | v1 Export/Import 기능 비활성 + 안내 |
| 권한 영구 거부 | 시스템 설정 화면으로 직접 이동 유도 |

### EC3. 입력 관련

| 케이스 | 처리 방법 |
|---|---|
| 빈 텍스트 전송 | 전송 버튼 비활성 또는 validation 오류 |
| 동일 메시지 연속 전송 | in-flight 상태 확인으로 중복 차단 |
| 이미지 형식 오류 | 오류 토스트 표시 + 첨부 취소 |
| 이미지 10MB 초과 | 오류 토스트 표시 + 첨부 취소 |
| 무음 음성 입력 | 재시도 안내 표시 |
| STT 인식 실패 | 오류 안내 + 텍스트 직접 입력 유도 |

### EC4. 캘린더 관련

| 케이스 | 처리 방법 |
|---|---|
| 일정 생성 요청에서 시간 누락 | 내부 처리상 validation 실패 가능, UX에서는 재확인 질문 |
| 중복 일정 감지 | 초안 카드 또는 안내 UI에 경고 표시 후 사용자 판단에 맡김 |
| 캘린더 Provider 읽기 실패 | 오류 안내 + 재시도 버튼 |
| 승인 후 캘린더 쓰기 실패 | 오류 메시지 + Audit 기록 |
| 사용자가 승인 거부 | 취소 처리 + Audit에 거부 이력 기록 |

### EC5. 네트워크 관련

| 케이스 | 처리 방법 |
|---|---|
| v1 검색 ON 상태에서 네트워크 없음 | 로컬 응답만 제공 + '웹 검색 보강 실패' 안내 |
| v1 검색 timeout | 로컬 응답만 제공 + 안내 |
| v1 검색 결과 없음 | 로컬 응답만 제공 + 안내 |
| v1 검색 쿼리에 민감 정보 포함 가능 | 검색 전 사용자 확인 문구와 쿼리 미리보기 표시 |

### EC6. 데이터 관련

| 케이스 | 처리 방법 |
|---|---|
| DB 쓰기 실패 | 오류 기록 + 사용자 안내 |
| DB migration 실패 | 오류 로그 기록 + 앱 재시작 안내 |
| v1 Export 저장 공간 부족 | 오류 안내 + 필요 공간 표시 |
| v1 Import 파일 형식 오류 | 오류 메시지 + 원인 설명 |
| v1 Import manifest 버전 불일치 | 버전 불일치 안내 + import 중단 |

### EC7. 발열 / 성능 관련

| 케이스 | 처리 방법 |
|---|---|
| 기기 온도 43°C 이상 | 경고 토스트 + Audit 기록 |
| 기기 온도 48°C 이상 | 추론 일시 중단 + 안내 메시지 |
| 연속 추론 5회 이상 | 쿨다운 딜레이 자동 적용 |

### EC8. 세션 관련

| 케이스 | 처리 방법 |
|---|---|
| 화면 회전 | 기존 sessionId 유지 |
| 일시적 프로세스 재생성 | 기존 sessionId 복원 시도 |
| 사용자가 새 대화 시작 선택 | 새로운 sessionId 발급 |
| 세션 복원 실패 | 안전하게 새 sessionId 생성 후 대화 시작 |

## 12. Version Scope

버전 범위는 아래 표를 단일 기준으로 사용한다.  
다른 문서의 우선순위와 충돌 시 이 표가 우선한다.

| 기능 | 적용 버전 | 비고 |
|---|---|---|

## 13. Success Metrics

### 기능 완료 기준 (Acceptance Criteria)

v0(MVP) 완료를 판단하는 최소 기준이다.

| # | 기준 | 검증 방법 |
|---|---|---|
| AC1 | 텍스트 입력 후 로컬 모델 응답이 생성되고 오류 없이 화면에 표시되며 사용자 / 비서 메시지가 저장됨 | 직접 테스트 + DB 확인 |
| AC2 | Push-to-talk 음성 입력 결과가 텍스트로 변환되고 동일 채팅 흐름으로 전송 / 저장됨 | 직접 테스트 + DB 확인 |
| AC3 | 스크린샷 / 문서 이미지 첨부 후 응답이 생성되고 오류 없이 화면에 표시되며 대화 기록에 저장됨 | 직접 테스트 + DB 확인 |
| AC4 | 오늘 일정 조회 결과가 오류 없이 화면에 표시됨 | 캘린더 권한 허용 기기에서 테스트 |
| AC5 | 자연어 일정 요청 → 초안 생성 → 사용자 승인 → 캘린더 저장까지 오류 없이 완료됨 | 직접 테스트 |
| AC6 | 프로필 / 대화 / 필수 감사 이벤트가 로컬 저장소에 저장됨 | DB 확인 |
| AC7 | 캘린더 / 마이크 권한 거부 시 앱 크래시 없이 기능 비활성 + 안내가 표시됨 | 권한 거부 시나리오 테스트 |
| AC8 | 모델 파일 없을 때 크래시 없이 설정 화면으로 이동하고 경로 안내가 표시됨 | 모델 파일 제거 후 테스트 |
