## Overview

**성격 한 줄 (D1)**: 덜렁대는 나 대신 꼼꼼히 챙기고, 고민될 땐 먼저 제안해 주는 다정한 비서. **화면은 조용하게, 말은 따뜻하게.**

| 층 | 뜻 | 화면에서 |
|---|---|---|
| 화면 | 조용하고 정돈됨 | 장식 최소, 결과 카드 중심, 강조색은 행동·선택에만 |
| 일 처리 | 꼼꼼함 | 숫자·시각은 항상 정확하게 크게, 놓친 것을 먼저 알림 |
| 고민 | 먼저 제안 | 답 끝에 다음 행동 칩 한두 개, 강요하지 않음 |
| 말투 | 밝고 친근 | 짧게, 감탄은 결과 뒤 한마디(0.38.5) |

**하지 않는 것** (0.38.0 감사의 "AI 티"): 유리·블러 질감, 다른 색상끼리 넘어가는 그라데이션(특히 하늘→보라)·그라데이션 글자, 발광·오로라 배경, 이모지·글자 기호 아이콘, 모든 요소에 같은 무게의 둥근 테두리 카드, 제목 위 작은 회색 라벨(eyebrow), 보라+시안 조합.
예외: 시작 화면(개성 ② 자리)의 행성·은하 둘레 은은한 하늘 빛은 장면의 일부로 허용한다 — 배경 전체를 덮는 발광이 아니라 천체의 빛이다(0.38.6 M6 점검에서 명시).

**참고 패턴 (D2)** — 겉모습은 빌리지 않고 문제를 푸는 방식만:
- 토스: 화면 하나에 핵심 하나, 큰 숫자·짧은 문장의 위계, 친근하고 짧은 UX 문구
- 카카오톡: 말풍선 밀도·날짜 구분선, 카드형 메시지를 대화 흐름에 끼우기
- Things 3: "오늘" 중심, 완료의 손맛, 조용한 목록
- 클로바노트: 요약과 근거(원문 위치)를 함께

## Colors

### 브랜드
- **하늘색 `brand` 는 면에만** — 선택된 날짜·칩 표시, 진행 바, 토글 켜짐, 보내기 버튼. 글자·아이콘으로 쓰지 않는다(흰 배경 위 2.0:1).
- 같은 색상의 **글자 단계 `brandText`** 가 링크·강조 글자·강조 아이콘을 맡는다(라이트는 짙게, 다크는 밝게).
- **`brandContainer`** 는 옅은 브랜드 면 — 사용자 말풍선, 선택된 칩 바탕, 결과 카드의 Duotone 면.
- 주 버튼은 꽉 찬 `brand` 가 아니라 채도를 낮춘 **`brandSoft` 면 + `onBrandSoft` 글자** — 흰 카드 위에서 꽉 찬 하늘색이 튀었다(사용자 지적). `brand` 면 위 글자는 `onBrand`(짙은 글자), 흰 글자는 대비 미달이라 쓰지 않는다.

### 표면
- `bg` < `surface` 두 단계와 한 단계 낮은 `surfaceSunk`. 위계는 그림자가 아니라 **면의 밝기 차 + hairline `border`** 로 만든다.
- 다크 바탕은 남색이 아니라 하늘색 기운이 아주 약한 회색 — 브랜드 하늘색이 두 테마에서 같은 앱으로 보이게.

### 글자
- `textPrimary` 본문·제목, `textSecondary` 설명, `textMuted` 날짜·태그·메타. 셋 다 라이트·다크 모두 surface 위 4.5:1 이상.
- 상태 글자는 `dangerText`·`successText`·`warningText`. 상태를 색만으로 전하지 않는다 — 아이콘이나 문구를 함께.

### 규칙
- 화면 코드는 토큰만(AGENTS §4-6). 새 색이 필요하면 이 문서와 `Color.kt` 에 토큰으로 추가하고 대비를 잰다.
- 다른 테마(예: 보라 계열)는 토큰 묶음을 하나 더 만드는 방식으로만 — 화면 코드를 바꾸지 않는다(추후 후보).

## Typography

- **하다 라운드** 400/500/700 세 굵기(앱에 원본 탑재, 서브셋 없음). Light·Black 은 쓰지 않는다.
- **설정의 "앱 글꼴 / 시스템 글꼴"** — 시스템 글꼴 모드에서는 기기에서 고른 글꼴을 같은 크기·굵기 단계로 따른다. 두 모드 모두 줄 높이·최소 폭을 글꼴 모양에 기대지 않는다.
- 단계는 위 7개뿐. 화면에서 `fontSize` 를 직접 쓰지 않는다. 숫자는 `number` 단계와 tabular 숫자.
  구현: `ui/theme/Type.kt` 가 7단계를 Material3 역할 15개에 모두 싣는다(표는 그 파일 KDoc) — 화면은 `MaterialTheme.typography.<역할>`.
  `BasicTextField` 는 기본 글자 스타일을 물려받지 않으니 `textStyle = MaterialTheme.typography.<역할>.copy(...)` 로 준다.
- **한국어는 어절 단위로 줄바꿈** — 모든 단계가 `LineBreak.Paragraph` + `WordBreak.Phrase`, locale 한국어 고정(기기 언어가 영어여도). 안드로이드 13+ 에서만 동작하고 그 아래는 음절 단위(0.38.3 M6 — "있었/는데"처럼 낱말 중간에서 끊겼다).
- 예외: 문서 뷰어 본문(`FlowView`·`SheetView` 의 셀)은 확대 배율을 곱하는 읽기용 글자라 직접 크기를 쓴다(글꼴은 단계와 같다).
- 한자는 글꼴에 없어 시스템 글꼴로 섞여 보인다(알려진 한계).
- 위젯(Glance)은 Compose 단계를 쓸 수 없어 시스템 글꼴 + 직접 크기(같은 수치를 따른다).
- 라이선스: SIL OFL 1.1 — 고지는 `app/src/main/assets/licenses/HadaRound-OFL.txt`(구성 글꼴 저작권 포함).

## Layout

- 모바일 단일 컬럼, 좌우 여백 `md`(16) **하나** — 분할 버튼·안내 상자도 같은 끝선(0.38.3 M6, 일정 화면만 20 이었다). 바텀시트 안 좌우는 20(승인·알림·프로필·에피소드 시트 같은 값). 묶음 사이 `lg`(24), 묶음 안 `xs`~`sm`.
- **목록은 카드 더미가 아니라 행** — 한 묶음(`surface` + `border` + `rounded.md`) 안에 행을 hairline 으로 나눈다. 행 높이는 내용 + 세로 12, 행 끝 동작은 48dp 아이콘 버튼.
  구현: `ui/component/KosmosList.kt` — `KosmosListGroup`(묶음), `KosmosListRow`(앞 아이콘·제목·보조 줄 + `Tag`·끝 동작, 구분선은 들여씀), `SectionHeader`, `EmptyState`, `DeleteIconButton`, `showUndo`.
  페이징 목록처럼 행이 따로 그려지면 `Modifier.groupItem(groupPosition(i, n))` 로 묶음 조각을 그린다.
- **화면 문법(0.38.3)** — 섹션 제목(`SectionHeader`) → 묶음 → 묶음 아래 각주(`caption` textMuted, 경고면 같은 자리에 `warningText`). 설정·모델 관리·활동 기록·메모·할 일·문서 홈·드로어가 이 문법이다.
  행의 보조 정보는 가운뎃점으로 잇지 않는다 — 날짜는 글자, 분류는 `Tag` 면, 나열은 쉼표.
  **가운뎃점 기준(0.38.4 사용자 결정)**: 세 항목 이상 이어지는 정보 줄(`a · b · c`)과 긴 나열은 쓰지 않는다. 짧은 두 항목 라벨("알림 · 취소함")과 붙여 쓴 국어 나열("메모·할 일")은 괜찮다. 화면 문구에 줄표(—)는 쓰지 않는다(문장을 나누거나 쉼표).
- **카드는 결과에만** — 알림·일정·기억처럼 "처리된 결과"가 카드다. 설정 섹션·메모 하나하나를 카드로 감싸지 않는다.
- 제목 위 작은 라벨을 두지 않는다. 섹션이 필요하면 `subtitle` 단계 제목으로.

## Elevation

- 그림자를 쓰지 않는다. 깊이는 면 밝기(`bg`→`surface`)와 `border`.
- 바텀시트·대화상자만 위로 뜬다 — `surface` + `rounded.xl` 윗모서리 + `scrim`.
- 유리·블러·반투명 면은 쓰지 않는다(v2 의 `glass*` 토큰 폐기).

## 시스템 바와 화면 틀

- **edge-to-edge** — 상태바·내비게이션 바도 앱 색으로 칠해진다(0.38.1 M2, 매니페스트 옛 테마 교체). 바 아이콘 밝기는 테마를 따른다.
- 인셋은 **화면 틀이 맡는다** — 상단 바(TopAppBar)가 상태바, 입력바·하단 버튼이 내비게이션 바·키보드(IME). 평범한 Row/Column 을 슬롯에 넣으면 바에 깔린다(AGENTS §2-③).
- **모든 하위 화면에 같은 상단 바** — 왼쪽 ← 아이콘 버튼(48dp, contentDescription "뒤로") + `title` 단계 제목(20). ← 도 20(`IconSize.inline`) — 화살표와 글자 크기를 맞춘다. 채팅의 "KOSMOS"·메뉴 아이콘도 같다(사용자 결정 2026-10-16, 17·22·20 시안 비교). 글자 "뒤로" 버튼은 쓰지 않는다. 시스템 뒤로·예측 뒤로는 그대로(`AppNavHost.navigateBack` 루트 가드).
- 채팅(홈)은 상단 바 왼쪽이 메뉴(드로어).

## Components

**버튼**
- 주 버튼(`KosmosButton(accent = true)`·승인 시트): `brandSoft` 면 + `onBrandSoft` 글자 700, `rounded.md`, 높이 48. 한 화면(시트)에 하나. 채팅 안 승인 카드의 승인 버튼은 `brandContainer` 면 + 테두리 + `brandText`(0.38.2 에서 시트로 대체).
- 보조 버튼: `surface` + `border` + `textPrimary`.
- 글자 버튼(링크형): `brandText`, 위험 동작은 `dangerText`. 터치 영역 48dp.
- 아이콘 버튼: 48dp 영역, 아이콘 24, `contentDescription` 필수. 글자 기호(✕ › ▾ +)를 버튼으로 쓰지 않는다.

**분할 버튼(탭 전환)** — `KosmosSegmentedControl`: `surfaceSunk` 트랙(안쪽 여백 4) 위에 선택 칸만 `surface` + `border`, `rounded.md`/`sm`, 글자 `button`(선택 칸 `brandText` 굵게). [WHY] M3 `SegmentedButton` 은 체크 아이콘·외곽선 칸 구분이 기본이라 이 모양을 내려면 덮어쓸 것이 더 많다(0.38.1 M5).
문서 뷰어 시트 탭도 같은 모양 — 칸은 글자 너비, 시트가 많으면 가로 스크롤(0.38.3 M4).

**스위치** — 켜짐: `brand` 트랙 + `surface` 손잡이, 꺼짐: `surface` 트랙 + `textMuted` 테두리·손잡이(흰 묶음 위에서도 보이게, 0.38.3 M6). 행 전체를 눌러도 바뀐다.

**입력** — `surface`(또는 `surfaceSunk`) + `border` + `rounded.md`, 높이 ≥48, 포커스 테두리·라벨·커서는 `brandText`(`kosmosTextFieldColors()` — 색을 안 넘기면 M3 primary = `brand` 라 라벨 대비가 약 2:1, 0.38.3 M6). 예외: 채팅 입력바는 알약 모양(`rounded.full`), 입력란 안내가 상태를 말한다("답을 쓰는 중이에요…"·"듣고 있어요…" — 위험색 아님).

**말풍선** — 사용자: `brandContainer`→`brandContainerEnd` 같은 색 그라데이션(대각선) + 옅은 테두리 — 개성 자리(아래 "개성"), `rounded.lg`(보낸 쪽 아래 모서리 4). 비서 답은 **카드**(`surface` + `border`, 받은 쪽 아래 모서리 4) 안에 문장과 결과 행(`surfaceSunk`, 누르면 시트)을 담는다 — 0.38.2 M0 결정. 읽기 버튼과 칩은 카드 밖 아래.

**결과 카드** — `surface` + `border` + `rounded.md`(결과 행은 `surfaceSunk`, 다크에서는 면 차이가 작아 hairline 을 더한다). 구성: Duotone 아이콘 + `label` 종류(brandText) / `subtitle` 이름 / `number` 값. 기억 답의 **근거 줄**은 아이콘 + 문장(메모·대화, 16 아이콘 textMuted) — 가운뎃점(·)으로 이은 정보 줄을 쓰지 않는다. 메모와 다른 값이 있었다는 줄은 옅은 주의 면(`warningText` 10%) 위에 둔다(0.38.2 M7b). **보기 전용** — 카드 안에 바로 실행되는 버튼을 두지 않고, 누르면 시트가 열려 그 안에서 바꾼다(D6 ②). 카드는 그 순간의 사진이 아니라 대상의 **현재 상태**(미룸·취소함·울렸음)를 보여 준다.

**칩** — 답 칩(누르면 그 글자로 한 턴)과 행동 칩(앱 기능으로 바로, 앞에 16 아이콘). `rounded.full`, 높이 36, `border`. **마지막 비서 답에만** 보이고, 고르거나 새 턴이 시작되면 사라진다(D6 ③). 칩은 코드 규칙으로 만들고 칩을 위해 추론을 더 하지 않는다. 결과 카드를 누르는 것과 같은 행동 칩은 두지 않는다 — 행동 칩은 카드로 할 수 없는 것만([지난 대화 정리], 0.38.6 M3). 지난 대화만 근거인 기억 카드는 제목이 그 대화 이름이고 누르면 대화 시트(카드 안 "지난 대화:" 줄 없음).

**승인·수정 시트** — 모든 승인(일정·리마인더·메모·프로필)과 결과 카드의 수정은 **같은 모양의 바텀시트**(D6 ①). 순서: `subtitle` 무엇을 할지 → 구조화된 내용(시각은 `number`, 제목, 메모) → [취소 보조][주 버튼] → 안내 줄(정확 알람 등, `caption`). 제한 시간이 있는 툴 승인은 문구 대신 버튼 줄 위 2dp 선(`brand`, 바탕 `border`)이 남은 시간만큼 줄어든다 — [취소]는 평범한 보조 버튼, 화면 읽기의 남은 초는 [취소]에(0.38.6 M2 — [취소] 면을 채우던 0.38.2 방식은 보조 버튼이 주 버튼만큼 무거워 보였다). 프로필 제안이 여러 건이면 머리는 개수("대화에서 찾은 항목 N개"), 본문은 체크 목록(기본 전부 고름) — [모두 무시][고른 N개 저장], 고르지 않은 항목은 무시로 처리. 경고 줄이 있으면 기본 안내 줄을 숨기고 경고 옆에 해결 행동("설정에서 켜기")을 둔다. 수정 시트는 [보조][주 동작] 아래 오른쪽에 위험 동작·닫기를 글자 버튼으로 모은다(위험 동작을 다른 시트의 '그만두기' 자리에 두지 않는다). 채팅 안 떠 있는 승인 카드는 쓰지 않는다.

**채팅 상단 요약** — 아이콘이 든 캡슐 한 줄(높이 44, `rounded.full`): 다음 알림 · 오늘 일정 · 남은 할 일, 칸마다 눌러 해당 화면. 헤더의 엔진 상태는 점이 아니라 네 갈래 별(`StarGlyph`, 색 = 상태)(0.38.2 M7b).

**첫 화면** — 대화 기록이 하나도 없을 때(처음 쓸 때·초기화 후 — 타임라인은 세션과 무관, ADR-022): 작은 별자리 + `title` 인사 + 한 줄 설명 + 눌러서 바로 보내는 예시 세 개(알림·일정·기억).

**목록 행** — `body` 내용 + `label` 메타(textMuted) + 끝 동작(48dp 아이콘). 할 일 완료는 왼쪽 원형 체크(48dp)만(0.36.2).
한 항목 삭제는 옅은 휴지통(`textMuted`) → 바로 삭제 → 스낵바 "되돌리기"(메모·할 일·프로필 항목·최근 문서 — 0.38.3 결정 2). 일괄 삭제·데이터 초기화·에피소드 요약 삭제는 확인 창.

**스낵바** — 일시 안내·되돌리기. 결정이 필요한 것만 대화상자. 액션 글자는 반전 면 위 글자라 **반대 테마의** `brandText`(`inversePrimary`, 0.38.3 M6 — 같은 테마 값은 다크에서 약 2:1).

**일정 "오늘" 탭** — 일정 화면 첫 탭(기본). 묶음 하나에 오늘 일정·오늘 울릴 알림을 시간순(시각 칸 84dp, 보조 글자 색), 아래에 날짜·알림 없는 할 일 체크 원, 그 아래 "다가오는 일정"(내일~이번 주). 알림 줄 → 알림 수정 시트(0.38.3 M1). 위젯도 같은 순서(날짜 → 일정 시간순 → 할 일 수).

**빈 화면·오류** — 아이콘(32, Light) + 한 줄 + 행동 버튼. 일러스트 없음.

**개성 (세 곳)** — 화면이 밋밋해지지 않게 정해진 자리에만 둔다(사용자 결정 2026-10-16, 한 곳 제한 해제; ③ 은 2026-10-19 추가).
① **사용자 말풍선** — 같은 하늘색 안에서 밝기만 넘어가는 그라데이션(보라 금지). ② **브랜드 마크** — 항성과 그 둘레의 행성·궤도(KOSMOS). 스플래시와 음성 입력 중 상태(0.38.4). ③ **응답 대기** — 비서 카드 모양 안에서 네 갈래 별 셋이 차례로 반짝인다(`TwinkleStars`, `brand`, 1.5초 주기, "애니메이션 제거"면 멈춘 그림). 같은 별 모양이 헤더 엔진 상태와 첫 화면 별자리에 쓰인다. 새 자리를 늘릴 때는 이 목록부터 고친다.

## Motion (0.38.4)

- 값은 `ui/theme/Motion.kt` 하나에서 — 화면에서 `tween(숫자)` 를 직접 쓰지 않는다. 곡선은 강한 감속 `EaseOut` = cubic-bezier(0.23, 1, 0.32, 1) 하나, ease-in 은 UI 에 쓰지 않는다.
- 길이: 누름 `PRESS_MS` 120 · 작은 상태 바뀜(아이콘 전환·세그먼트 칸) `SHORT_MS` 150 · 화면 전환·결과 등장 `MEDIUM_MS` 250. 모두 300 아래.
- 화면 전환은 공유 축 — 들어갈 때 새 화면이 오른쪽 30dp 에서, 뒤로는 왼쪽에서(`Motion.NavTransitions`). 예측 뒤로가 같은 움직임을 따른다.
- 누름은 0.97배(`pressScale`), 물결은 둥근 모서리 안으로. 결과가 생길 때만 작게 움직인다 — 방금 저장된 답의 결과 행(`appearOnce`, 8dp), 할 일 체크. 스크롤로 다시 보일 때는 움직이지 않는다. 같은 등장 효과를 모든 요소에 뿌리지 않는다.
- 시스템 "애니메이션 제거"(`rememberReducedMotion`)면 위치 변화 없이 바로 바뀐다. 시간에 뜻이 있는 것(승인 60초)은 프레임 시계로 세어 남은 초가 맞게.
- 계속 도는 움직임은 상태가 진행 중일 때만 — 응답 대기 별, 녹음 파형(소리 크기), 엔진을 기다리는 시작 화면. 장식용 무한 애니메이션은 쓰지 않는다(발열에 민감한 앱).
- **시작 화면**(설정에서 행성/은하, 기본 행성): 하루에 한 번 보는 장면이라 길이·가속 곡선 예외. 장면은 채팅으로 끊기지 않고 이어진다 — 셸 덮개가 같은 시계로 그리며 진짜 채팅을 드러내고, 우리 별(헤더 엔진 별과 같은 네 갈래 별)이 헤더 별 자리에 앉는다. 이미 준비돼 있으면 장면 없이 바로 채팅.

## Voice (0.38.5)

**화면 문구**
- **해요체**, 짧은 문장, 결과를 먼저. "1시 56분에 알려 드릴게요." 합니다체·하십시오체를 쓰지 않는다(알림 채널·위젯 설명처럼 시스템 화면에 나가는 글도).
- 다정한 한마디는 결과 뒤에 한 번. 감탄·느낌표 남발 금지. 화면 문구에 이모지를 쓰지 않는다.
- 줄표(—) 금지, 세 항목 이상은 가운뎃점 대신 쉼표("알림, 일정, 기억"). 짧은 두 항목 라벨과 붙여 쓴 국어 나열("메모·할 일")은 둔다.
- "해 주세요"처럼 보조 용언은 띄어 쓴다.
- 내부 이벤트·툴 이름, ISO 시각, 모델에게 하는 지시 문장을 화면에 보여 주지 않는다(활동 기록 "원문 보기"만 예외).

**낱말** (같은 뜻은 한 낱말로)

| 뜻 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 없애기 | 지우기, 지웠어요 (목록에서만 빼는 최근 문서는 "빼기") | 삭제 |
| 다시 하기 | 다시 시도, 다시 시작 | 재시도, 재시작 |
| 선택 | 고르기, 골라 주세요 | 선택 |
| 다운로드 | 내려받기 | 다운로드 |
| 정한 시각에 울리는 것 | 알림 (시스템 알림 채널 이름만 "정한 시각 알림") | 리마인더 |
| 정확한 시각 권한 | 알람 및 리마인더 (휴대폰 설정 이름 그대로 — 사용자가 찾을 이름) | 정확한 알림 |
| 저장한 것 / 기능 영역 | 메모 / 기억 | 메모리(기기 RAM 에만) |
| 요약해 둔 지난 대화 묶음 | 지난 대화, 지난 대화 정리, 이 대화 요약 (원래 채팅은 "채팅 기록"·"채팅에서 보기") | 과거 대화, 함께 본 대화, 과거 기록, 원문 대화, 타임라인 |
| 비서가 한 말 | 답 (답 길이, 답 멈추기, 모델 답) | 답변, 응답 |

**비서 답(모델 출력)** — 프롬프트 영역이라 실험실 실측 후에만 바꾼다(§2-⑤).
- 채팅: 시스템 지시의 `Reply briefly in polite 해요체 (…해요, …했어요), not 합니다체.`("자세히" 설정은 briefly 없이). 답 속 이모지는 막지 않는다(0.38.5 사용자 결정).
- 한 번 쓰는 추론(브리핑·회고·일정 요약 등)의 지시는 공통 형식 — `[System]` + 영어 역할 한 줄 + 한국어 역할 한 줄 + "~하세요" 목록. 줄여도 이득이 없었다(exp54 요소 가르기).
- 지시를 바꿀 때는 합성 입력만 믿지 않는다 — 실제 입력에서 말투가 반대로 나왔다(exp54_real). 지시에 재료 문구를 따옴표로 인용하지 않는다(그대로 옮겨 적는다). 예시 문장은 모델이 따라 쓴다.
- 말투 롤모델은 내부 참고로, 실존 인물의 이름·말버릇을 문구나 프롬프트에 쓰지 않는다.

## Accessibility

- 글자 대비 4.5:1(큰 글자 3:1) — 위 토큰을 쓰면 자동으로 지켜진다. 새 조합은 재서 넣는다.
- 터치 영역 48×48dp, 사이 8dp. 보이는 크기를 작게 둬야 하는 캡슐·칩은 `minimumInteractiveComponentSize()` 로 누르는 영역만 키우고 `Role.Button` 을 붙인다(0.38.3 M6).
- 눌리는 것은 버튼 역할(`Button`/`IconButton`/`Role.Button`)과 설명을 가진다. 글자에 `clickable` 만 붙이지 않는다.
- 글자 크기는 sp — 시스템 글자 크기 1.3배에서 잘리지 않게(실기기 확인).
- 색만으로 상태를 전하지 않는다.

  `./gradlew test` 가 비교하고(`gradle.properties` 의 `roborazzi.test.verify`) 다르면 실패, 차이 이미지는 `app/build/outputs/roborazzi/`(`_compare`·`_actual`).
  의도한 변경은 전후 비교를 사용자에게 보이고 확인받은 뒤 `./gradlew :app:recordRoborazziDebug` 로 다시 기록한다. 시각·시간대는 테스트가 고정한다(`LocalClock`).
- 검색으로 지키는 지표: 테마 밖 하드코딩 색 0, 이모지·글자 기호 아이콘 0, 테마 밖 직접 `fontSize` 0.
  예외: 문서 뷰어 표의 원본 셀 서식 색(`CellPaints` — 파일에서 읽은 색이라 토큰이 아니다). 다크에서는 배경을 색조 유지·어둡게, 대비가 모자란 글자색은 밝기만 옮긴다(0.38.7).

## Known Gaps

- 엑셀 셀 서식은 배경·글자색·굵기·가로 정렬만 — 테두리·글꼴 종류·글자 크기·조건부 서식은 보이지 않는다(0.38.7 결정)
- 목록 행 삭제 움직임 — 묶음을 행 조각(`groupItem`)으로 그리는 구조라 아래 행이 올라오는 동안 틈이 보인다(0.38.4 M4 에서 뺌)
- 시작 화면·녹음 파형의 실기기 부드러움 — 휴대폰 gfxinfo 로 확인 전(device_gate R)
- 기억·대화 합치기 판정 프롬프트는 공통 형식 밖(해라체) — 형식을 바꿔도 끝맺음이 안 바뀌어(exp59) 합친 문장 끝만 코드로 정리, "…마신다" 같은 동사 끝은 남는다(0.38.6)
- 보라 계열 등 추가 테마 — 추후 후보
- 태블릿·가로 전용 배치
