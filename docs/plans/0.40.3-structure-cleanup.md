## M1 — 언어 주입 통일 (`CurrentLanguage`)

### 문제
- `AppLanguageHolder? = null` + `?: AppLanguage.KO` 대체 패턴이 13개 클래스에 흩어져 있고, 대부분 테스트 전용 보조 생성자를 하나씩 더 갖고 있다.
- 툴 실행기 등 11개 클래스는 `languageProvider: () -> AppLanguage` 를 받는 생성자 **세 개**(내부 기본 · "하위 호환" · `@Inject`)를 갖는다.
- `:domain` 은 `AppLanguageHolder`(앱 모듈)를 볼 수 없어 M2 의 유스케이스 이동을 막는다.

### 처방
1. **`:core` 에 인터페이스 추가** — `core/src/main/java/com/kosmos/app/core/common/CurrentLanguage.kt` (AppLanguage 옆):
   ```kotlin
   /**
    * 현재 앱 언어의 읽기 전용 창구 (0.40.3 M1).
    * [WHY] 앱 모듈의 AppLanguageHolder 를 :domain·테스트가 직접 알지 않게 한다 — 기본값 [KO] 로 테스트는 주입 없이 한국어 동작.
    */
   interface CurrentLanguage {
       val languageFlow: StateFlow<AppLanguage>
       val current: AppLanguage get() = languageFlow.value

       companion object {
           fun fixed(language: AppLanguage): CurrentLanguage = object : CurrentLanguage {
               override val languageFlow: StateFlow<AppLanguage> = MutableStateFlow(language).asStateFlow()
           }
           val KO: CurrentLanguage = fixed(AppLanguage.KO)
       }
   }
   ```
   - `:core` 는 코루틴을 `implementation` 으로 쓴다. 공개 시그니처에 `StateFlow` 가 나오므로 `core/build.gradle.kts` 의
     `implementation(libs.kotlinx.coroutines.core)` 를 `api(...)` 로 바꾼다(`[WHY]` 한 줄).
2. **`AppLanguageHolder : CurrentLanguage`** — 기존 `languageFlow`·`current` 에 `override` 만 붙인다. 동작 변화 없음.
3. **Hilt 바인딩** — 앱 DI 모듈(예: `PlatformModule` 또는 새 `LanguageModule`)에
   `@Binds abstract fun currentLanguage(holder: AppLanguageHolder): CurrentLanguage`. 싱글턴 하나를 두 타입으로 노출.
4. **`? = null` 13개 클래스** — 아래 12개는 `private val currentLanguage: CurrentLanguage = CurrentLanguage.KO` (생성자 **마지막** 인자)로 바꾸고,
   `appLanguageHolder?.current ?: KO` → `currentLanguage.current`, `appLanguageHolder?.languageFlow` → `currentLanguage.languageFlow`.
   **테스트 전용 보조 생성자는 삭제**한다(기본값이 같은 역할).
   | 파일 | 비고 |
   |---|---|
   | `assistant/orchestrator/AssistantOrchestrator.kt` | M2 에서 한 번 더 손댄다 |
   | `domain/usecase/SendChatMessageUseCase.kt` (앱 모듈) | M2 에서 :domain 으로 이동 |
   | `feature/chat/ChatViewModel.kt` | `languageFlow` 구독 — 아래 주의 |
   | `feature/chat/result/ChatExtrasViewModel.kt` | `languageFlow` 구독 — 아래 주의 |
   | `feature/chat/result/ReminderEditor.kt` | `ReminderEditorTest:111` 이 `mockk<AppLanguageHolder>` 를 넘긴다 — 홀더가 `CurrentLanguage` 를 구현하므로 그대로 컴파일돼야 한다 |
   | `feature/episode/EpisodeSheetViewModel.kt` | |
   | `feature/memory/MemoryViewModel.kt` | |
   | `feature/profile/ProfileSheetViewModel.kt` | |
   | `feature/settings/DataResetViewModel.kt` | |
   | `feature/settings/ModelManagementViewModel.kt` | |
   | `platform/alarm/ReminderFireHandler.kt` | |
   | `platform/notification/BriefingNotifier.kt`, `DownloadNotifier.kt` | |
   - **예외 — `ui/theme/ThemeViewModel.kt` 는 바꾸지 않는다**: 언어 *선택지*(`optionFlow`)를 읽고 `setOption` 으로 쓰기까지 하므로 읽기 전용 창구로
     대체할 수 없다. 그대로 두고 CHANGELOG 에 이유를 적는다.
   - **주의 — `languageFlow` 구독**: 지금은 홀더가 null 이면 구독을 건너뛴다. 기본값이 `CurrentLanguage.KO`(값이 안 바뀌는 흐름)가 되면 테스트에서도
     구독 코루틴이 하나 돈다. 값이 바뀌지 않으므로 동작은 같지만, **E2E·Robolectric 테스트가 멈추거나 시간 초과가 나면 STOP**.
5. **`languageProvider` 11개 클래스** — 생성자 셋을 둘로 줄인다.
   - 내부 기본 생성자: `languageProvider: () -> AppLanguage` → `currentLanguage: CurrentLanguage = CurrentLanguage.KO`.
     **인자 순서는 시각(`now` 등) 뒤, 맨 끝에 둔다** — 그래야 지금 "하위 호환" 생성자를 쓰는 테스트 호출 `(a, b, c, now)` 가 위치 인자 그대로 컴파일된다.
   - "하위 호환" 생성자 삭제.
   - `@Inject` 생성자: `appLanguageHolder: AppLanguageHolder` → `currentLanguage: CurrentLanguage`.
   - 본문의 `languageProvider()` → `currentLanguage.current`.
   - 대상: `assistant/tool/` 의 `AddMemory`·`AddReminder`·`AddSchedule`·`GetSchedule`·`ListReminders`·`SearchMemory`·`SearchWikipedia` 실행기,
     `assistant/context/ContextBuilder.kt`, `assistant/briefing/MorningBriefingGenerator.kt`, `assistant/cleanup/MemoryCleanupRunner.kt`,
     `platform/speech/SpeechOutput.kt`.
   - 클래스마다 생성자 모양이 조금씩 다르다(`ContextBuilder` 는 private 기본 + 공개 둘). 원칙은 같다: **테스트 호출부가 생성부 수정 없이 컴파일되는
     순서를 우선**하고, 안 되면 생성부만 고친다(단언 불변).
6. 앱 안의 다른 `AppLanguageHolder` 주입처(`KosmosApp`·`KosmosWidget` EntryPoint 등 홀더 고유 기능을 쓰는 곳)는 그대로 둔다.

### 검증
- 게이트 녹색. 픽스처 비교 diff 없음.
- `grep -rn "AppLanguageHolder? = null\|languageProvider" app/src/main` 결과가 `ThemeViewModel` 한 곳만 남아야 한다.

### 3-2. ToolParser 텍스트 경로의 `toolCalls` (T1)

## M5 — 전체 경로(FQN) 표기 정리 (D3, 마지막 코드 마일스톤)

### 범위
- **대상**: `app`·`data`·`domain`·`core` 의 `src/main`·`src/test`·`src/androidTest` Kotlin 파일 안, **코드 위치에 쓰인** `com.kosmos.app.…` 전체 경로
  (코드 줄 기준 약 870줄). 예: `com.kosmos.app.core.common.AppLanguage.KO` → import 후 `AppLanguage.KO`.
- **제외**:
  - `package`·`import` 줄 자체.
  - KDoc·주석 안의 경로(`[com.kosmos…]` 링크 포함) — 손대지 않는다.
  - 문자열 리터럴 안의 경로(로그 태그·인텐트 액션 등) — **절대** 바꾸지 않는다.
  - **이름 충돌**: 한 파일에서 같은 단순 이름의 다른 클래스를 쓰면(예: `com.kosmos.app.R` 과 `android.R`, 다른 패키지의 같은 이름) 그 파일의 해당 이름은 전체 경로로 둔다.
  - 생성 코드(`build/`).
- `androidx.*`·`java.*`·`kotlinx.*` 등 다른 패키지의 전체 경로는 **이번 범위가 아니다**(사용자 결정 범위는 `com.kosmos.app.…`).

### 방법
- 스크립트로 해도 되지만 **모듈 하나씩**(core → domain → data → app main → app test) 바꾸고, 모듈마다 컴파일
  (`./gradlew :<모듈>:compileDebugKotlin` 또는 `compileKotlin`, 테스트는 `compileDebugUnitTestKotlin`)로 확인한다.
- import 는 파일의 기존 import 묶음에 알파벳 순으로 넣는다. 와일드카드 import(`.*`) 금지.
- 기능 변경·서식 변경(줄바꿈·들여쓰기 재정렬)을 섞지 않는다 — diff 는 "전체 경로 → 단순 이름 + import 추가"만.
- 커밋은 이 마일스톤 하나로 하되, 너무 크면 `main` / `test` 두 커밋으로 나눠도 된다(제목 끝에 `(0.40.3 M5)`).

### 검증
- 게이트 녹색. 픽스처 비교 diff 없음. 테스트 수 M3 와 동일.
- `grep -rEn "com\.kosmos\.app\.[a-z.]+\.[A-Z]" --include=*.kt app/src data/src domain/src core/src | grep -v ":\s*\(import\|package\)\|^\s*\*\|//"` 로 남은 곳을
  세어 CHANGELOG 에 "남긴 곳 N건(이름 충돌·주석)"으로 적는다.
