# 0.42.1 앞부분 고정 다이어트

> **상태**: 승인 (2026-11-17, D1~D4 계획대로). 계획·구현·검증 Claude 한 세션.
> 정본 순서: **AGENTS.md > 이 계획서**.
> 근거: 0.42.0 exp94 — 앞부분 약 1,210토큰 중 툴 관련 약 890(선언 약 590 · 트리거 줄 약 300). 사용자 의견(2026-11-16): 컨텍스트가 여러 단계 계획의 병목.
> 턴마다 선언을 바꾸는 라우팅은 기각(재프리필·툴 누락, ADR-040 기각란) → **매 턴 같은 앞부분을 짧게** 만들어 대화 재사용·미리 준비를 지킨다(0.21.0 다이어트와 같은 결).

## 목표
1. 앞부분(시스템 지시 + 툴 선언)을 줄여 **대화 기록 몫을 늘린다** — 실측이 줄면 예약 `PREFILL_OVERHEAD_TOKENS`(지금 1,450)를 같이 내린다. 줄인 만큼이 매 턴 기록 몫이다.
2. 헷갈리는 툴 선택 두 가지를 문구로 고친다(exp94 6/64): "약속 언제였지?"·"치과 몇 시라고 했지?" → 일정 조회 대신 기억 검색, "내일 회의 있는 거 기억해 둬" → 일정 추가 대신 메모 저장.

## 지금 앞부분 (fixture `system_instruction.txt`, 선언은 `KosmosToolDeclarations`)
- 머리 4줄(역할·언어·말투) · `[System Data]` 날짜 줄(요일별 엿새 포함) · 트리거 규칙 7줄(툴마다 한국어 낱말 목록 + "you MUST call") · 공통 규칙 4줄.
- 선언 6종(웹·문서 검색 꺼짐): 설명은 이미 짧고, 크기의 대부분은 런타임이 그리는 스키마(인자 이름·형식). 인자 설명 중 긴 것: `get_schedule.range`, `search_memory.keyword`, `add_memory.tags` 예시.

## 결정 (사용자 승인 2026-11-17)
- **D1 목표치** — 앞부분 −200토큰 이상을 목표로 하되, 회귀 세트 새로 깨진 것 0 인 안만. 못 미치면 줄인 만큼만 적용(억지로 맞추지 않는다).
- **D2 줄인 몫의 쓰임** — 예약 `PREFILL_OVERHEAD_TOKENS` 를 실측에 맞춰 내려 **대화 기록 몫으로 돌린다**(추천). 설정 "대화 기억 범위" 하한·기본값은 그대로 두고 기록 몫만 는다.
- **D3 헷갈리는 질문의 정답** — "약속·예약 + 언제/몇 시였지"는 **일정 조회 먼저**(약속은 일정으로 저장되므로), "일정 + 기억해 둬"(날짜·시각 있음)는 **일정 추가**. 이렇게 정해도 될지.
- **D4 "세부 규칙을 불린 뒤로"의 범위** — 후보를 실측으로만 옮긴다: ① 날짜 줄의 요일별 엿새(약 40토큰 — 0.41.13 요일 가드가 틀린 날짜를 고쳐 주므로 빼도 되는지) ② 일정 규칙의 "never ask for end_time or memo"(부르기 전에 필요한 규칙이라 옮기면 되묻기가 돌아올 수 있음).
  효과가 떨어지면 그대로 둔다.

## 고정 제약
- 모델 입력 변경 → `engine.tokenize` 실측, `MEASURED_OVERHEAD`(KO·EN) 갱신, `kosmos_lab.py`·`run.py` 미러, 픽스처 재생성, 회귀 세트(AGENTS §2-⑤). 한/영 같이(영어 시스템 지시 `system_instruction_en.txt` 도).
- 선언과 트리거 규칙에 같은 정보를 두 번 쓰지 않는다(AGENTS §2-⑤).
- 기존 테스트 단언 불변(선언 문구를 고정한 단언이 있으면 보여 드리고 확인). 실험 `exp95`~, 출력 커밋 안 함. 휴대폰 사용 없음.
