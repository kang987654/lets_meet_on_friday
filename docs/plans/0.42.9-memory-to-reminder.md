# 0.42.9 기억 → 알림 (한국어)

> **상태**: 계획 (승인 대기).
> 정본 순서: **AGENTS.md > 이 계획서**.
> 근거: 0.42.6 exp101 묶음 C(실험실 PC, 기록 신뢰 — 다시 돌리지 않음). 회차 성격: 전체 흐름 2단계(여러 단계 계획)의 남은 과제.

## 지금 모습 (exp101, 문항 × 2회)
| 문항 | 결과 | 모습 |
|---|---|---|
| C1 "내가 알려준 병원 예약 시간에 알림 맞춰줘" | 0/2 | `search_memory` 대신 `list_reminders({})` → 되묻기(괜찮은 실패) |
| C2 "병원 예약 하루 전에 알림 맞춰줘" | 0/2 | 기억을 찾지 않고 **지금 시각**(`[Now]` 11-08 10:53)으로 `add_reminder` → "맞춰 드렸어요"(해로운 실패) |
| C-en "Set a reminder at the hospital appointment time I told you about" | 2/2 | 기억 검색 → 11-12 14:00 알림 |
| D1 "내일 첫 일정 30분 전에 알려줘"(조회 → 계산 → 쓰기) | 2/2 | 대상이 분명하면 두 단계도 된다 |

- 앱은 이미 **지난 시각 알림**을 시트 전에 되돌린다(`AddReminderToolExecutor` — "이미 지난 시각입니다. 미래의 시각으로 다시 호출하세요."). exp101 은 이 결과를 흉내 내지 않아서, C2 가 앱에서 어떻게 끝나는지는 모른다(다시 지어낸 미래 시각으로 부를 수 있다).
- 알림에는 일정의 "몇 시 없음" 가드(`ScheduleTimeIntent.needsClock`)가 없다 — 시각 근거 없는 `add_reminder` 가 그대로 시트까지 간다.
- 가드는 이번 턴 앞선 툴 결과를 보지 않는다(`ToolCallGuards.check` 인자: 사용자 말·앞 비서 말·앞 사용자 말·시작 시각).

## 결정 (승인 때 정할 것)
- **D1 처방 — 실측(M1)으로 고른다.** 결과가 나은 쪽, 같으면 단순한 쪽(앞부분을 늘리지 않는 쪽).
  - **G 가드 (먼저 볼 후보)**: 시각 근거 없는 `add_reminder` 를 막고 돌려준다 — 예 "실행하지 않았습니다. 몇 시인지 정해지지 않았습니다. 사용자가 전에 알려 준 일이면 search_memory 로 먼저 찾아보고, 없으면 몇 시인지 물어보세요." 막힐 때만 비용이 들고 고정 앞부분은 늘지 않는다. 문구는 실측으로 고른다(2~3안).
  - **T 트리거 한 줄**: "사용자가 전에 알려 준 일을 가리키면('내가 알려준', '메모해 둔') 먼저 `search_memory`." 고정 앞부분이 늘어(수십 토큰 추정) `MEASURED_OVERHEAD` 실측·갱신이 따른다(§2-⑤).
  - **G+T**: 둘 다 — G 만으로 모자랄 때만.
- **D2 시각 근거로 인정하는 것 (G 를 고르면)** — 이번 사용자 말의 시계 시각(`ScheduleTimeIntent.hasClock` — "3시"·"10분 뒤"·"정오" 등), 앞 비서 말의 시각(대답일 때만 — 0.42.7 `isReply` 와 같은 규칙), **이번 턴 앞선 툴 결과의 시각**(기억 검색이 돌려준 "11월 12일 오후 2시" → 하루 전 계산을 막지 않으려면 필요). 세 번째는 가드에 인자를 하나 더한다.
- **D3 몇 시 없는 알림은 묻는다 (추천, 사용자 확인)** — G 를 넣으면 "내일 아침에 알려줘"처럼 시간대만 있는 알림도 막혀 "몇 시에 알려 드릴까요?"가 된다. 일정의 0.41.15 결정 (가) "몇 시가 없으면 묻는다"와 같은 모습. 지금은 모델이 시각을 골라 시트를 띄운다.
- **D4 범위 — 알림만 (추천)**: "내가 알려준 회의 시간에 일정 잡아줘"도 같은 모양이지만, 일정은 이미 몇 시 가드가 막고 묻는다(되묻기 — 괜찮은 실패). 일정 가드 문구(exp92 실측)는 바꾸지 않는다.

## 고정 제약
- 모델 입력(툴 결과 문구 포함)을 바꾸는 회차 — 실험실 실측 + 회귀 세트(§2-⑤). 회귀 세트에 알림 흉내(지난 시각 되돌림 + 새 가드)를 넣고, 새 묶음 `remind_mem`(기억 → 알림 문항)을 더한다. 기준값 저장은 결과 확인 뒤에만.
- 대조 문항이 깨지면 안 된다: "3시에 알려줘"·"10분 뒤에 알려줘"(바로 시트), "알림 뭐 있어"(`list_reminders`), "내일 첫 일정 30분 전에 알려줘"(D1 그대로), 영어 C-en.
- 기존 테스트 단언 불변. 휴대폰 확인은 짧게(약 5분, 미리 묻기) — 재현·진단은 에뮬레이터.

- 문항: 기억 → 알림 한국어 6(C1·C2 + "메모해 둔 회의 10분 전에"·"내가 말한 치과 시간에"·"전에 알려 준 약속 전날 저녁 8시에" 등, 기억에 시각이 있는 것 4 · 없는 것 1 · 기억 자체가 없는 것 1) + 영어 1 + 대조 5, × 2회.

- 테스트: 근거 없는 알림 막힘 · 사용자 말/앞 비서 대답/이번 턴 툴 결과의 시각이면 통과 · 대조. 게이트.
