# 0.42.6 여러 단계 요청 — 지금 어디까지 되나 (실측 회차)

> **상태**: 완료 (CHANGELOG 0.42.6). 다음 회차 선택지는 CHANGELOG 0.42.6 [Note].
> 정본 순서: **AGENTS.md > 이 계획서**.
> 전체 흐름 2단계(0.42 의 원래 주제 — 묶음 D). 이 회차는 **재기만** 한다 — 무엇을 만들지는 결과를 보고 다음 회차 계획에서 정한다.

## 지금 구조
- 한 턴 안에서 툴을 **최대 3번** 이어 부른다(`BaseAgent.MAX_TOOL_LOOP_COUNT`) — 결과를 받은 모델이 다음 툴을 부를 수 있다. 넘으면 "툴 호출 반복 상한" 오류.
- 쓰기 툴(일정·알림·메모)은 부를 때마다 승인 시트. 툴 결과는 `TOOL_RESULT_MAX_TOKENS`(500)까지, 대화 예산을 넘을 것 같으면 툴 반복 KV 가드(0.41.6).
- 앞부분 약 1,150토큰(0.42.1) — 사용자 의견(11-16): 컨텍스트가 여러 단계의 병목.

## 재는 것 (exp101, 실험실 PC — 회귀 세트 `turn()` 을 늘려 툴 3번까지 잇는다)
| 묶음 | 예 | 정답 순서 |
|---|---|---|
| A 조회 → 판단 → 쓰기 | "내일 일정 확인하고 비는 시간에 치과 예약 잡아줘" | get_schedule → add_schedule(빈 시간) |
| B 같은 쓰기 여러 개 | "내일 3시 치과, 5시 팀 미팅 둘 다 잡아줘" | add_schedule × 2 |
| C 기억 → 쓰기 | "내가 알려준 병원 예약 시간에 알림 맞춰줘" | search_memory → add_reminder |
| D 일정 → 알림 | "내일 첫 일정 30분 전에 알려줘" | get_schedule → add_reminder |
| E 한 번에 안 되는 것 | "이번 주 일정 다 지우고 다시 잡아줘"(지우기 툴 없음) | 못 한다고 말함 |
| 영어 | A·B·C 각 1 | 같음 |

- 문항당 2회, 가짜 툴 결과(일정·메모)는 고정. 판정: **정답 순서로 끝까지** · 중간에 멈추고 묻기(괜찮은 실패) · 틀린 툴/인자 · 지어낸 성공("잡았어요"인데 호출 없음) · 상한 초과.
- 함께 기록: 턴당 프리필·KV 증가(툴 결과가 쌓이는 양), 걸린 시간(PC 비율로만).

## 결과로 정할 것 (다음 회차 계획에서)
- **D1 무엇을 만들까** — 대부분 되면: 승인 시트 여러 장을 묶는 UX·상한 조정 정도. 자주 끊기면: 계획을 먼저 말하게 하기(턴 리마인더) / 앱이 단계를 나눠 이어 주기 / 4B 한계로 범위 좁히기.
- **D2 쓰기 여러 개의 승인** — 시트를 한 장씩(지금) vs 한 장에 묶기. 실측에서 B 가 되면 정한다.
- **D3 상한 3** — 모자라면 늘릴지(KV·시간 비용과 함께).

## 고정 제약
