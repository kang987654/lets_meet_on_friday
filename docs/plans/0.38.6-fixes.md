# 0.38.6 — 결함과 넘긴 것 정리

## 목표
실기기 확인에서 나온 **생성 취소 뒤 모든 입력이 취소되는 결함**을 먼저 고치고, 0.38.5 impeccable 점검에서 넘긴 화면 항목과
모델 답·글의 어색함을 정리한다. 모델 입력을 바꾸는 항목은 §2-⑤대로 실험실 실측이 먼저다.

## 정한 것 (2026-10-23 사용자)
1. **넘긴 후보는 전부 이번 회차** — 단 엑셀 셀 서식(배경·글자색·굵기·정렬)은 0.38.7 로 분리. 표 열 잘림은 이번에.
2. **일정·알림·메모 거절은 고정 문장으로 턴을 끝낸다** — 거절하면 모델을 다시 부르지 않고 해요체 고정 문장("알림을 등록하지 않았어요." 등)으로
   답한다. 앞 턴 따라 하기·지시문 읊기·거절을 오류로 말하기가 구조적으로 사라지고 예산 0. `ToolApprovalE2ETest` 거절 분기 단언 변경은 대상을 보이고 확인.
3. **프로필 제안은 체크 목록으로 골라 저장** — 기본 전부 체크, 체크를 푼 항목은 거절(무시와 같음).
4. **모델이 쓰는 요약·합치기 글은 지시를 해요체 공통 형식으로 바꾸고 재측정** — 이미 저장된 3인칭 글은 그대로 둔다(섞임 허용).

## 조사에서 확인한 사실 (2026-10-23)
- **취소 결함**: "Task cancelled"는 litert-lm 네이티브 문자열(상태 코드 1 → `CancellationException`). 앱은 채팅 Conversation 을 캐시해 재사용하는데
  (`ConversationPolicy` Reuse, 툴 회신 턴은 무조건 Reuse) 취소·실패 뒤 캐시를 버리는 코드가 없다(`GemmaModelRunner` 오류 경로). 취소 상태가 그 대화에 남으면
  매 턴 즉시 실패하고 엔진 해제(앱 재시작·백그라운드) 전까지 풀리지 않는다 — 증언과 일치. `cancel()` 은 `activeConversation ?: conversation` 으로 **쉬고 있는
  캐시 대화에도** `cancelProcess` 를 건다(음성 턴의 전사 직후·프롬프트 조립·승인 대기 구간). 사용자 취소는 주석과 달리 부분 답 보존이 아니라 오류 말풍선.
  GemmaModelRunner 테스트 없음, 가짜 러너의 `cancel()` 은 빈 함수.
- **프로필 "외 2건"**: 실제로는 첫 건만 저장(`ChatScreen` → `acceptSuggestion(first)`). "나중에"는 첫 건 id 만 기억해 남은 제안 전체를 숨긴다.
- **표 열 잘림**: 너비 정보 없는 시트는 글자 수 × 고정 폭(ASCII 7.5dp)으로 어림 — HadaRound 숫자가 더 넓어 "100…". xlsx `<col width>` 환산 계수 7dp 는 실제(약 11.7dp)보다 좁다.
- **승인 [취소]**: 카탈로그 02 에서 면이 이미 전부 하늘색으로 차 [추가하기]와 무게가 비슷하다.
- **기억 카드**: 지난 대화만 근거면 `ref` 가 비어 있고 누르면 메모 화면으로 간다. 근거 에피소드 id 는 화면 전용 meta 에 없다(`recallEpisodeIds` 는 턴 전체 합).
- **합니다체 내부 사유**: 활동 기록에 실제로 보이는 것은 전사 실패(`TranscribeAudioUseCase` "전사 결과가 비었습니다", `SttError(reason=…)` 원문 노출)와 문맥 구성 실패(`AssistantOrchestrator`).
- **모델 답**: 거절·메모 거절 문구는 툴 결과(턴 몫). 툴 밖 요청 거절·메모 오호출·불필요한 기억 검색은 시스템 지시·트리거(고정 몫, 여유 13).
  exp56 이 말포이 사례를 재현 못 한 이유는 웹 검색 툴을 켠 채 돌렸기 때문 — 휴대폰은 꺼져 있었다. 요약·합치기 지시와 거절 문구는 픽스처로 내보내지 않는다.
