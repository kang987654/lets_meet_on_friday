# 0.41.15 반복 질문 처방 · 몇 시 없는 일정 가드

> **상태**: 승인 (2026-11-16) — 계획·구현·검증 Claude 한 세션. 사용자 결정: 두 주제를 한 회차로(회귀 세트 한 번), 일정은 (가) "몇 시가 없으면 묻기".
> 정본 순서: **AGENTS.md > 이 계획서**.
> 근거: CHANGELOG 0.41.13 — exp90(반복 질문 일반 거절 원인), exp89 1-A(시간대 낱말만 말한 일정 26/28 이 오늘 날짜·지어낸 시각).

## 목표
1. **반복 질문 일반 거절** — `RepeatedQuestions.forModel` 이 값이 안 바뀐 단순 반복에서도 앞 질문·답을 빼, ① 기록이 비면 검색 없이 "정보가 없어요" 거절(exp90 Part 2, 2/14)
   ② 앞의 개인정보형 거절이 바로 앞 답 자리로 올라와 따라 함(S7, 4/14) ③ 방금 대화에서 말한 값을 잊음(S2, 정답 10/14 → 빼지 않으면 14/14).
2. **몇 시 없는 일정** — "아침 운동 일정 추가해줘"·"저녁 약속 일정 넣어줘"처럼 시간대 낱말만 있으면 모델이 오늘 날짜에 시각을 지어내 넣는다(exp89 1-A 26/28 — "아침 운동" → 오늘 10:53).
   0.41.11 일정 가드(`ScheduleTimeIntent`)가 아침·저녁·오늘·내일 같은 낱말도 시각으로 쳐 통과한다.

## 결정
- **D1 반복 질문 (처방 A)**: 앞의 같은 질문과 지금 질문 **사이에 질문이 아닌 사용자 말**(값을 바꾸는 진술 — "아니야, 4821이야")이 있을 때만 앞 질문·답을 뺀다. 없으면 그대로 둔다.
  판정은 기존 `isQuestion`. "응"·"고마워"도 질문이 아니라 빼는 쪽으로 간다 — 지금 동작과 같아 손해는 없다(좁힐지는 M1 실험을 보고, 넓히면 멈추고 묻는다).
- **D2 일정 (가)**: `add_schedule` 은 이번 턴 사용자 말이나 바로 앞 비서 말에 **시계 시각**(숫자+시·분, `HH:MM`, 한글 수+시, 정오·자정, am/pm·o'clock)이 있어야 실행한다.
  - 날짜·시간대 낱말만 있으면(아침·저녁·내일·금요일 등) 막고 "몇 시인지 물어보라"는 새 안내를 돌려준다.
  - 날짜·시간대 낱말도 없으면 지금 안내(`NO_TIME` — 사실 문장 가드, "메모해 둘까요?")를 그대로 쓴다. 사실 가드의 행동은 바꾸지 않는다.
  - 바로 앞 비서 말에 시각이 있으면 통과("저녁 7시로 잡을까요?" 뒤 "응") — 현행 유지.

## 고정 제약
- 바꾸는 모델 입력: 대화 기록 구성(D1)과 새 가드 안내 문구(D2) 둘뿐. 시스템 지시·툴 선언·리마인더 불변 → `MEASURED_OVERHEAD` 불변이어야 한다(바뀌면 멈춤).
- 회귀 세트 흉내(`run.py` 의 `repeated_drop`, `SCHEDULE_TIME`)를 앱 판정과 같이 고친다(AGENTS §2-⑤). 기준값 저장은 결과를 보인 뒤.
- 기존 테스트 단언 불변. 0.41.11 `ScheduleTimeIntentTest` 에 "시간대 낱말은 통과"를 고정한 단언이 있으면 D2 가 그 동작을 일부러 바꾸는 것이라 **대상(파일:줄)을 보여 드리고 확인** 후 변경(§2-② 예외).
- 한/영 같이. 실험 스크립트 새로(`exp91`·`exp92`), 출력 커밋 안 함. 휴대폰 사용 없음.
