# 0.42.5 지난 시각 일정 · 종료 시각 되묻기 · 기억 검색 "다른 값" 잡음

> **상태**: 승인 (2026-11-18 — D1 (가), D2·D3 는 실험 뒤 결정). 계획·구현·검증 Claude 한 세션.
> 정본 순서: **AGENTS.md > 이 계획서**.
> 전체 흐름(2026-11-18 사용자 승인): 1 작은 모델 행동 정리(이 회차) → 2 여러 단계 계획 → 3 앱 결함 → 4 실사용 준비(0.43) → 5 실사용 → 6 포트폴리오.
> 후보 대조: "사실을 일정으로"(0.41.11 M1)·"조건형 저장 물음"(0.41.10 M1)·채팅 점프·모델 관리 내려받기(0.41.10 M2·M3)는 **이미 고쳐짐** — 3단계 앱 결함 몫은 아래 M3 하나만 남아 이 회차에 합친다.

## 근거
1. **지난 시각으로 일정** — 11-17 휴대폰 13:40 에 "아침 운동 일정 추가해줘" → "7시" → 시트 "오늘 07:00~08:00"(이미 지남). 시스템 지시 날짜 규칙이 "A time with no date word means today." 라 모델이 그대로 따른다.
2. **종료 시각 되묻기** — 같은 흐름에서 "7시"에 툴을 부르지 않고 "종료 시간은 몇 시로 할까요?". 트리거 줄에 "never ask for end_time or memo" 가 있는데도 — exp92(0.41.15)에서도 "종료 시각까지 묻는 답이 섞인다"고 기록.
4. **병원 이름을 물음** — 0.39.2 휴대폰: "모레 오전 10시에 치과 예약 잡아줘"에 등록 대신 병원 이름을 물었다(새 대화로는 3/3 등록). "재현 빈도부터"로 넘겼으나 재지 않았다.
5. **실기기 확인 목록이 어긋남** — `device_gate.md` 일부 미체크 칸은 이미 확인됨(0.41.10 휴대폰), 0.41.10~11 두 칸은 휴대폰 미확인, 0.42.x 항목은 목록에 없다.
3. **기억 검색 "다른 값" 잡음** — 0.39.2 실기기: "(과거 대화) N건에는 다른 값: 5, 214, 6043…"이 질문과 무관한 숫자를 긁었다(`RecallConflict.otherValues`). 지금도 재현되는지 미확인.

## 결정 (승인 때 정할 것)
- **D1 지난 시각 처리** — 시스템 지시를 바꾸지 않고 앱 가드로(요일 가드 G1 과 같은 결, ADR-030).
  `add_schedule` 의 시작 시각이 지금보다 과거이고 사용자 말에 날짜 낱말("오늘"·"어제" 등)이 없으면 막고, 결과 문구로 "오늘 그 시각은 지났으니 내일인지 물어보세요"를 돌려준다.
  (가) 막고 묻게(추천 — 기존 가드와 같은 모양, 다음 턴 "응"이면 내일로) / (나) 앱이 내일로 바꿔 승인 시트에 띄움(턴이 줄지만 모델 답 "오늘 7시에 추가할게요"와 시트 날짜가 어긋난다).
  결과 문구는 실험실 실측(exp99)으로 고른다 — 툴 결과도 모델 입력이라 §2-⑤.
- **D2 종료 시각 되묻기** — 실험실에서 빈도부터 잰다(exp99 같은 판). 자주면(예: 4/8 이상) 후보: 시각을 답한 턴의 툴 결과·턴 리마인더에 짧은 구절 / 드물면 한계로 기록. 시스템 지시를 늘리는 안은 0.42.1 다이어트와 충돌해 뒤로.
- **D3 "다른 값" 잡음** — 실험실에서 재현부터(합성 메모·요약). 재현되면 질문과 같은 대상의 숫자만 남기도록 `RecallConflict` 를 좁힌다(결과 문구가 바뀌면 회귀 세트 `overlap` 확인). 재현 안 되면 기록만.

## 고정 제약
- 툴 결과 문구·가드를 바꾸므로 회귀 세트(`clock`·`weekday`·`overlap` 포함 전체) + `run.py` 흉내 갱신. 기준값 저장은 확인 뒤.
- 시스템 지시·툴 선언 불변 목표 → `MEASURED_OVERHEAD` 불변. 바뀌면 실측·갱신.
- 시각 판정은 `now` 인자(§2-④), 테스트는 UTC 명시. 기존 테스트 단언 불변.
- 휴대폰: 회차 끝 짧은 확인만(미리 묻기). 진단은 실험실·에뮬레이터.

- 0.42.5 · 42005, 이 계획서.

### M1 — 지난 시각 가드 (exp99, D1)
- exp99: 오후 시각 픽스처에서 "아침 운동 일정 추가해줘 → 7시", "7시에 헬스 일정 잡아줘", "아침 9시 회의 넣어줘" 등 8문항 × 2회. 지금 / 가드 + 문구 후보 2~3개 →
  다음 턴 "응" 뒤 내일 날짜로 넣은 비율 · 오늘 과거로 넣은 비율 · 엉뚱한 답.
- 같은 판에 **병원 이름 물음** 문항("모레 오전 10시에 치과 예약 잡아줘" 등 3~4개, 앞 기록 있음·없음)을 넣어 재현 빈도를 잰다 — 자주면 처방 후보를 CHANGELOG 에, 드물면 기록만.
- 구현: `ScheduleTimeIntent`(또는 새 `SchedulePastIntent`)에 판정(순수 함수, `now` 인자) → `ToolCallGuards` 에 한 단계. 영어 문구 같이. 테스트.

### M2 — 종료 시각 되묻기 (exp99 같은 판, D2)

### M3 — 기억 검색 "다른 값" (exp100, D3)
