# C1+C′3 기억 검색 — 바이그램 스코어러 + 미스 시 모델 확장 (0.25.0)

## Context

기억 회수 정확도는 비서 신뢰의 바닥이다(expand.md:143). 지금 `SearchMemory` 툴과 드로어 검색은
SQLite `LIKE '%키워드%'` 부분 일치 + "맞은 토큰 수" 랭킹이다 — 글자가 조금만 어긋나면("자물쇠번호" ↔
"자물쇠 비밀번호") 놓치고, 동의어(자물쇠 ↔ 비밀번호)는 태그 목록 재호출에만 의존한다. exp33
(2026-08-15)은 **모델 검색어 확장 + 문자 바이그램 겹침 점수**로 16문항 recall@1 16/16 을 재어 두었고,
이 회차는 그 측정을 앱으로 옮긴다.

**현황 (탐색 확정)**:
- `SearchMemoryToolExecutor`(app/assistant/tool): 키워드 공백 분리(≤4) → 토큰마다 지식 LIKE·태그, 에피소드
  LIKE·태그 4쿼리 → `LinkedHashMap` 에 "맞은 토큰 수"로 합산 → createdAt 보조 정렬 → 상위 3. 0건이면
  `searchRecent(50)`+`getEpisodes(0,50)` 의 태그 목록(≤20)을 돌려 재호출 유도. 결과 봉투
  `{"status","data","meta":{"episodeIds"}}` 는 BaseAgent 의 🧠 칩 계약(`BaseAgentStreamTest`).
- 계약을 고정한 테스트 8개가 `MemoryPipelineIntegrationTest` 에 있다(단언 불변): 저장→키워드 회수 /
  **두 토큰 맞은 노트가 앞** / 태그 경로 / **0건 → 태그 목록 + "한 번 더 호출"·"지어내지 마세요"** /
  기억 0건 문구 / `search` 실패 → error / 빈 키워드 → `ToolArgumentException`. 이 테스트들은
  `repository.search/searchByTags` 를 토큰별로 mock 한다 → **정밀 LIKE 후보 단계는 그대로 두고** 그 뒤에
  바이그램을 얹는 구조여야 단언이 산다. 특히 "좋아하는 것" 질의는 여전히 태그 목록으로 떨어져야 한다
  (→ 바이그램 스캔에 **최소 겹침 임계**가 필요: "좋아하는"의 바이그램 3개 중 "좋아" 1개 = 0.33).
- Room 에는 `@Fts5` 가 없고 FTS5 내장 토크나이저에 바이그램이 없다(`unicode61` 은 한글을 어절 단위로만
  자름 — 0.x 에서 FTS4/5 를 기각한 이유). 프레임워크 SQLite 라 OEM 가용성 프로브도 필요. exp33 의
  16/16 은 **인메모리 바이그램 스코어러**(`score()` = 항별 겹침 비율 합)로 잰 수치이며 FTS5 bm25 가 아니다.
- 드로어 검색(`DrawerViewModel.searchResults`)은 에피소드 LIKE+태그 결과를 **정렬 없이** 이어 붙인다 —
  ui_a_prime.md:47 의 "드로어와 SearchMemory 가 같은 색인" 원칙이 아직 사실이 아니다.
- 자동 RAG 주입은 죽었다(ADR-013) — 지식·에피소드는 오직 `SearchMemory` 결과(≤3건·≤400토큰)로 모델에 닿는다.
- 프롬프트 표면(툴 선언·트리거)은 **건드리지 않는다** → `MEASURED_OVERHEAD` 1,277 유지(여유 23토큰).
- 실험실: `exp33` retrieve 는 폐기 API(`K.Lab/Config`)에 묶여 못 돌린다 → 현행 API 로 포팅(exp37).
  코퍼스 `exp33_summaries.json`(9 문서, gitignore)·질문 16개 재사용.

   스코어러만 넣는다.

## M0 — 실험실 실측 (exp37)

`scratch/lab/exp37_memory_retrieval.py` (exp35/36 템플릿, 현행 API). 코퍼스 = exp33 요약 9 문서(`title tags
summary`)+ 픽스처 지식 1건. 질문 = exp33 의 16문항(정답 에피소드 매핑 포함, 바꿔 말하기 2쌍).

- **단계 ①**: 질문마다 **실제 앱 프롬프트**(`fixture("system_instruction.txt")` + 툴 6종 + 턴 리마인더)로 모델의
  `search_memory.keyword` 인자를 받는다 — 앱이 실제로 검색하는 문자열. 툴 미호출은 기록(회수 실패로 계산).
- **단계 ②** 네 조건의 recall@1 (코퍼스 9라 @3 은 무의미 — exp33 주의 그대로):
  - **A 현행**: 공백 분리 토큰, 부분 일치(LIKE 대용 `in`) 문서 수 카운트, 동점 최신순.
  - **B 바이그램**: 토큰 바이그램 겹침 합(exp33 `score()` 원문).
  - **C 바이그램+확장**: B + 확장 oneShot 키워드(EXPANDER 원문에 `[System]` 영어 프리픽스 관례 적용 — 이 최종
    문구로 재야 한다) + 원 키워드.
  - **D 앱 정책**: A 적중(≥1) → A 후보를 B 점수로 재정렬 / A 0건 → 확장 → 전수 스캔, **최소 항 겹침 0.5** 임계.
    D 에서 확장이 실제로 돈 횟수와, 확장 없이 D 를 돌린 결과(D′)를 함께 낸다.
- **판정 지표 추가**: 임계 0.5 가 "좋아하는 것 ↔ 커피보다 녹차…(태그 선호도)" 를 **통과시키지 않는지**
  (기존 태그 목록 계약 보존) 합성 케이스로 확인.
- **게이트**: D ≥ 14/16 이고 D ≥ A. **확장 포함 여부** = D − D′ ≥ 2문항이면 포함, ≤1 이면 M2 생략(결정 2).
  실패(D < 14) → 임계 조정(0.4/0.6) 1회 재실측 → 그래도 실패면 중단·보고.
- 결과·확정 문구를 `scratch/lab/README.md` 에 기록. 출력(`exp37_results.json`) gitignore.

     "두 토큰 맞은 노트가 앞" 단언은 2.0 > 1.0 으로 보존.
