# 0.41.9 — 오래 쉰 뒤 첫 답 (빈 기록 미리 읽기 · 요약의 결과 표기 · 픽스처 시각 고정)

## Context
- **쉰 뒤 첫 답 약 4.6초** — 0.41.7 M4 이후 30분 넘게 쉬면 지난 대화를 모델 기록에서 빼고 시스템 지시 끝 요약 한 줄로 바꾼다(`IdleGapHistory`).
  그러면 기록이 비어 `GemmaModelRunner.prepareConversation` 이 `last == null` 에서 멈춘다 — 대화 만들기(문법 준비)까지만 하고
  시스템 지시는 첫 사용자 send 에서야 읽힌다(exp66b: 대화 생성은 문법 준비뿐, 기록은 첫 send 에서 읽힌다). 휴대폰: 프리필 1,294토큰 약 4.6초를 그 턴이 치렀다
  (미리 준비가 있으면 첫 글자 약 0.5초, 아예 없으면 10~12초 — 0.41.7 M0).
  앱에는 새 세션이 없고(세션 하나), 간격 뒤 요약이 없으면 원문을 그대로 싣으므로(F1) **기록이 비는 경우는 "간격 + 요약 있음" 하나뿐**이다 —
  즉 기록이 빌 때는 언제나 보낼 수 있는 요약이 있다(사용자 지적, 2026-11-09).
  지금 미리 준비는 빈 메시지가 아니라 **기록의 마지막 비서 답(실제 메시지)** 을 model 역할로 보내 시스템 지시+기록을 KV 에 올린다 —
  다음 턴의 프롬프트 앞부분과 글자 그대로 같아서 KV 를 이어 쓸 수 있다. 기록이 비면 보낼 실제 메시지가 없다는 것이 이번 문제다.
- **엔진 API 확인 (litertlm-android 0.19.0 jar, 2026-11-09)** — `Conversation` 에는 프리필만 하는 함수가 없다(`sendMessage`·`sendMessageAsync`·`clone`·`getTokenCount`·
  `renderPrefaceIntoString` 뿐). `Session.runPrefill` 은 있지만 대화 API(템플릿·툴 호출) 밖의 낮은 층이라 앱 구조와 맞지 않는다 → 미리 읽으려면 **무언가를 send 해야 한다**.
- **요약의 "요청했다"** — 휴대폰에서 간격 뒤 "What did I ask you about Spain earlier" 에 기억 검색을 거쳐 맞게 답하면서
  "B2-17 메모를 저장해 달라고 요청하셨던 것도 기억하고 있어요"를 덧붙였다. 실제 저장은 취소됐다. 요약 지시문(`SummarizeEpisodeUseCase.SYSTEM_INSTRUCTION`·`_EN`)은
  "누가 무엇을 했는지"만 요구하고 **요청의 결과(했다·취소·거절)** 는 요구하지 않는다 → 요청만 남은 요약이 저장된 것처럼 읽힌다.
- **픽스처 시각** — `PromptFixtureExportTest` 가 `assembleWithTools` 의 기본값(벽시계 `today`·`now`)으로 픽스처를 내보낸다. 턴 리마인더의 `[Now]` 가
  실행 시각마다 달라 회귀 세트 1건이 시각 탓에 깨졌다(0.41.7: 17:28 → 실패, 10:53 → 20/20).

## 결정 필요 (M0 뒤 사용자에게 묻는다)
- **빈 기록 미리 읽기 방식** — M0 실측을 보고 고른다(후보는 M0).
- **이미 만들어진 요약** — 지시문을 바꾸면 새 요약부터 적용된다. 기존 요약을 다시 만들지는 기본 "안 함"(쓰는 사람이 한 명이고, 요약은 30분마다 새로 쌓인다).

## 고정 제약
- 기존 테스트 단언 불변(바꿔야 하면 먼저 보이고 확인). E2E 계약 표면 불변.
- 모델 입력이 바뀐다(미리 읽기 방식에 따라 대화 KV·요약 지시문) → **실험실 실측 선행**(§2-⑤), 회귀 세트 다시 실행·`baseline.json` 차이를 CHANGELOG 에, 기준값 갱신은 확인 뒤.
  시스템 지시·툴 선언은 바꾸지 않을 계획이라 `MEASURED_OVERHEAD` 는 그대로(바뀌면 실측).
- 실험실 미러: 요약 지시문은 픽스처(`episode_summary_system.txt`)로 읽히는지 M0 에서 확인하고, 아니면 미러를 함께 고친다.
- 미리 읽기는 지금처럼 입력이 멎은 뒤·시작 단계에서만(§2-⑥, 0.41.7 원칙 "입력 중 버벅임 없음"). 백그라운드 로드 금지. 휴대폰에 파일을 남기지 않는다(§2-③).

## 마일스톤

### M0 — 실험실 실측 (PC, 앱 코드 수정 없음)
- **exp84 빈 기록 미리 읽기** — 픽스처 시스템 지시로, 기록 없는 대화에서 첫 질문의 프리필 토큰·시간과 후보별 결과를 잰다.
  - **원리상 제약** — 미리 보낸 메시지는 KV 에 남으므로 다음 턴의 실제 프롬프트에도 **같은 자리에 같은 글자로** 있어야 이어 쓸 수 있다.
    그래서 "요약을 미리 보내기"(사용자 제안)는 요약이 **대화 기록의 메시지가 된다**는 뜻이고, 시스템 지시 끝에도 두면 두 번 실린다.
  - **ㄱ 요약을 메시지로 보내기**(사용자 제안) — 요약 줄을 시스템 지시 끝 대신 기록 첫 메시지로 두고, 미리 준비가 지금 경로대로 그 메시지를 보낸다. 역할별로 잰다:
    - ㄱ-model: model 역할 — exp81 에서 4/5(요약 속 "비서가 물어봤어요"를 자기 질문으로 읽음), 시스템 지시 끝 5/5 보다 낮았다.
    - ㄱ-user: user 역할에 `(과거 대화)` 꼬리표 — 재 본 적 없다. 사용자가 방금 한 말로 읽고 답하려 드는지 본다.
    - ㄱ-둘 다: 시스템 지시 끝은 그대로 두고 메시지로 한 번 더 — 요약 토큰이 두 배, 같은 말 반복이 답을 끌어가는지 본다.
  - **ㄴ 빈 메시지** — 내용 없는 메시지로 시스템 지시만 KV 에 올린다. 대가: 실제 대화에 없는 빈 턴이 KV 에 남는다. 엔진이 빈 메시지를 받는지도 본다.
  - **ㄷ 그대로 둠** — 4.6초를 받아들인다(비교 기준).
  - 같은 잣대: exp81 세트(간격 뒤 새 말 · 지난 대화 이어 말하기 · 지난 비서 물음 이어받기 안 함)를 조건마다 돌리고, 회귀 세트 일부와 프리필 토큰을 함께 본다.
  - 기각해 둔 것: `Session.runPrefill`(대화 API 밖), 시스템 지시 일부만 미리 읽기(같은 API 문제).
- **exp85 요약의 결과 표기** — 저장 요청 뒤 취소·거절·실제 저장이 섞인 대화(합성, 실제 대화 아님)로 지금 지시문과 "요청의 결과까지 쓰라"는 한 구절을 더한 지시문의 요약을 만들고,
  그 요약을 `(과거 대화)` 줄로 실어 "아까 뭐 부탁했지?"류 질문에서 **취소된 저장을 저장된 것처럼 말한 비율**을 비교한다. 한·영 둘 다. 요약 형식(제목·태그·요약 파싱)과 태그 품질이 유지되는지도 본다.
- 결과를 보고 미리 읽기 방식을 사용자에게 묻는다.

### M1 — 픽스처 시각 고정 (테스트 생성부만)
- `PromptFixtureExportTest` 가 `assembleWithTools(today = …, now = …)` 를 고정값으로 넘긴다 — 값은 `baseline.json` 을 만든 픽스처와 같게(0.41.7 기록상 `[Now] 10:53`, 날짜는 확인해 맞춘다).
- 단언은 그대로. 회귀 세트를 다시 돌려 기준과 같은지(0.41.6 과 같은 20/20) 확인 — 이후 M2·M3 의 회귀 비교가 시각에 흔들리지 않게 먼저 한다.

### M2 — 빈 기록 미리 읽기 (M0 에서 고른 방식)
- ㄱ 이면: `ContextBuilder.pastEpisodeLine` 을 기록 첫 메시지(고른 역할)로 옮기고 `PromptAssembler` 의 시스템 지시 꼬리를 뺀다(ㄱ-둘 다면 둔다, 토큰 예산 계산 함께).
  미리 준비 경로(`prepareConversation`)는 그 메시지를 보내도록 마지막 메시지 판정만 손본다(지금은 비서 답만 본다).
- ㄴ 이면: `prepareConversation` 의 `last == null` 분기에서 빈 메시지로 시스템 지시만 읽고, 대화 재사용 판정이 다음 턴에서 그 대화를 그대로 쓰게 한다.
- 둘 다 실패·취소면 지금처럼 버린다. 시작 단계(`StartupCoordinator`)와 턴 뒤 미리 준비가 같은 경로.
- 테스트: 빈 기록에서 미리 준비가 엔진에 보내는지·다음 턴이 대화를 다시 만들지 않는지(가짜 런너), 기존 미리 준비 테스트 무수정.

### M3 — 요약 지시문 결과 표기 (exp85 가 이득을 보이면)
- `SummarizeEpisodeUseCase.SYSTEM_INSTRUCTION`·`_EN` 에 결과 구절 한 줄. 실험실 미러 함께. 회귀 세트 다시 실행.
- 테스트: 지시문 문구 단언이 있으면 생성부가 아니라 단언이 바뀌므로 먼저 보여 주고 확인받는다.
