# 0.40.0 — 한↔영(Korean / English) 언어 전환 지원 (표준 리소스 · 프롬프트 · 부수 추론 · 행동 가드)

## 목표
설정에서 앱 언어를 **`시스템 / 한국어 / English`** 로 바꿀 수 있게 하고, 안드로이드 표준 리소스(`strings.xml` + `values-en/strings.xml`)와 `LocaleManager` 앱별 언어 API 로 화면(UI)·일시·공휴일을 전환하며, 비서(Gemma)의 시스템 지시·툴 트리거·툴 결과 문구·부수 추론(요약·자동 추출·아침 브리핑·기억 정리)·음성 읽기(`SpeechOutput`)·모델 행동 가드(`MemoSaveIntent`·`RepeatRequest`·`RefusalTurns`)까지 모두 한/영 양방향으로 동작하게 한다.

## 미리 정한 결정 (2026-11-02 `/grill-me` 사용자 결정 & 1·2차 대조 검토 반영)

1. **문자열 관리 및 앱별 언어 단일 정본 (`LocaleManager` + `locales_config.xml`)**:
   - **표준 리소스**: `res/values/strings.xml`(한국어 기본) + `res/values-en/strings.xml`(영어)로 화면 문자열을 관리한다. Android Lint 의 `MissingTranslation`(오류 등급)이 번역 누락을 자동으로 잡는다.
   - **시스템 앱별 언어 연동 (`ComponentActivity` 기준, `appcompat` 미사용)**:
     - `MainActivity` 와 `DocumentViewerActivity` 는 `ComponentActivity` 이고 `appcompat` 의존성이 없으므로 `AppCompatDelegate` 를 쓰지 않는다(테마 전체를 건드리지 않기 위함).
     - `res/xml/locales_config.xml`(`ko`, `en`)을 추가하고 `AndroidManifest.xml` 의 `<application>` 에 `android:localeConfig="@xml/locales_config"` 를 등록해 휴대폰 시스템 설정의 "앱 언어"에 KOSMOS 가 노출되게 한다.
     - **단일 정본(Single Source of Truth)**: 언어가 두 군데(`SettingsDataStore` 와 OS `LocaleManager`)로 갈라져 "휴대폰 설정에서 언어를 바꿨더니 화면은 영어인데 비서는 한국어로 답하는" 불일치가 생기지 않도록, Android 13(API 33, 대상 기기 S25 포함) 이상에서는 **`LocaleManager.applicationLocales` 와 `context.resources.configuration.locales` 를 유일한 정본**으로 삼는다(API 26~32 폴백만 DataStore 에 보존).
     - **초기화 시점(3차 검토 반영)**: 요약·브리핑·위젯은 화면 없이도 돌므로, `AppLanguageHolder` 는 `KosmosApp.onCreate` 에서 앱 컨텍스트로 한 번 읽고 `Application.onConfigurationChanged` 에서 갱신한다(화면 `onResume` 에 기대지 않는다). 생성자·init 에서 구독을 시작하지 않는다(AGENTS §2-④).
     - 앱 시작과 설정 화면의 **`시스템 / 한국어 / English`** 토글 변경 시 현재 적용된 언어를 `AppLanguageHolder`(`StateFlow<AppLanguage>`)로 내보내 도메인·어시스턴트 계층(`ContextBuilder`, `UseCase`, `SpeechOutput`)이 항상 화면과 똑같은 `AppLanguage`(`KO` / `EN`)를 읽게 하고, 언어가 바뀌면 `modelRunner.invalidateConversation()` + `ConversationPrewarmer` 를 호출한다.

2. **Robolectric 기본 로케일 고정 (`robolectric.properties` `qualifiers=ko-rKR`)**:
   - **문제(2차 대조 검토 반영)**: Robolectric 의 기본 Configuration 로케일은 `en-US` 라서, 화면 문자열을 `strings.xml` 로 옮기면 Robolectric 테스트에서 `values-en/strings.xml` 이 선택되어 한국어 문자열을 찾는 기존 테스트 파일 8개가 깨진다.
   - **해결**: [app/src/test/resources/robolectric.properties](../../app/src/test/resources/robolectric.properties) 에 `qualifiers=ko-rKR` 한 줄을 추가해 전체 Robolectric 테스트가 한국어 리소스로 돌게 한다. 제품 코드에 `Build.FINGERPRINT == "robolectric"` 같은 테스트 환경 판정을 넣지 않는다. 영어 화면을 검증하는 새 테스트만 `@Config(qualifiers = "en")` 또는 `AppLanguage.EN` 을 명시한다.
   - **부작용 주의(3차 검토 반영)**: `qualifiers=ko-rKR` 는 리소스뿐 아니라 Robolectric 테스트 전체의 기본 `Locale` 도 `ko_KR` 로 바꾼다. 기본 로케일에 기대어 날짜·숫자 형식(`DateTimeFormatter` 의 `a` → "PM"/"오후" 등)을 단언하던 테스트가 M1 에서 깨지면, **단언이 아니라 제품 코드에 `Locale` 을 명시해서** 고친다(AGENTS §2-②).

3. **프롬프트 · 턴 리마인더 · 툴 선언 · 툴 결과 (`PromptAssembler`, `KosmosToolDeclarations`, `ToolExecutor`)**:
   - **턴 리마인더 (`TURN_TOOL_REMINDER`, `TURN_AFFIRM_CLAUSE`, `DOC_TURN_REMINDER`)**: 이미 영어로 작성돼 있어([PromptAssembler.kt:102](../../app/src/main/java/com/kosmos/app/assistant/context/PromptAssembler.kt#L102)) 한/영 공통으로 유지한다(매 턴 KV 비용 61 토큰 불변).
   - **툴 선언 (`KosmosToolDeclarations`)**: 현행 선언을 그대로 유지해 한국어 `MEASURED_OVERHEAD`(1,257)를 건드리지 않는다. M0 실험실에서 현행 툴 선언 + 영어 시스템 지시 조합으로 영어 툴 호출 스모크를 먼저 실측하고, 한국어 설명 때문에 오작동하는 툴이 관측될 때만 영어 전용 `ToolSet` 공급자와 `kosmos_lab.py` 미러를 추가한다.
   - **영어 시스템 지시 (`PromptAssembler`)**: `EN` 일 때 응답 언어(`Always respond in English unless the user speaks another language.`), 말투(`Reply briefly in clear, natural, polite English.`), `[System Data]` 날짜 블록(`Today=..., Tomorrow=..., Day after tomorrow=..., Next Monday=...`), 각 툴 트리거 예시(`"remember"`, `"save"`, `"what was"`, `"schedule"`, `"remind me"` 등), 사실만 말할 때 되묻기(`confirm it and ask "Would you like me to save this as a note?"`)를 영어 세트로 조립한다.
   - **오버헤드 2단계 실측 (2차 대조 검토 반영)**: M0 에서는 실험실 초안으로 예산 적합성과 스모크를 먼저 확인하고, **M2 에서 `PromptFixtureExportTest` 가 실제 앱의 `system_instruction_en.txt` 를 내보낸 직후 그 픽스처 원문으로 다시 실측**해 `TokenBudgetInvariantTest` 의 영어 오버헤드 불변식(`EN 실측 + 프로필 상한 100 ≤ Constants.PREFILL_OVERHEAD_TOKENS`)을 확정한다.
   - **툴 결과 · 거절 고정 문장 · 위키 · 음성 읽기**: 승인 거절 고정 문장(`BaseAgent.rejectionReply`), 7개 `ToolExecutor` 결과/충돌 안내 문구, 위키백과 기본 검색 언어(`lang = "en"`), 음성 읽기([SpeechOutput.kt](../../app/src/main/java/com/kosmos/app/platform/speech/SpeechOutput.kt) `Locale.US`)를 현재 언어로 전환한다.

4. **기억 검색 (`SearchMemoryToolExecutor` · `BigramMatcher`) — 라틴 단어 토큰 매칭 + 한계 명시**:
   - **문제(2차 대조 검토 반영)**: [BigramMatcher.kt:26](../../domain/src/main/java/com/kosmos/app/domain/search/BigramMatcher.kt#L26) 은 공백을 지우고 2글자씩 자른다. 한국어에서는 어미·조사를 떼는 데 유리하지만, 영어에서는 `"my bike password"` 가 `"mybikepassword"` 로 붙어 단어 경계를 넘는 조각(`yb`, `ik`, `ep`)과 흔한 2글자(`th`, `er`, `in`)가 점수를 오염시켜 무관한 영어 메모까지 높은 점수를 받는다.
   - **해결**:
     - 한글(가~힣) 구간은 기존 공백 제거 2글자 바이그램을 그대로 유지(한국어 회수율 100% 불변)하고, **라틴 알파벳(a~z) 구간은 소문자화(`lowercase()`)한 단어 토큰(길이 ≥ 2, 불용어 제외) + 단어 내부 어간(접미사 `-s/-es/-ed/-ing` 처리 또는 단어 내 조각)이 단어 경계를 넘지 않게** 뽑아 점수를 매긴다.
     - M1 에서 `SemanticRecallBenchmarkTest` 에 영어 유의어·상위 개념·무관 문서 분리도 세트를 추가해 실측으로 임계값(`BIGRAM_MIN_TERM_OVERLAP` 호환)을 검증한다.
     - **한국어 불변은 실측으로 확인(3차 검토 반영)**: 라틴 단어 토큰화는 영문이 섞인 한국어 메모("KTX 예매", "와이파이 PIN 0427", "wifi 비번")의 점수도 바꾼다. 검색 결과는 모델이 읽는 툴 결과이므로, M1 에서 한국어 기준 세트(`SemanticRecallBenchmarkTest` 40/40)와 영문 혼합 한국어 메모 단위 테스트, 회귀 세트 `smoke`·`repeat`·`newval` 을 함께 돌려 불변을 확인하고 차이를 CHANGELOG 에 적는다(AGENTS §2-⑤).
   - **알려진 한계로 명시**: 한국어 메모를 영어 질문으로 찾거나(`"what's my bike password?"` ↔ `"자전거 비밀번호는 134"`) 그 반대인 **한↔영 교차 언어 검색**은 지원하지 않으며, 사용 안내(`USER_GUIDE`)와 `README` 에 한계로 명시하고 추후로 미룬다(사용자 결정).

5. **모델 행동 가드 (`MemoSaveIntent` · `RepeatRequest` · `RefusalTurns` · `RecallConflict`) — M2 에서 프롬프트·회귀 세트와 함께 변경**:
   - **마일스톤 배치 조정(2차 대조 검토 반영)**: AGENTS §2-⑤("가드를 바꾸는 마일스톤에서 회귀 세트를 돌린다")를 지키기 위해, 가드 4종의 영어 패턴 추가는 프롬프트·회귀 세트(`scratch/lab/regression/run.py`)가 함께 준비되는 **M2** 에서 수행한다(M1 은 순수 도메인 타입·일시·공휴일·영어 단어 검색만).
   - **0.39.2 M4b 함정 방어**:
     - `RepeatRequest` 가 먼저 조회/되묻기(`tell me again`, `what was`, `what did I say`, `do you remember`, `remind me what`)를 판정해 저장을 차단하고, `RepeatRequest.SAVE` 는 명시적 저장 명령(`remember that/this`, `save this/it`, `make/take a note`, `write down`, `don't forget`)만 인정한다.
     - `MemoSaveIntent.SAVE_WORD` 의 영어 패턴도 의문문(`^(do|can|could|did) you remember\b`, 끝이 `?` 인 `remember what/where/when/my...`)이나 일상 서술(`"I wrote a long note..."`)이 걸리지 않도록 부탁하는 명령 표현(`remember (that|this|to)`, `please remember`, `save (this|it|that)`, `(make|take|save|keep) a note (of|that)`, `write (it |this |that )?down`, `don't forget`, `keep in mind`)으로 좁힌다.
     - `MemoSaveIntent.YES` 는 문장 전체 매칭(`YES.matches`)으로 짧은 긍정(`yes`, `yeah`, `yep`, `sure`, `ok`, `okay`, `please`, `go ahead`, `yes please`)만 통과시킨다.

6. **부수 추론 (`SummarizeEpisodeUseCase` · `ExtractFactsUseCase` · `MorningBriefingGenerator` · `MemoryCleanupRunner`)**:
   - **출력 언어 결정(3차 검토, 2026-11-02 사용자 결정)**: 기억으로 남는 산출물(에피소드 요약·자동 추출·중복 합치기)은 설정 언어가 아니라 **그 재료 대화의 언어**를 따른다 — 재료의 사용자 발화 한글 비율로 `KO`/`EN` 을 판정하는 순수 함수(`ContentLanguage.detect`)를 두고, 판정이 어려우면(혼합·짧음) 설정 언어로 넘어간다. 한↔영 교차 검색을 지원하지 않으므로(4번), 한국어로 나눈 대화가 영어 설정에서 영어 요약으로 저장되면 나중에 한국어 질문으로 찾지 못하기 때문이다. 사용자에게 바로 보여 주는 문장(아침 브리핑·주간 회고)만 설정 언어를 따른다.
   - 파서는 한/영 라벨(`제목:/Title:`, `태그:/Tags:`, `요약:/Summary:`, `프로필:/Profile:`, `지식:/Knowledge:`, `없음/None`)을 모두 인식해 언어를 바꾼 뒤에도 기존 기억과 함께 동작하게 한다.

7. **전체 화면 · 일시 · 공휴일 · 플랫폼 표면 · 문서 규칙 갱신**:
   - 메인 앱 전체(채팅·헤더 캡슐·상태 시트·드로어·에피소드 시트·승인 시트·결과 카드·일정 오늘/월 탭·기억 메모/프로필/활동 기록·기억 정리·문서 홈·설정·모델 관리·시작 화면), `DocumentViewerActivity`, 홈 위젯(`KosmosTodayWidget`), 빠른 설정 타일([VoiceTileService.kt](../../app/src/main/java/com/kosmos/app/platform/tile/VoiceTileService.kt)), 알림 채널([NotificationChannels.kt](../../app/src/main/java/com/kosmos/app/platform/notification/NotificationChannels.kt))·브리핑/리마인더 알림 문구까지 모두 한/영 전환한다.
   - **E2E 계약 보호 (AGENTS §2-②)**: `contentDescription = "Attach"` / `"Send"`, `"Document Attached"` 는 테스트 계약이므로 언어와 무관하게 그대로 유지한다.
   - **문서·규칙 갱신**: `AGENTS.md` §4-7("UI 문자열은 `values/strings.xml`(한국어)과 `values-en/strings.xml`(영어) 두 벌을 함께 관리하며, 영어 번역이 빠지면 `lintDebug` 의 `MissingTranslation` 이 실패한다"), `USER_GUIDE.md`·`USER_GUIDE.en.md`("한국어·영어 지원" 및 교차 언어 기억 검색 한계 명시), `README.md` 한계 표를 함께 갱신한다.
