# 0.39.4 — 체감 지연 개선 2

## 목표
앱을 처음 열거나 다른 앱에서 돌아온 뒤 첫 답, 그리고 요약 드레인 중에 보낸 질문의 대기를 줄인다.

## 근거 (지금까지 실측, 디버그 빌드 SM-S938N)
- 평소 첫 글자: 0.66~1.9초
- 첫 실행: 엔진 준비 약 9~10.5초, 그 뒤 첫 턴은 대화 생성(문법 준비) 3.0초 + 첫 글자까지 10.0초 (0.39.2 M4)
- 다른 앱 복귀: 엔진 준비 8.4초 + 첫 답 10.2초 (0.39.0 M1)
- 요약 직후 이어진 자동 추출 뒤에서 질문 대기: 3.95초 (0.39.1 M3 — 드레인이 요약 → 자동 추출 → 다음 에피소드를 연달아 돈다)

## 미리 정한 결정
1. 백그라운드에서 모델을 올리지 않는다(AGENTS §2-⑥ — onStop 이 3.6GB 를 즉시 해제).
2. **엔진이 준비되면(Ready) 그 자리에서 지금 대화방의 대화를 미리 만든다** — 0.39.2 의 `ConversationPrewarmer` 를 Ready 에도 건다. 앞 화면에서 일어나므로 §2-⑥ 안이다.
   모델 입력은 바뀌지 않는다(0.39.2 에서 회귀 세트 `--prewarm` 으로 검증된 같은 방식) — 회귀 세트 대상 아님.
3. **드레인은 항목 사이마다 새 요청을 다시 본다** — 요약이 끝나고 자동 추출·다음 에피소드로 넘어가기 전에 그사이 사용자 요청이 있었으면 남은 항목을 큐에 되돌리고 멈춘다. 돌고 있는 추론은 취소하지 않는다(0.38.6 결함 경로).

## 마일스톤 (각각: 게이트 → 커밋)
- **M0 실측 (코드 수정 0)** — `latency_instr.py apply` → 빌드·설치 →
  ① 첫 실행: `session.py --cold "안녕! 한 문장으로 답해 줘."`
  ② 복귀: 홈 화면(`KEYCODE_HOME`) 15초 대기 → 앱 복귀 → 엔진 준비(`Engine initialized`) 뒤 `"오늘 할 일 뭐 남았어?"`
  ③ 드레인: 긴 메시지 4개로 예산 정리를 일으킨 뒤 65초 조용히 → 요약 `oneShot=true` 시작 직후 질문 하나 → 대기 시간.
  각 상황 2회, 배터리 온도 기록 → `latency_instr.py revert`. 결과로 M1~M3 "진행/닫기".
  - **M0 결과 (SM-S938N, 디버그 빌드 + 측정용 임시 로그, 배터리 29.5→32.9°C, 예산 설정 2,000)** —
    ① 첫 실행(2회): 엔진 준비 약 10.8·10.6초(폴링 2초 포함), 첫 질문 요청 후 대화 생성(문법 준비) 3.44·3.04초 + 첫 글자 10.37·10.00초.
    ② 복귀(2회): 엔진 준비 약 8.5·8.5초, 첫 질문 요청 후 대화 생성 3.01·3.13초 + 첫 툴 호출(`GetSchedule`)까지 10.92·11.15초, 첫 글자 11.56·11.78초.
    ③ 드레인 중 질문(2회): 요약 `oneShot=true` 가 돌던 중 질문이 들어오자 요약 완료(요청 후 4.89·3.07초) + `getTokenCount` 대화 복원(3.31·3.28초) 직후
    `EpisodeSummarizeScheduler` 가 곧바로 자동 추출 `oneShot=true` 를 던지고, `llmDispatcher` 줄에서 사용자 턴이 먼저 잠금을 얻어 답(첫 글자 8.82·7.13초)을 낸 뒤 자동 추출이 잠금을 얻었다(9.46·7.84초).
    요약이 끝났을 때 이미 사용자 요청이 대기 중인데도 자동 추출·다음 에피소드로 계속 진입하여 추론 경합을 일으키므로 M1 진행, 첫 실행·복귀의 대화 생성+프리필(약 9~10초)을 Ready 직후 미리 치르는 M2 진행, 복귀 엔진 재로드 자체(8.5초)는 §2-⑥ 안에서 할 수 있는 것이 없으므로 M3 닫기.
- **M1 드레인 항목 사이 새 요청 확인** — `EpisodeSummarizeScheduler`: `onUserActivity()` 가 올리는 활동 순번(`AtomicLong`)을 두고, `drain()` 시작 시 값을 잡아 둔다.
  `process()` 의 요약 뒤·자동 추출(`factExtractor.extract`) 전, 그리고 다음 항목 전에 순번이 바뀌었으면 남은 항목(지금 항목의 추출 포함)을 `deferred` 앞쪽으로 되돌리고 종료.
  다음 조용한 창(`whenQuiet`)이 이어서 처리한다. 추출만 남은 항목을 다시 요약하지 않게 에피소드 상태를 확인한다.
  테스트(`EpisodeSummarizeSchedulerTest` 에 추가 — 기존 단언 그대로): 요약 중 요청이 오면 추출이 다음 창으로 미뤄짐 · 두 항목 중 첫 항목 뒤 요청이면 둘째가 미뤄짐 · 요청이 없으면 지금처럼 끝까지.
  - **M1 결과**: `userActivitySeq`(`AtomicLong`)와 `pendingExtractions`(`LinkedHashSet`)로 요약 도중 들어온 요청이 있으면 자동 추출과 남은 에피소드를 큐 앞으로 되돌리고, 다음 조용한 창에서 재요약 없이 추출만 이어서 실행. 기존 테스트 11건 불변 + 새 테스트 2건 통과.
- **M2 엔진 준비 직후 대화 미리 만들기** — `ConversationPrewarmer` 가 `ModelRunner.loadState` 를 구독하는 `start()`(init 구독 금지, AGENTS §2-④, `KosmosApp.onCreate` 에서 호출)에서
  현재 대화방(`SessionStore` 의 활성 세션)으로 `afterTurn(sessionId)` 와 같은 준비를 한다. 요약 catch-up(60초 조용한 뒤)·아침 브리핑과의 순서: 미리 만들기가 먼저, 다른 부수 추론은 그 뒤.
  사용자가 준비 중에 질문하면 남은 시간만 기다린다(0.39.2 와 같음). 테스트: Ready 에서 준비가 한 번 불린다 · Ready 가 반복돼도(복귀) 매번 · 새 요청이 오면 엔진에 닿기 전 준비는 취소.
  - **M2 결과**: `ConversationPrewarmer.start()` 가 `ModelRunner.loadState` 의 `Ready` 를 구독해 활성 세션(`SessionStore`, 없으면 생성·저장)으로 `afterTurn` 을 호출하고, `KosmosApp.onCreate` 에서 `briefingGenerator.start()` 보다 먼저 시작. 기존 테스트 3건(생성부 인자 추가) + Ready/복귀 테스트 1건 통과.
- **M3 복귀 재로드** — M0 에서 "엔진 준비" 자체(약 8초)가 대부분이면 §2-⑥ 안에서 할 수 있는 것이 없다 → 닫고 기록. 첫 답 몫은 M2 가 덮는다.
  - **M3 결과**: 복귀 후 엔진 준비(약 8.5초)는 §2-⑥(백그라운드 로드 금지) 안에서 줄일 수 없으므로 닫음 — 첫 답 문법 준비·프리필(약 10초)은 M2 가 덮는다.
- **M4 실기기 확인** — M0 과 같은 시나리오로 전·후(첫 실행 첫 글자, 복귀 첫 글자, 드레인 중 질문 대기). 평소 턴 0.7~1.9초가 나빠지지 않았는지.
  - **M4 결과 (SM-S938N, 디버그 빌드 + 측정용 임시 로그, 배터리 29.4→33.3°C, 예산 설정 2,000, 측정 뒤 revert + 클린 APK 재설치)** —
    ① 첫 실행(2회): 엔진 준비 약 10.1·9.7초, 이어서 Ready 대화 미리 준비(문법 + 프리필)가 약 9.5·10.1초 뒤에 끝나고, 그 뒤 첫 질문은 대화 생성 없이 첫 글자 **0.71·0.69초**(전 10.37·10.00초). 이어지는 평소 턴 **0.71·0.67초**.
    ② 복귀(4회): 엔진 준비 약 8.5초, Ready 대화 미리 준비 완료(복귀 시작 후 약 16.8~18.5초) 뒤 일반 질문 2회는 첫 글자 **0.65·0.64초**(전 11.56·11.78초), 이어지는 턴 **0.66·0.67초**. 앞 기록에 있던 질문을 되풀이한 복귀 2회는 `RepeatedQuestions`(0.39.3 M4d)가 앞 답을 빼 대화를 다시 만들었으나 첫 글자 6.87·6.82초.
    ③ 드레인 중 질문(2회): 요약 `oneShot=true` 시작 직후 질문이 들어오자 현재 요약(끝까지 실행) + 대화 복원 뒤 **자동 추출(`factExtractor.extract`)을 던지지 않고 멈춰**, 사용자 질문이 경합 없이 바로 실행됐다(요약 도중 도착 12.40초 / 요약 끝 직후 도착 2.74초, 그 뒤 `oneShot=true` 추가 진입 0건).
