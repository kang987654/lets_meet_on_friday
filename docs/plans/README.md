# docs/plans — 회차 계획서

계획 세션(Claude)이 승인받은 계획을 여기 저장소 파일로 남기고, 구현 세션(Antigravity/Gemini 또는
다른 에이전트)이 이 파일을 읽어 그대로 수행한다 (`AGENTS.md` §2-①, 2026-09-02 분업 결정).

## 파일 규칙
- 이름: `<대상 버전>-<회차명>.md` (예: `0.24.0-auto-extract.md`)
- 상단 첫 줄: `> **상태**: 승인 (YYYY-MM-DD)` → 회차가 끝나면 `완료 (CHANGELOG x.y.z)` 로 갱신
- 본문 필수 절: **Context**(왜) · **고정 제약** · **사용자 확정 결정** · **M0..Mn 마일스톤**(각각
  파일·함수·테스트·게이트) · **실기기 게이트 목록** · **실행 순서**. 예시: `0.23.0-profile-injection.md`
- 프롬프트 표면(툴 선언·시스템 지시)을 건드리는 회차는 **M0 = 실험실 실측**이 먼저다 — 실측한
  문구를 계획서에 원문 그대로 적어 구현이 표류하지 않게 한다 (`AGENTS.md` §2-⑤).

## 구현 에이전트가 지킬 것
1. 계획서의 마일스톤 단위로 구현 → 매 마일스톤 `./gradlew test lintDebug assembleDebug` 녹색 → 한 줄 커밋.
2. 계획과 갈리는 발견은 조용히 덮지 말고 `[WHY]` 주석 + CHANGELOG 에 적는다.
3. 마지막 마일스톤은 문서(CHANGELOG · expand.md 상태 · 관련 설계 문서) — 이 계획서의 상태 줄 갱신 포함.
