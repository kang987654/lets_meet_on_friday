# 0.41.9 — 라이브러리 최신화 후속 (대화 앞부분 미리 읽기 · 화면 이동 연타 · 다운로드 견고성 · 잠재 결함 정리)

## Context
### 출발점 ① 쉰 뒤 첫 답 약 4.6초 (0.41.7 휴대폰 확인)
30분 넘게 쉬면 지난 대화를 시스템 지시 끝 요약 한 줄로 바꿔(`IdleGapHistory`) 모델 기록이 빈다. 미리 준비(`GemmaModelRunner.prepareConversation`)는
마지막 비서 답을 model 메시지로 출력 1토큰 send 해서 KV 를 채우는데(ADR-030, exp66d·e), 기록이 비면 보낼 것이 없어 시스템 지시를 첫 질문이 읽는다.
앱에는 새 세션이 없고 간격 뒤 요약이 없으면 원문을 그대로 실으므로(F1) 기록이 비는 경우는 "간격 + 요약 있음" 하나뿐이다.

### M0 실측 (완료, PC, 앱 코드 수정 없음 — 스크립트 `scratch/lab/exp84*`·`exp85`)
- **exp84** (exp81 9건 × 조건): 지금(시스템 지시 끝 요약, 미리 읽기 없음) 새 말 5/5·이어 말하기 4/4. 요약을 기록 메시지로 옮기는 안(model·user·둘 다)은
  새 말 2~4/5 — 지난 비서 물음(노트북 비밀번호·회의 일정)을 다시 꺼냈다. 빈 model 메시지로 미리 읽기는 4/5.
- **exp84b** (걸린 물음 있는 에피소드 4 × 애매한 말 6 = 24): 지금 방식을 두 번 — 23/23, 첫 응답 일치 **24/24**(MTP ADAPTIVE 에서도 결정적).
  빈 메시지 미리 읽기 23/24 지만 지금과 첫 응답 일치 **1/24** — 자기 이름을 "Kosmos" 로(15/24, 지금 0/24). 실제 대화에 없는 빈 턴이 KV 에 남아 답의 성격을 바꾼다 → 기각.
- **exp85** (요약 지시문에 "요청은 결과까지" 구절): 지금 지시문도 거절을 이미 적는다("비서가 메모를 남기지 않았어요", "did not save the note" 6/6).
  답 판정(눈 확인) A 약 7/8 · B 약 8/8 — 1건 차이, 표본 1회씩이라 구분 불가 → **요약 지시문은 바꾸지 않는다**. 휴대폰의 "요청하셨던 것도 기억하고 있어요"는
  요약이 아니라 답이 결과를 빼고 말한 것으로 본다.

### 해법: `ConversationConfig.prefillPrefaceOnInit` (litertlm-android 0.19.0 에 이미 있음)
- 공식 소스(LiteRT-LM `Config.kt`·`runtime/conversation/conversation.h`): "Whether to prefill the preface on initialization. Defaults to false" —
  켜면 대화 생성(`createConversation`)이 앞부분을 바로 프리필해 첫 답이 빨라지는 대신 생성이 길어진다. exp66b 의 "생성은 문법 준비뿐"은 기본값(꺼짐) 때문이었다.
- 앞부분 = 시스템 지시(Role.SYSTEM) + `initialMessages`(기록 전체) + 툴 선언 — `Engine.createConversation` 바이트코드로 확인. 그래서 빈 기록뿐 아니라
  지금의 우회(`dropLast(1)` + model 메시지 출력 1토큰 send, KV 에 1토큰 비서 턴이 남는 대가 — ADR-030)까지 대체할 수 있을 수 있다.
- 켜면 앞부분을 **대화 설정의 생각 모드**로 렌더링한다(`conversation.cc` — `config.thinking_config()`). 지금은 `THINKING_OFF` 를 send 에만 넘기므로
  `ConversationConfig.thinkingConfig = THINKING_OFF` 를 함께 넣어야 앞부분과 턴의 템플릿이 맞는다.
- PC 실험실은 못 잰다 — 파이썬 패키지 0.19.0 의 C API 에 이 설정 함수가 없다(`litert-lm.dll` 내보내기 확인). **실측은 휴대폰**, 회귀 세트는 이 경로로 못 돌린다.

  ② 켬/끔 같은 질문 몇 건의 답 동일성 ③ 지금 우회 대신 "전체 기록 + 켬"으로 만들었을 때 다음 턴이 대화를 재사용하는지·답 동일성·KV 토큰 수
  ④ 요청 경로(미리 준비 없이 바로 질문)에서 켬이 생성+send 두 번 프리필로 늘리는 시간.
- 결과에 따라: (가) 늘 켜고 미리 준비는 생성만(우회 제거) / (나) 미리 준비 경로에서만 켬(우회 유지, 빈 기록만 해결) — 실측을 보고 사용자에게 묻는다.
- 테스트: 설정 조립 순수 함수(`chatConversationConfig`)의 새 필드, 미리 준비가 빈 기록에서도 대화를 만드는지(가짜 런너). 기존 미리 준비 테스트 무수정.

### M3 — 체감 결함 (모델 입력 무관)
- **C2 화면 이동 연타** — `AppNavHost` 의 뒤로·앞으로 람다를 `dropUnlessResumed { }` 로 감싸고, 설정 → 모델 관리·기억 정리·스플래시 → 모델 관리에
  `launchSingleTop = true`. `navigateBack()` 루트 가드는 그대로. 테스트: 두 번 눌러도 한 단계만(Compose 내비 테스트 가능하면).
- **W2 다운로드 재시도 예산** — WorkManager 는 Wi-Fi 끊김 같은 제약 중단마다 `runAttemptCount` 를 올린다(2.12.0 `WorkerWrapper` 확인). 포기 판정을
  "진행 바이트가 늘지 않은 연속 시도 수" 같은 자체 카운터로(입력 데이터·부분 파일 크기 기반). 테스트: 판정 순수 함수.
- **W3** — `WorkManagerModelDownloadScheduler.acknowledge()` 의 전역 `pruneWork()` 삭제(채팅·임베딩 모델 다운로드 정보가 서로 지워짐). 확인 처리는 `ackedWorkId` 로 충분.
- **O2 다운로드 취소 지연** — `ModelDownloadService` 가 블로킹 `execute()` 중인 `Call` 을 코루틴 취소 때 `call.cancel()` 로 끊는다(멈춘 연결에서 최대 60초 → 즉시).
- **C1 상태 폴링** — `ChatViewModel.observeDeviceStatus()` 의 5초 폴링을 화면이 보일 때만(`ChatScreen` 의 수명 주기 효과 또는 가시성 플래그 — 기본 인자로 단독 compose 유지),
  어긋난 KDoc 두 곳(`RuntimeMetricsCollector`·`ChatViewModel`) 바로잡기.
