## Context

예산 1,700 체제에서 대화는 자주 리셋되고, 리셋된 대화는 에피소드 요약(검색용)으로만 남는다.
C′2 는 그 약점을 **캡처 트리거로 뒤집는다**: 에피소드가 닫혀 요약될 때 oneShot 1회를 더 돌려
"이 대화에서 앞으로도 기억할 사실 0~3개"를 뽑는다 — 지식 급은 Knowledge 에 `source=auto` 로
자동 저장, 프로필 급(이름·호칭·말투·직업…)은 **승인 카드**를 거쳐 Profile 에 들어간다.
C′1(0.23.0)이 답변의 톤을 바꿨고, C′2 가 "쓸수록 쌓이게" 한다 (expand.md:81·139).

**현황 (탐색 확정)**:
- "리셋 직전" 훅은 코드상 추론 불가 — 리셋은 **다음 턴 프리필 시점**에 `GemmaModelRunner.getOrCreateConversation`(비-suspend, `llmDispatcher` 직렬)에서 일어난다. 유일한 경로는 기존 요약 파이프라인: `EpisodeBoundaryManager.closedEpisodes`(IDLE/RESET) → `EpisodeSummarizeScheduler.drain()`(턴 종료·엔진 Ready 편승, 발열 게이트, 재시도 3회).
- `ProfileEntry.SOURCE_AUTO = "auto"` 는 v8 에서 C′2 용으로 예약됨(생산처 0곳). `ProfileRepository.upsert(key, value, source)` 이미 source 인자 있음.
- `knowledge_note` 에는 출처 컬럼이 없다(`sourceSessionId` 만, 항상 null). MemoryScreen 지식 카드는 **읽기 전용(삭제 UI 없음)** — expand.md 관리 장치 스펙("출처 표시 + 검토·삭제") 미구현.
- 기존 `ApprovalCoordinator` 는 단일 슬롯·60초 자동 거절·채팅 화면 생존 전제 → 백그라운드 추출의 승인에 부적합. 제안은 **테이블에 영속**하고 화면이 구독한다.
- 프로필 상한(100토큰) 집행은 `ProfileSheetViewModel.upsert` 안에만 있다 — 자동 경로가 우회하면 `PREFILL_OVERHEAD >= 실측 + PROFILE_MAX_TOKENS` 불변식이 깨진다. 공용 순수 함수로 뽑아 양쪽이 쓴다.
- 채팅 프리필 예산은 **무변경**(추출은 oneShot, 시스템 지시·툴 선언 불변 → `MEASURED_OVERHEAD` 1,277 유지).
