# 0.41.1 — LiteRT-LM 0.19.0 상향과 추측 디코딩(MTP)

## Context
LiteRT-LM 0.19.0(2026-11-02)이 나왔다. 릴리스 노트의 핵심은 "GPU 로짓 마스킹으로 제약 디코딩이 빨라지고 MTP 디코딩을 완전히 지원" — ADR-011 이 MTP 를
켜지 않은 이유(툴 선언 + 제약 디코딩과 드래프터 제안의 충돌로 해석, gallery 도 에이전트 채팅에서만 MTP 를 뺐다)를 겨냥한 변경이다.
모델 파일에는 드래프터(`tf_lite_mtp_drafter`)가 원래 들어 있다(ADR-011). 0.41.2 가 임베딩 엔진·NPU 에 기대므로 엔진 버전을 먼저 정한다(사용자 결정).

## M0 — PC 실측 (완료 2026-11-04, `scratch/lab/exp77*.py` · 회귀 세트)
- **API(AAR javap 전수 비교)**: 제거 0. 추가 = `SpeculativeDecodingConfig`/`SpeculativeDecodingMode`(OFF·ON·ADAPTIVE — Engine·Conversation·Session 설정),
  `Conversation.clone()`·`Session.clone()`, `ExperimentalFlags.enableYnnpack`. `EngineConfig`·`ConversationConfig` 는 끝에 인자 추가 + 옛 생성자 유지(소스 호환).
  `BenchmarkInfo`/`benchmark()` 서명 변경(앱 미사용). `EmbeddingEngine` 변경 없음. 0.18.1 은 소스 빌드의 EmbeddingGemma 2 ABI 수정뿐(배포 패키지 무관).
- **exp77 (CPU)**: 임베딩 5문장 0.18.0 과 **비트 동일**. 툴 호출(`add_schedule` 인자 동일)·숫자 따라 쓰기 양 버전 온전. Gemma 파일 `has_speculative_decoding_support=True`.
  `clone()` 복제본에 턴을 보내도 원본 KV 1,374 그대로. CPU 에서는 MTP 속도 이득 없음.
- **exp77b (PC GPU, 툴 없음)**: 디코드 초당 52 → **65~72 토큰**(ON·ADAPTIVE), 긴 답 25s → 18s. greedy 인데도 ON 에서 글자가 조금 달라진다(검증 경로의 수치 차).
- **회귀 세트 (PC GPU FP32, 기준 = 0.18.0 baseline)**: 0.19.0 MTP 꺼짐 — 만점 세트 동일, drift 10/12(−1 "회사 동료 생일 선물", 흔들림 범위), overlap 20/20(+2).
  **MTP 켜짐 — 꺼짐과 같은 수준**(drift 10/12, overlap 19/20, smoke·save·iso 만점 = 툴 호출·제약 디코딩과 충돌 없음). 드래프터 적중률 로그 0.57.
- **exp77c (PC GPU, 앱 시스템 지시·툴, 깨끗한 채움 대화 깊이 2,200~3,800)**: 대조군 FP16·MTP 꺼짐 **8/8 깨짐**(`20206-0-017T10:0:`, 툴 인자
  `2026-08-07T1010:00:000` — ADR-021 재현), FP32 × OFF/ON/ADAPTIVE **각 8/8 온전**.
- 결론: PC 에서는 0.19.0 상향 무회귀, MTP 는 툴 호출·숫자 온전성을 해치지 않고 GPU 생성을 빠르게 한다. **휴대폰 GPU 경로(OpenCL)는 PC(WebGPU)와 다르다** → 속도·발열은 M2.

## 결정
- 사용자(2026-11-04): 짧은 회차로 먼저, 번호 0.41.1. MTP 모드는 휴대폰에서 OFF·ON·ADAPTIVE 를 재 보고 정한다. 숫자 온전성은 FP32 유지라 PC 결과로 갈음하고
  휴대폰은 문서 첨부로 가볍게 한 번.
- `clone()`(부수 추론이 채팅 KV 를 지우지 않게 — ADR-010·014)은 이 회차 범위 밖, 후속 후보로 기록만.

## 고정 제약
- 모델 입력 불변(시스템 지시·툴 선언·리마인더·결과 문구) — 픽스처·`MEASURED_OVERHEAD` 그대로. 회귀 세트는 M0 에서 돌렸다.
- 기존 테스트 단언 불변. FP32 처방(ADR-029)·에뮬레이터 CPU 경로·GPU 실패 시 CPU 폴백 동작 불변.
- MTP 설정은 채팅·oneShot 대화 모두에 같은 값(엔진 하나, 대화 설정 두 곳). CPU 엔진(에뮬레이터·폴백)에는 걸지 않는다 — 이득이 없고(exp77) 검증하지 않은 경로다.

## 마일스톤

### M1 — 상향과 측정 장치 (`:app`)
- `litertlm = "0.19.0"`(+ `[WHY]` 주석에 M0 요약). 실험실 파이썬 환경 `friday` 의 `litert-lm`·`litert-lm-api` 도 0.19.0 으로 맞춘다(앱과 같은 것을 재도록 — §2-⑤).
- `ConversationPolicy`: `chatConversationConfig`·`oneShotConversationConfig` 에 `speculativeDecodingConfig` — 값은 `MtpMode`(OFF/ON/ADAPTIVE)에서. GPU 엔진일 때만.
  기본값은 M2 전까지 **OFF**(현행과 같은 동작).
- 디버그 빌드 전용 덮어쓰기: 앱 외부 파일 폴더의 `debug_mtp.txt`(off/on/adaptive)를 엔진 로드 때 읽는다 — `adb push` 로 바꾸고 앱을 다시 켜면 된다. 릴리스는 읽지 않는다.
- 디버그 진단: `ExperimentalFlags.enableBenchmark`(디버그만) + 턴 종료 시 `Conversation.getBenchmarkInfo()` 로 첫 토큰 시간·프리필/디코드 초당 토큰을 한 줄 로그.
- 테스트: 대화 설정에 모드가 실리는지(OFF/ON/ADAPTIVE, CPU 엔진은 미지정), 디버그 파일 파싱(잘못된 값 → 기본값). 게이트 후 커밋.

### M2 — 휴대폰 실측 (사용자 연결 필요)
- 모드마다(OFF·ON·ADAPTIVE, 앱 재시작) 같은 질문 세 종류(짧은 답·긴 답·툴 호출) × 2회 — 디코드 초당 토큰, 첫 토큰 시간, 프리필 속도(벤치마크 로그), 발열 체감.
- 정한 모드로 문서 첨부(공개 법령 일부, 깊이 2,500+) → 숫자·날짜 따라 쓰기 1회, 일정 추가 툴 1회.
- 0.40.7 조용한 구간·프리워밍과의 상호작용: 답 직후 입력 버벅임이 다시 생기지 않는지 체감.
- 결과로 기본 모드 확정(사용자 확인).
