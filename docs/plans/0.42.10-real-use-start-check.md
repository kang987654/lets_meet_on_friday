# 실사용 시작 점검 (0.42.10 — 결함을 고칠 때만 버전)

> **상태**: 계획 (사용자 승인 2026-11-19 — "작은 점검 회차로 줄이기"). 다음 세션이 이 파일만 보고 이어 갈 수 있게 썼다.
> 정본 순서: **AGENTS.md > 이 계획서**.
> 전체 흐름(2026-11-18 사용자 승인) 4단계 "실사용 준비"의 전부. 1~3단계는 끝(0.42.5~0.42.9). 이 점검이 끝나면 5단계 실사용.
> 0.43.0 계획서(`0.43.0-real-use-prep.md` — 릴리스 빌드 전환)는 **보류**: 매일 쓸 빌드는 **디버그 빌드 그대로**(사용자 결정 2026-11-19).
> 이유 — 릴리스로 얻는 것은 화면 부드러움·APK 약 23MB 정도이고 답 생성 속도는 같다(네이티브 LiteRT). 반면 진단 기록(`diag_runaway.txt`)·벤치마크 수치·채팅 밖 추론 출력 상한·디버그 파일 백엔드 전환을 잃는다 — 실사용은 쓰면서 고칠 시기라 진단이 더 중요. 릴리스 전환은 6단계(포트폴리오·공개) 때.

## 버전
- 고칠 결함이 나오면 그 회차를 0.42.10(`versionCode` 42010)으로 올린다. 확인만으로 끝나면 버전을 올리지 않고 CHANGELOG 0.42.9 아래 메모 + `device_gate.md` 체크만.
- 지금 앱 버전은 0.42.9(42009) — 0.42.9 는 앱 코드 변화 없음(트리거 줄 접음), 휴대폰에는 0.42.8 빌드가 깔려 있다. 0.42.9 커밋 두 개(`949fe83`, `1cb2d42`)는 아직 푸시 안 함.

## 할 일
### 1. 초기화가 남기는 것 확인 (에뮬레이터 `my_phone`, `adb -s emulator-5554`)
- 설정 → 데이터 초기화(`DataResetRepositoryImpl` — 대화·할 일·메모·프로필·보관함 표를 지움)가 **안 지우는 것**을 확인한다:
  - 예약된 알림(AlarmManager): 알림을 하나 만든 뒤 "할 일" 초기화 → 그 시각에 그래도 울리나. **울리면 결함 → 고친다**(초기화 때 예약 취소, 테스트 포함). 알림이 어느 표에 저장되는지부터 코드로 확인.
  - 위젯 숫자(초기화 뒤 갱신되나), 기기 캘린더에 들어간 일정(앱 밖이라 남는 게 정상 — 체크리스트에 적기), 앱 외부 폴더 파일(`debug_*.txt`·`diag_runaway.txt`·`embedding/`).
- 에뮬레이터 앱 데이터에 시험 알림·메모를 만드는 일은 **미리 사용자에게 묻는다**(앱 데이터 변경).

### 2. 실사용 시작 체크리스트 — `docs/checklists/real_use_start.md`
- 순서: (필요하면) 메모 백업 내보내기 → 설정 → 데이터 초기화(어떤 대상을 고를지) → 기기 캘린더 앱에서 시험 일정 지우기(제목 예: 아침 운동·헬스·치과·팀 미팅 등 휴대폰 확인 때 만든 것) → 앱 폴더 디버그 파일 지우기(adb 또는 파일 앱) → 앱 다시 열어 비었는지 확인.
- 지우는 것은 **사용자가 실사용 시작 때 직접**(기존 결정 — "실사용 전에 정리할까요?"라고 묻지 않는다).

### 3. 휴대폰 확인 몰아서 (SM-S938N, 약 20분 — 시작 전에 무엇·왜·몇 분을 말하고 허락받기)
- `docs/checklists/device_gate.md` 0.42.x 의 `[ ]` 줄. 승인 시트는 거절(실제 일정·알림을 만들지 않음). adb 캡처·덤프는 가져온 뒤 휴대폰에서 지운다. 끝나면 adb 종료(`adb kill-server`).
  - Claude(adb `scratch/lab/device/turn.py`·`ui.py`): 0.42.5 "아침 운동 → 7시 → 내일 7시로 할까요? → 응" · 0.42.3 바꿔 말한 메모 합치기 후보(메모 두 개가 필요 — 앱 데이터라 미리 묻기) 등 채팅으로 되는 것.
  - **사용자 손**: ① 0.42.7 "내일 3시 치과, 5시 팀 미팅 둘 다 잡아줘" → 시트 이름 옆 "1/2"·"2/2" 표시(둘 다 취소해도 됨) ② 0.42.2 기억 정리 중 **홈 버튼**으로 나갔다 오면 "중간에 멈췄어요" ③ 0.42.2 백업 → 할 일 추가 → 복원 → 위젯 숫자 원복.
  - 0.42.4 폭주 재발 감시·"실사용 중 지켜볼 것" 줄은 실사용 중 계속 보는 항목(체크하지 않음).

### 4. 마무리
- 결함을 고쳤으면: 버전 0.42.10, 게이트(`./gradlew test lintDebug assembleDebug`), CHANGELOG 0.42.10, 커밋(한 줄 제목). 고친 것이 모델 입력과 무관하면 회귀 세트 대상 아님.
- `device_gate.md` 체크, 이 계획서 상단 `상태: 완료`, 0.43.0 계획서 상단은 그대로 "보류".
- 푸시는 사용자 요청 시(0.42.9 두 커밋 포함).

## 열린 것 (이 점검 밖 — 실사용 중 다시 보이면 회차로)
- 기억 → 알림(0.42.9 접음 — 트리거 줄이 회귀 세트 clock·inject 를 깸). 다음에 시스템 지시를 손볼 때 `remind_mem` 묶음으로 다시 잰다. 그 묶음 기준값(지금 0/4)은 아직 저장 안 함 — 저장은 사용자 확인 뒤.
- GPU 임베딩 공존 시 채팅 출력 깨짐의 근본 원인(0.42.8 에서 CPU 로 피함).
- 시각을 답한 뒤 끝 시각만 다시 묻는 흔들림(0.42.5 기록).
