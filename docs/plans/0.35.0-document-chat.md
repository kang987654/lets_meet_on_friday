# 문서 뷰어 2차 — docx · hwpx 읽기 모드 + 채팅으로 보내기 (0.35.0)

## Context

0.34.0(`0.34.0-document-viewer.md`)의 경량 뷰어 위에 **워드(docx)·새 한글(hwpx)** 을 얹고, 뷰어에서 고른 내용을 **채팅으로 넘기는 연결**을
만든다. 사용자 지시(2026-10-02): 채팅 첨부는 있으면 좋지만 **위험 요소 관리를 잘 해야 한다**, 모델은 **연결할 때만 켜진다**.

**현황 (탐색 확정)**:
- 채팅 첨부 본문 상한 `Constants.MAX_ATTACHED_DOC_CHARS = 300`(`core/.../Constants.kt:147`) — 예산에서 파생된 값이고 KDoc 이 "문서 요약 기능이
  못 된다"고 명시한다. 표로 치면 10행 안팎. **늘리지 않는다**(TD-3 해소 전 예산 불변).
- 입력바 첨부 피커는 `GetContent("*/*")` → `AttachmentReader.readDocument` 가 **모든 비이미지를 텍스트로 읽는다** — xlsx·docx·pdf 를
  고르면 zip/PDF 바이트가 깨진 문자열로 모델에 들어간다(**현존 결함**). 이 읽기는 E2E `waitForIdle` 경합 때문에 **동기**다(KDoc [WHY]).
- 모델 입력 래퍼: `ChatViewModel.sendMessage` 가 `"첨부된 문서 내용(${fileName}):\n${textContent}"` 로 감싼다.
- `ShareIntentHandler` 는 외부 `ACTION_SEND`(text/image)만 처리하고 `SharedInput.Document(uri, fileName, textContent)` 를 만드는 쪽은
  `AttachmentReader` 뿐이다.
- 긴 문서 요약의 정식 경로는 `expand.md` D1(페이지 단위 oneShot 요약 + 발열 게이트)이다 — 이 회차 범위 밖.

## 사용자 확정 결정 (2026-10-02)
1. docx·hwpx 는 **읽기 모드**(문단·제목·굵게/기울임/밑줄·목록·표·이미지 재배치). 쪽 나눔·글꼴·정밀 배치는 재현하지 않는다. doc 미지원.
2. 채팅 연결은 **"채팅으로 보내기"** — 뷰어에서 범위를 골라 넘기고, **그 순간에만 모델이 켜진다**(MainActivity 진입 → 0.34.0 D2 의 warmUp).
3. 300자 상한 유지 + 얼마나 들어갔는지 표시.

## 승인 결정 (2026-10-02 — 전부 제안대로)
- **D1 범위 고르기**:
  - 시트: **행 번호 탭으로 시작·끝 행 선택**(전체 열), 사각 범위 드래그는 하지 않는다(터치 조작 오류가 잦고 구현이 크다).
  - docx·hwpx: **문단 선택 모드**(문단 탭으로 체크, 표는 통째로 한 블록).
  - PDF: **현재 페이지** 텍스트 — 안드로이드 15+ 텍스트 API 가 확인될 때만(M0), 아니면 PDF 의 보내기 버튼은 숨긴다.
  - 하단 막대에 "n / 300자" — 초과분은 잘리고 "앞 300자만 보내요" 안내. 0자면 버튼 비활성.
- **D2 넘기기 방식**: 뷰어 → `MainActivity` 를 **명시적 인텐트 + 내부 전용 action**(`com.kosmos.app.action.ATTACH_DOCUMENT`, extra: 파일 이름·
  변환 텍스트·원본 uri)으로 시작 → `ShareIntentHandler` 가 `SharedInput.Document` 로 방출(replay 계약 그대로) → 입력바 프리뷰.
  **매니페스트 필터에 넣지 않는다**(외부 앱이 같은 action 으로 임의 텍스트를 주입하지 못하게 — 명시적 인텐트만 처리, 발신 패키지 확인).
  **자동 전송하지 않는다** — 사용자가 질문을 적어 보낸다.
- **D3 표 변환 형식**: M0 실측(exp46)으로 고른다 — 후보 ① `|` 구분 마크다운 표 ② 탭 구분(TSV) ③ "열머리: 값" 줄. 같은 300자에서
  **표 질문 정답률**이 가장 높은 것(동률이면 짧은 것). 래퍼 문장(`"첨부된 문서 내용(…)"`)은 바꾸지 않는다.
- **D4 입력바 첨부(`AttachmentReader`) 결함 수정**: 텍스트 계열은 **지금처럼 동기**(E2E 계약 보존), xlsx·docx·hwpx·pdf 는 문서 파서로
  **비동기**(IO) 추출 — 프리뷰는 "읽는 중…" 후 채워진다. 내용은 앞에서부터 300자(시트는 첫 시트 앞 행). 지원하지 않는 바이너리(xls·doc·hwp·zip 등)는
  **첨부를 거부하고 안내**("이 형식은 문서 뷰어에서 열어 범위를 골라 보내 주세요" 또는 "지원하지 않는 형식이에요")한다 — 깨진 바이트가
  모델에 들어가는 경로를 닫는 것이 우선이다.
- **D5 이미지가 든 docx·hwpx**: 무작위 접근이 필요해 앱 캐시로 한 번 복사(크기 상한 0.34.0 과 동일) 후 `ZipFile` 로 지연 로드, 뷰어 종료 시 삭제.
  이미지 없는 문서는 스트리밍 그대로.

- 파서는 순수 JVM 테스트, 픽스처는 테스트 코드가 조립(개인 문서 커밋 금지). 기존 단언 수정 0건 목표 — 결함 수정으로 단언이 바뀌어야
  하면 목록을 먼저 보이고 확인받는다.

## M0 — 실측 (exp46) + PDF 텍스트 API 확인
- `scratch/lab/exp46_attached_table.py`: 합성 표 5종(가계부·성적·재고·일정·연락처, 각 8~15행) × 형식 3종(D3) × 질문 4개(특정 셀 값·합계·
  최댓값 행·조건 개수) — 300자 절단 후 `"첨부된 문서 내용(파일명):\n…"` 래퍼 그대로 채팅 대화로 투입, 정답 포함 여부 채점. 형식별 정답 수와
  300자 안에 들어간 평균 행 수를 기록. 채택 형식 원문을 이 계획서에 적는다.
- docx 문단 텍스트(같은 래퍼)는 형식 선택지가 없어 스모크 3건만(요약·특정 문장 찾기).
- PDF: 에뮬레이터 API 35+ 이미지에서 `PdfRenderer` 텍스트 추출 API 존재·한글 추출 품질 확인(합성 PDF). 미달이면 D1 대로 PDF 보내기 숨김.

## M1 — docx · hwpx 파서 (순수 JVM)
`domain/document/`
- 공통 결과 `FlowDocument(blocks)`: `Heading(level, spans)` · `Paragraph(spans)` · `ListItem(level, spans)` · `Table(rows: List<List<List<Block>>>)` ·
  `Image(entryName, widthPx?, heightPx?)` · `PageBreak`. `Span(text, bold, italic, underline)`.
- `DocxReader`: `word/document.xml`(`w:p`·`w:r`·`w:t`·`w:tab`·`w:br`, `w:pStyle` Heading1~6/Title → 제목, `w:numPr` → 목록, `w:tbl`(병합
  `w:gridSpan`·`w:vMerge` 단순화), `w:drawing` `r:embed` → `word/_rels/document.xml.rels` 로 미디어 경로), 머리글·바닥글·각주·주석은 제외.
- `HwpxReader`: `Contents/content.hpf`(섹션 순서) → `Contents/section*.xml`(`hp:p`·`hp:run`·`hp:t`·`hp:tbl`·`hp:pic` → `BinData/`),
  굵게·기울임은 `Contents/header.xml` 의 `charPr` 참조로. **hwpx 는 실파일 다양성이 커서** 모르는 요소는 텍스트만 건지고 건너뛴다(실패하지 않게).
- `DocumentType` 에 DOCX·HWPX 추가: MIME `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, hwpx 는 기기마다 MIME 이
  달라(`application/hwp+zip`, `application/haansofthwpx` 등 — **실기기에서 확인**) 확장자 판별을 함께 쓴다.
- `SheetTextFormatter`(D3 채택 형식) · `FlowTextFormatter`(문단 줄바꿈, 표는 D3 형식) — 300자 절단과 "몇 자 중 몇 자" 계산 포함.
- 테스트: `DocxReaderTest`·`HwpxReaderTest`(테스트 안에서 zip 조립 — 제목·서식 런·목록·표 병합·이미지 참조·모르는 요소 무시·깨진 XML),
  `TextFormatterTest`(절단 경계에서 행/문단 중간을 자르지 않음 — 행 단위로 끊고 남는 자리는 비운다).

## M3 — 채팅으로 보내기
- 뷰어 선택 모드(D1) + 하단 막대("n / 300자", "채팅으로 보내기").
- `DocumentViewerActivity` → 명시적 인텐트(D2), 원본 uri 는 `FLAG_GRANT_READ_URI_PERMISSION` 으로 넘긴다.
- `ShareIntentHandler.handleIntent`: 내부 action 분기 추가 — `SharedInput.Document(uri, fileName, textContent)` 방출. 외부에서 온 같은 action
  (명시적 컴포넌트가 아닌 경우)은 무시.
- 테스트: `ShareIntentHandlerTest` 내부 action → Document 방출, 300자 초과 텍스트는 절단 상태로 방출. Robolectric: 보내기 → MainActivity 인텐트
  내용(action·extra) 검증, **뷰어 단계에서 warmUp 0회**(0.34.0 테스트 확장).

## M4 — 입력바 첨부 결함 수정 (D4)
- `AttachmentReader`: `DocumentType.detect` 로 분기 — 텍스트 계열은 기존 동기 경로 그대로, 지원 바이너리는 비동기 추출 콜백, 미지원 바이너리는
  거부 결과(`Result(input = null, rejected = 형식)`)로 안내.
- `ChatScreen`: 비동기 결과 수신 시 프리뷰 갱신("읽는 중…" 상태는 기본값 있는 파라미터로).
- 테스트: `AttachmentReaderTest` — xlsx 첨부가 깨진 바이트가 아니라 표 텍스트, xls/zip 거부, txt 는 기존과 동일(동기). 기존
  `MultimodalChatE2ETest` 무수정 통과.
