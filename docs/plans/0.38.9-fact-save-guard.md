# 0.38.9 — 기록에 끌린 메모 저장과 넘긴 것 마무리

## 목표
0.38.8 M3(사실만 말하면 "메모해 둘까요?")가 실기기에서 깨졌다 — 대화 기록에 "사실 → 저장 시트 → 거절" 쌍이 쌓이면 모델이 그 모양을 따라
저장을 부른다(휴대폰 3/3, exp62g 3쌍 5/7). 프롬프트로는 기록의 끌림을 못 이기므로(M1 과 같은 모양) 앱이 막는다. 그리고 0.38.5~0.38.8 에서
"다음 후보"로 넘긴 것을 이번 회차에 모두 닫는다 — 고치거나, 측정해서 바꾸지 않기로 결론을 내거나, 사용자만 볼 수 있는 항목은 목록으로 넘긴다.

## 정한 것 (2026-10-26 사용자)
1. **사실 저장은 코드로 막는다** — 사용자 말에 저장 낱말이 없고 바로 앞 비서 말이 저장을 묻는 말("메모해 둘까요?" 등)도 아니면, add_memory 는
   승인 시트 없이 막고 모델에 "확인하고 메모해 둘까요?라고 물어보라"는 결과를 돌려준다(0.38.7 `RepeatRequest` 가드와 같은 자리, `BaseAgent`).
   부작용(사용자에게 설명함): ① 목록에 없는 말("이거 알아둬")로 부탁하면 한 번 더 묻는다 ② 모델이 다른 표현으로 물은 뒤 "응"이면 다시 물을 수 있다
   ③ 막힌 뒤 엉뚱한 답("기억해 둘게요") ④ 막혀도 지난 대화 요약에는 남는다. ①②는 낱말 목록을 넉넉히, ③은 결과 문구 실측으로 줄인다.
2. **ISO 일시는 앱이 고쳐 보여 준다** — 모델 답의 ISO 원문(`2026-10-26T16:30:00` 등)을 `IsoDateTimeParser.toDisplayKorean` 표기로 바꿔 화면·대화 기록에
   남긴다. 프롬프트는 건드리지 않는다(고정 예산 영향 없음).
3. **은하 전환도 이번 회차에** — 휴대폰 연결해서 확인.
4. **넘긴 것은 이번 회차에 모두 닫는다.**

## 지금 알고 있는 것 (CHANGELOG 0.38.5~0.38.8 [Note], device_gate S~V)
- 기록 없는 새 대화에서는 F1 이 듣는다(exp62e 저장 호출 0/8, exp62g h0 1/7). 사실·거절 1쌍 2/7, 3쌍 5/7 — 쌓일수록 나빠진다.
  저장 시트 내용이 앞 대화 문장을 가져온다("다음 주 금요일 회의실은 5층 C룸이에요." — 이번 말은 "회의실은 5층 C룸이야").
- 되묻기 가드 `RepeatRequest`(domain/memory) 의 `SAVE` 낱말: 기억해·저장·메모해·잊지 마·적어 둬/놔/줘. 막을 때 결과는 `ToolResultJson.error(REPEAT_NOT_SAVE)`.
- 저장 호출 없이 "기억해 둘게요" 약속: F1 뒤 1/8(exp62e) — 툴을 부르지 않으니 위 가드로는 못 잡는다.
- 앞에서 한 거절 따라 하기: 프롬프트 후보 셋 모두 효과 없음(0.38.8 M1, exp62d 현행 2/12). 기록 쪽(모델 입력에 들어가는 앞 거절 답)은 아직 안 해 봄.
- ISO 노출은 실험실에서 "회의는 오후 4시 30분에 시작해" 답에서 봄(현행에도 있음). 빈도는 아직 모름.
- 기억 합치기 문장 끝: `MemoryMergeGuard.toMemoEnding` 이 "이다·있다·없다"만 정리 — "…마신다"·"좋아한다" 같은 동사 끝이 남는다(0.38.6 넘김).
- 은하 전환: 채팅 확대·입자 수는 병목이 아니다(0.38.8 M5 A/B). Ready 에 편승하는 백그라운드 추론(`EpisodeSummarizeScheduler` catch-up·drain,
  `MorningBriefingGenerator`)이 전환과 같은 시점에 GPU 를 쓸 수 있다 — 아직 확인 안 함.
- 이미 닫힌 것(확인함): 표 숫자 천 단위 구분(`XlsxNumberFormat` grouping), 런타임 의존성 최신화, 말줄임표 통일, 활동 기록 문구, 위젯 13sp(코드).

## 마일스톤 (각각: 측정 → 사용자 확인 → 구현 → 게이트 → 커밋)
- **M0 재현 세트** — exp62g 를 기준으로: 기록 h0/h1/h3 × 사실 8, 저장 요청 낱말 변형(목록 안 6 + 목록 밖 "알아둬"·"까먹으면 안 돼"·"나중에 물어볼게" 등),
  "메모해 둘까요?"/"저장해 드릴까요?"/"기억해 둘까요?" 뒤 "응·그래·좋아·부탁해", 저장 없는 약속, 거절 따라 하기(exp62d A), ISO 노출 빈도(일정·시각이 든 사실·질문 12).
  - **M0 결과(2026-10-26, 현행 기준값)**: 사실 저장 호출 h0/h1/h3 1·2·5/7(물어봄 5·4·1), 목록 밖 저장 부탁 5/6 저장인데 지금 가드 낱말은 0/6 — 낱말을 넓혀야 한다,
    물음 뒤 긍정 12/12, 거절 3/12, ISO 1/12(일정 추가를 묻는 답).
- **M1 사실 저장 가드 + 저장 없는 약속** — 결정 1. 앱 가드를 실험실에서 흉내(막힌 호출에 결과 문구를 돌려줌)해 문구 후보를 잰다: 물어봄 비율·거짓 약속·"응" → 저장.
  낱말 목록(사용자 말 저장 낱말·앞 비서 말 저장 물음)은 domain 순수 객체 + 테스트, `BaseAgent` 의 `RepeatRequest` 가드 옆. 앞 비서 말은 세션 기록의
  마지막 비서 메시지. 저장 없는 약속은 답 글자에 약속 표현이 있고 이번 턴에 add_memory 가 실행되지 않았으면 그 문장을 "메모해 둘까요?"로 바꾸는 안을
  같이 잰다(코드, 모델 입력 아님). 회귀: 저장 요청 6/6·스모크 11/11·되묻기 가드 그대로.
  - **M1 결과(2026-10-26)**: G3 문구 채택, 낱말 넓힘(12 중 11·사실 0). 갈린 점 — "응" 뒤 모델이 저장 없이 "메모해 두었어요" 2/6 을 발견해 앱이 저장 시트를 연다(사용자 결정).
- **M2 거절 따라 하기 (기록 쪽)** — 0.38.8 M1 은 프롬프트만 바꿨다. 이번에는 모델에 넣는 대화 기록에서 앞 거절 답("…기능은 없어요")을 빼거나 줄이는 안을
  실험실에서 잰다(exp62d 세트, 현행 2/12). 나아지면 기록 조립(코드)에, 아니면 "바꾸지 않음"으로 닫는다.
  - **M2 결과(2026-10-27)**: 거절 쌍을 모델 입력 기록에서 빼고 거절 뒤 대화를 다시 만듦 — 6/12 → 1/12(exp64c).
- **M3 ISO 고쳐 보여 주기** — 결정 2. domain 순수 함수(답 글자 안의 ISO 날짜·일시 → 한국어 표기, 시간대 인자) + 테스트(UTC 명시). 적용 자리는
  스트리밍 표시와 저장되는 최종 답 둘 다(대화 기록·음성 읽기도 같은 글자). 숫자만 있는 "2026"·전화번호·송장번호는 건드리지 않는다.
- **M4 합치기 문장 끝** — `toMemoEnding` 에 동사 끝(…ㄴ다/는다/한다 → …ㅁ/음/함: "마신다" → "마심", "먹는다" → "먹음", "좋아한다" → "좋아함") + 테스트.
  모델 입력이 아니라 실측 불필요.
- **M5 은하 전환과 엔진** — 결정 3. 휴대폰 logcat·framestats 로 Ready 직후 백그라운드 추론이 전환과 겹치는지 확인. 겹치면 Ready 편승 작업을
  스플래시 전환이 끝날 때까지 미룬다(미루는 신호는 시각이 아니라 전환 완료 — 결정성 수칙). 안 겹치면 원인만 기록하고 바꾸지 않는다. 온도 기록.
- **M6 마무리와 확인 목록** — CHANGELOG·계획서 상태, 휴대폰 확인(device_gate W). 넘긴 확인 항목을 누가 볼 수 있는지로 나눠 닫는다:
  - 휴대폰에서 직접(앱 안에서만): 사실만 말하기·"응" → 저장·목록 밖 부탁·저장 없는 약속·ISO 표기·은하 전환, 라이트 모드 엑셀 원본 색(앱 설정의 테마),
    기억 정리 주간 회고 해요체, 테스트 대화가 요약된 뒤 거절이 "저장하지 못했어요"로 적히는지.
  - 에뮬레이터에서: 위젯 글자 13sp 잘림(홈 화면은 다른 앱이라 휴대폰에서 캡처하지 않는다), 프로필 제안 체크 목록(제안이 둘 이상 생기게 대화한 뒤).
  - 사용자만 볼 수 있는 것(시각·실사용): 아침 브리핑 첫 줄(다음 날 아침), 긴 대화에서 예산 리셋이 줄었는지, 휴대폰 홈 화면 위젯.
  - 사용자 결정으로 생략한 것(TalkBack·애니메이션 제거·영상 비교)은 그대로 둔다.

## 예산·실측 수칙
M1 의 결과 문구는 턴 몫(툴 결과)이라 고정 예산 밖이지만 모델 입력이므로 실측 선행(AGENTS §2-⑤). M2 는 기록 조립이 바뀌면 모델 입력이 바뀐다 — 실측 선행.
시스템 지시·트리거 줄은 바꾸지 않을 계획 — 바꾸게 되면 `MEASURED_OVERHEAD` 갱신(지금 여유 35). M3·M4·M5 는 모델 입력이 바뀌지 않는다.
