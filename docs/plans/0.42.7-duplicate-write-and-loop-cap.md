# 0.42.7 같은 쓰기 반복 막기 · 툴 실행 상한

> **상태**: 완료 (CHANGELOG 0.42.7). 계획과 갈림 — 원인은 앱의 첫 호출만 실행 정책, 차례 실행으로 해결(중복 가드·상한 변경 없음).
> 정본 순서: **AGENTS.md > 이 계획서**.
> 근거: CHANGELOG 0.42.6 exp101 — "내일 3시 치과, 5시 팀 미팅 둘 다 잡아줘"류 6/6 이 첫 일정을 같은 인자로 두 번 부른 뒤 "둘 다 잡았어요"(지금 실사용에서도 생기는 결함).

## 계획과 바뀐 점 (구조 확인)
- **선택지 2(알림 지난 시각)는 이미 있다** — `AddReminderToolExecutor` 가 과거 시각이면 인자 오류(`ToolArgumentException.Reason.PAST`)를 돌려준다. exp101 장치가 흉내 내지 않아 성공으로 보였을 뿐 → 기록만.
- **선택지 1 은 상한과 묶인다** — 한 턴 툴 실행은 2번(생성 3번, `MAX_TOOL_LOOP_COUNT = 3`). 첫 일정 실행 → 중복 호출을 막음 → 세 번째 생성의 둘째 일정 호출은 상한 오류. 막기만 하면 "중복 + 거짓 완료"가 "솔직한 실패(오류 말풍선)"로 바뀔 뿐이다.

## 결정 (exp102 로)
- **D1 중복 쓰기 가드** — 같은 턴에서 이미 **실행된** 쓰기(일정·알림·메모)와 이름·인자가 같은 호출은 실행하지 않고, 결과 문구로 "이미 추가했다, 남은 항목이 있으면 그것을 추가하라"를 돌려준다(`BaseAgent` 툴 루프 — 턴 안 실행 기록이 필요해 순수 가드 밖). 문구는 실측.
- **D2 생성 상한 3 → 4(실행 2 → 3)** — 중복 가드만 / 가드 + 상한 4 를 비교. 상한을 올리면 KV·시간 비용(툴 반복 KV 가드 0.41.6 이 이미 막는다)과 함께 판단.
- 채택 기준: 두 항목 요청이 두 일정 다 바르게 들어가는 비율, 거짓 완료 0, 한 항목 요청·회귀 세트 무손상.

## 고정 제약
- 툴 결과 문구 = 모델 입력 → 실험실 실측 + 회귀 세트(흉내 갱신). 시스템 지시·선언 불변 목표 → `MEASURED_OVERHEAD` 불변.
- 기존 테스트 단언 불변(상한 테스트가 `MAX_TOOL_LOOP_COUNT` 값을 고정하고 있으면 바꾸기 전 보여 드리고 확인).
