# 월 캘린더 + 오늘 요약 제거 (0.28.0)

## Context

일정 화면은 "오늘 / 이번 주(오늘부터 7일)" 세그먼트와 7일 날짜 띠, 선택 범위의 AI 요약(oneShot ~10초)으로
되어 있다. 사용자는 실제 캘린더 앱처럼 **한 달 전체가 보이는 화면**을 원한다(2026-10-01). 동시에 오늘 요약은
목록만 봐도 충분해 비용 대비 가치가 낮다.

**현황 (탐색 확정)**:
- `GetTodayScheduleUseCase(range, now, zoneId)` — `RangeType.TODAY|WEEK` 로 끝 시각만 정한다. 내부 일정은
  `getPendingTasksData(0, 1000)`(미완료만)에서 `dueDateIso` 로 거르고, 기기 캘린더는 `readEvents(startMs, endMs)`
  — **임의 범위를 이미 받는다**. 실패는 `deviceCalendarFailed` 로 올린다(ADR-004).
- `RangeType` 사용처 7곳: GetScheduleToolExecutor(툴 `today|week`), MorningBriefingGenerator,
  BriefingNotificationWorker, KosmosWidget, CalendarViewModel/Screen, SummarizeScheduleUseCase.
  → enum 에 MONTH 를 넣으면 `when` 분기 전부가 영향받는다. **월은 날짜 범위 오버로드로 받는다**(enum 무변경).
- `CalendarViewModel.loadSchedule` 은 일정이 1건 이상이면 범위 무관 요약을 돌린다. 날짜 띠로 하루를 고르면
  목록은 그날로 좁혀지지만 요약은 7일 전체 그대로다(이번 회차에서 "이번 주 요약" 라벨로 의미를 맞춘다).
- `CalendarEvent(id, title, startIso, endIso, location, description)` — **출처 필드가 없다**. 점 색으로 Kosmos/기기
  일정을 가르려면 `source` 필드(기본값 있음)가 필요하다.

## 사용자 확정 결정 (2026-10-01)
1. 월 단위 AI 요약 없음.
2. 일요일 시작 그리드.
3. 탭으로 **월 / 목록** 둘 다 둔다. 목록 탭은 현재 화면(오늘 / 이번 주 세그먼트 + 날짜 띠)을 그대로 옮긴다.
4. 요약은 **오늘 요약을 빼고**, 이번 주(오늘부터 7일 — 현재 구현 그대로)만 남긴다.

## 승인 결정 (2026-10-01 — 전부 제안대로)
- **D1 기본 탭**: 월(확정) / 목록.
- **D2 점 색 구분**: `CalendarEvent.source`(`app`|`device`, 기본 `app`) 추가해 Kosmos·기기 일정을 색으로 가른다(확정).
- **D3 공휴일**: 이번 회차는 **일요일만 빨강**(확정). 공휴일 데이터 출처(기기 공휴일 캘린더 판별 또는 내장 목록)는 별도 회차.
- **D4 기존 테스트 1건 수정(규칙 예외 — 확인 필요)**: `CalendarViewModelTest.요약을 기다리지 않고 목록을 먼저 내보낸다`
  가 `loadSchedule()`(기본 범위 TODAY)로 요약 도착을 단언한다. 오늘 요약을 없애면 깨지므로 호출을
  `loadSchedule(RangeType.WEEK)` 로 바꾼다 — 단언 자체(목록 선행·요약 도착)는 그대로.

## 고정 제약
- `get_schedule` 툴·`RangeType`·브리핑·위젯 동작 무변경 → **프롬프트 표면 무변경**(M0 실측 불필요).
- 색은 `KosmosTheme.colors` 토큰만(§4-6). 표기는 `IsoDateTimeParser` 단일 출처(§4-7).
- 벽시계 금지(§2-④): 그리드 계산은 `YearMonth`·`today` 를 인자로 받는 순수 함수.
- 완료한 할 일은 지금처럼 표시하지 않는다(내부 일정 = 미완료만).

## M1 — 도메인: 날짜 범위 조회
- `GetTodayScheduleUseCase` 에 `invoke(start: LocalDate, endInclusive: LocalDate, zoneId)` 오버로드 추가 — 기존
  `RangeType` 경로는 이 오버로드를 부르도록 내부 정리(동작 불변). 월 조회는 **전용 반환 타입**
  `MonthSchedule(events, deviceCalendarFailed)` 을 쓴다 — `ScheduleData.rangeType` 에 맞는 값이 없고, 기존 단언이 보는
  `ScheduleData` 를 건드리지 않기 위해.
- `CalendarEvent.source` 추가(D2, 기본값 `"app"`), 기기 캘린더 매핑에서 `"device"`.
- 테스트: 월 경계(1일 00:00 포함·말일 23:59:59 포함·다음 달 1일 제외), 기기 실패 플래그 유지.

## M2 — 순수 그리드 계산
- `ui/calendar/MonthGrid.kt`: `monthGrid(yearMonth, firstDay = SUNDAY): List<List<LocalDate>>` — 앞뒤 달 날짜로 채운
  **필요한 만큼의 주(4~6)**. 테스트(표 형식): 2026-10(목 시작, 5주), 2026-02(일 시작·28일 → 4주), 2028-02(윤년 29일),
  2026-08(토 시작 → 6주), 31일 달의 마지막 주. 주 수가 달마다 달라 그리드 높이가 바뀌므로 페이저 높이는 6주 기준으로 고정.
- `eventsByDate(events, zoneId): Map<LocalDate, List<CalendarEvent>>` — 여러 날에 걸친 일정은 시작일에만(이번 회차).
