# 0.42.2 몇 시 가드 빈틈 · 뒤로가기 움직임 · 설정 설명 위치

> **상태**: 완료 (CHANGELOG 0.42.2). D4 는 구현 중 "뒤 각주만 안으로, 앞 안내는 제목 아래 그대로"로 좁힘(사용자 확인). 계획·구현·검증 Claude 한 세션.
> 정본 순서: **AGENTS.md > 이 계획서**.
> 근거: 2026-11-17 휴대폰 확인(CHANGELOG 0.42.1 [QA/Device]) + 사용자 화면 녹화(2026-11-17 14:13). 원래 0.42.2 로 잡았던 부수 추론 품질(묶음 C)은 0.42.3 으로 민다.

## 목표
1. **몇 시 가드 빈틈** — "금요일 오후 3시에 치과 예약 잡아줘" 다음 턴의 "목요일에 미용실 예약 잡아줘"가 00:00 으로 승인 시트까지 갔다.
   `ScheduleTimeIntent.needsClock` 이 바로 앞 사용자 말(0.41.15 `2452611` — 요일 확인 뒤 "Yes" 흐름용)에서 **다른 요청의 시각**을 찾아 통과시킨다.
2. **뒤로가기 축소 애니메이션 제거** — 화면(일정 등)에서 뒤로 갈 때 화면이 70% 로 줄며 사라진다.
   navigation-compose 2.10.2 는 예측 뒤로가기 전환을 일반 pop 과 **따로** 두고 기본값이 `scaleOut(0.7f)`(라이브러리 `DefaultNavTransitions`) — 우리는 `popExit`/`popEnter` 만 줘서 기본값이 쓰였다. `AppNavHost` 의 "pop 쪽을 주면 예측 뒤로가 따라간다" 주석이 지금 버전에서 틀렸다.
   지난 대화 시트도 닫힐 때 줄어든다(M3 `ModalBottomSheet` 의 예측 뒤로가기).
3. **지난 대화 시트가 뒤로가기 두 번에 닫힘** — 녹화 6.0초 첫 번째 뒤로가기에 시트가 그대로, 7.25초 두 번째에 닫힘. 서랍은 그다음 한 번에 닫힘. 원인 미상.
4. **설명(각주) 위치 통일 — 박스 안으로(사용자 결정)** — 지금 `Section(footnote=…)` 는 박스 **아래**(0.38.3 각주 문법), AI 모델·뜻 검색 모델 칸은 박스 **안**. 같은 문법을 쓰는 화면 전체의 각주를 박스 안 맨 아래로(D4).
5. **에뮬레이터 확인 남은 것** — 정리 중단 안내(휴대폰에서 시작 화면으로 돌아옴, 원인 미상), 복원 뒤 위젯(할 일 개수 — 일정은 기기 캘린더에도 들어가 복원 시험에 쓸 수 없다).

## 결정
- **D1 가드** — 바로 앞 사용자 말의 시각은 **이번 말이 짧은 긍정 한마디일 때만**(`MemoSaveIntent.isYes` 재사용 — "응", "그래", "Yes" 등) 인정한다. 요일 확인 뒤 "Yes"(0.41.15 빈틈)는 그대로 통과, 다른 요청이 끼면 막힌다.
  바로 앞 비서 말의 시각은 지금처럼 인정("내일 3시로 잡을까요?" 뒤 "응").
- **D2 화면 뒤로가기** — `predictivePopEnterTransition`·`predictivePopExitTransition` 을 일반 pop 과 같은 "옆으로 미끄러지기"로. 끌기(제스처) 중에도 같은 움직임.
- **D3 시트** — 시트 닫힘도 축소 없이 아래로 내려가게(M2 진단 결과에 따라 3번과 함께 한 방식으로). 모든 `ModalBottomSheet`(지난 대화·승인·프로필·알림 수정·채팅 머리) 공통으로.
- **D4 각주 — 각주 문법을 쓰는 화면 전체를 박스 안으로(사용자 결정 (나), 2026-11-17)** — 설정 · 모델 관리 · 활동 기록 · 메모·할 일 · 문서 홈 · 드로어 · 기억 정리 등.
  `docs/DESIGN.md` 화면 문법(0.38.3 "묶음 아래 각주")을 "묶음 안 맨 아래"로 고친다.
  설정 밖 화면은 사용자가 거슬린다고 본 적이 없으므로 **바뀐 모습을 기록으로 남긴다**: 에뮬레이터 전·후 캡처(라이트·다크)를 `docs/design/footnote-0.42.2/` 에 화면별 비교표(.md)와 함께(0.38 `audit-0.38/` 선례).

## 고정 제약
- 가드는 모델 입력이 아니지만 모델 행동 가드라 **회귀 세트**(AGENTS §2-⑤ 예외) — `run.py` 의 흉내(`prev_user` 조건 2곳)를 같이 고치고 clock·weekday·guard_en 포함 전체를 돌린다. 기준값 저장은 확인 뒤.
- 기존 테스트 단언 불변. 새 테스트: 가드(다른 요청 뒤 막힘 · "Yes" 뒤 통과 유지).
- UI 셸 변경 → CHANGELOG 에 실기기 확인 목록(라이트 모드 포함, AGENTS §2-③). 진단·재현은 **에뮬레이터**(`emulator-5554`, 3버튼·제스처 둘 다), 휴대폰은 회차 끝 짧은 최종 확인만(미리 묻기).
- E2E 계약 표면 불변(`ChatScreen` 기본 인자, `"Attach"`/`"Send"`/`"Document Attached"`).

### M2 — 시트 뒤로가기 진단 (에뮬레이터)
- 에뮬레이터에서 서랍 → 지난 대화 → 뒤로(3버튼·제스처). 첫 뒤로가기가 어디로 가는지 로그(임시, 커밋 안 함)로 확인 — 후보: 서랍의 `BackHandler`(MainScreen)·`ModalNavigationDrawer` 자체 처리·시트 창의 예측 뒤로 콜백.
- 원인을 CHANGELOG 에. 고치는 방식은 D3 과 묶어 정한다(진단 결과가 계획과 갈리면 [WHY]·CHANGELOG).

### M3 — 뒤로가기 움직임 (D2·D3)
- `AppNavHost`: `predictivePopEnterTransition = { nav.popEnter() }`, `predictivePopExitTransition = { nav.popExit() }`, 틀린 주석 고침.
- 시트: M2 결과대로 — 축소 없는 닫힘 + 뒤로 한 번에 닫힘. 공통 래퍼가 필요하면 `ui/components` 에 하나(시트 5곳 교체).
- 테스트: 가능한 범위(시트가 뒤로 한 번에 닫힘 — Robolectric 은 시트 창·예측 뒤로를 흉내 못 할 수 있다 → 안 되면 실기기 목록으로).

### M4 — 각주 박스 안으로 (D4)
- 먼저 각주를 쓰는 화면을 전부 찾는다(`SettingsSections.Section`·`KosmosList`·화면별 캡션 `Text`) → 목록을 CHANGELOG 에.
- **바꾸기 전 캡처**: 에뮬레이터에서 화면마다 라이트·다크 → `docs/design/footnote-0.42.2/before/`.
- 각주·경고를 묶음 안 맨 아래로 — 가능하면 공통 컴포넌트(`KosmosListGroup` 의 각주 자리) 한 곳에서, 여백·구분선은 AI 모델 칸 설명과 맞춤. `docs/DESIGN.md` 화면 문법 갱신.
