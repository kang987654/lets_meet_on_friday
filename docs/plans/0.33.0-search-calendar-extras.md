> **상태**: 승인 (2026-10-01)

# 예산 밖 개선 — 기억 검색 질문 확장 · 공휴일 표시 · 여러 날 일정 (0.33.0)

## Context

채팅 프롬프트 예산과 무관한 세 가지(사용자 순서 ③, 2026-10-01). 셋은 서로 독립이라 마일스톤을 따로 커밋한다.

## A. 기억 검색 질문 확장 (C′3 보류분)
**현황**: exp37(0.25.0 M0) — 현행 11/16, 바이그램+**항상 확장(원 질문 전달)** 13/16, 앱 정책(미스 시에만 확장) 11/16. 미스 5건 중 2건은
툴 미호출(검색 밖 — 0.32.0 회상 트리거가 일부를 다룬다). 확장은 검색마다 oneShot 1회(+1~2초)와 **원 질문을 실행기까지 전달하는 배선**
(지금 `SearchMemoryToolExecutor` 는 모델이 고른 `keyword` 만 받는다)이 필요해 보류했다.

**승인 결정 (2026-10-01 — 전부 제안대로)**
- **D-A1 할지 말지**: 0.32.0 회상 트리거 결과를 본 뒤 exp37 을 다시 돌려(미호출 2건이 줄면 남는 이득이 확장만의 몫) **+2 이상일 때만** 구현(확정).
  +1~2초 지연은 답변 체감에 직접 붙으므로 이득이 1건이면 하지 않는다.
- **D-A2 원 질문 전달 방식**: `ToolArguments` 에 사용자 원문을 실행기 전용 필드로 끼우는 `BaseAgent` 배선(모델 입력 무변경, 제안).

**마일스톤**: M-A0 exp37 재실행(0.32.0 이후, `rescore` 로 모델 없이 일부 재계산 가능) → 판정 → (통과 시) M-A1 확장 oneShot 유스케이스 +
배선 + 발열 시 확장 생략 + 테스트(확장 실패 시 기존 경로 그대로) → M-A2 실기기 지연 측정 항목.

## B. 공휴일 표시 (월 캘린더)
**현황**: 0.28.0 은 일요일만 빨강(D3). 기기 캘린더 읽기(`AndroidCalendarTool`)는 일정만 가져오고 **캘린더 종류(공휴일 캘린더인지)를 모른다**.

**승인 결정 (2026-10-01 — 전부 제안대로)**
- **D-B1 데이터 출처**:
  - ① 기기의 **공휴일 캘린더 구독을 판별**(캘린더 이름·계정 유형으로 "대한민국의 휴일"류 식별) — 사용자가 구독해야 보이고, 이름 판별이
    제조사·언어마다 달라 불안정하다.
  - ② **앱 내장 공휴일 표**(양력 고정 휴일 + 음력·대체공휴일은 연도별 표) — 오프라인 원칙에 맞고 결정적이지만 **매년 갱신**이 필요하다
    (표가 없는 해는 일요일만).
  - 확정: ② 내장 표(2026~2027) + 표 밖 연도는 일요일만, 갱신 시점은 CHANGELOG Known Issue 로 남긴다.
- **D-B2 표시**: 날짜 숫자 빨강 + 선택일 목록 맨 위에 "추석 연휴" 같은 이름 한 줄(확정).

**마일스톤**: M-B1 `KoreanHolidays`(순수 함수, 연도별 표, 테스트: 고정 휴일·설/추석·대체공휴일 경계) → M-B2 그리드 색·목록 이름 → 에뮬레이터 육안.

## C. 여러 날 일정
**현황**: `eventsByDate` 가 시작일에만 묶는다(0.28.0 M2 범위 결정). `CalendarEvent.endIso` 는 있다.

**승인 결정 (2026-10-01 — 전부 제안대로)**
- **D-C1 표시 방식**: 걸친 날마다 **점**과 선택일 목록에 포함(목록에는 "10월 3일 ~ 10월 5일" 기간 표기) — 막대(띠) 표시는 그리드 레이아웃을
  다시 짜야 해 이번 범위 밖(확정).
- 종일 일정(날짜만 있는 ISO)의 끝 날짜가 배타(exclusive)인지 기기 캘린더 규약을 M-C1 에서 확인해 하루 더 칠하는 오류를 막는다.

**마일스톤**: M-C1 `eventsByDate` 기간 전개(상한 31일 — 잘못된 끝 날짜로 한 달을 다 칠하지 않게) + 표 테스트 → M-C2 목록 기간 표기 → 육안.

## 고정 제약
