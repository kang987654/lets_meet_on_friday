# 0.38.4 — 디테일과 움직임, 스플래시

## 목표
0.38.3 점검에서 넘긴 P2·P3 를 먼저 정리하고, 앱에 움직임의 기준(`Motion.kt` 토큰)을 세운다 — 화면 전환·누름·결과 등장을 짧고 한결같게, 시스템 "애니메이션 제거"는 어디서나 존중.
음성 입력 중에는 소리에 반응하는 파형을, 스플래시는 빛나는 구체 대신 브랜드 마크(항성과 행성·궤도)를.

## 정한 것 (2026-10-21 사용자)
1. **0.38.3 에서 넘어온 점검 P2·P3 는 이번 첫 마일스톤들에서** — 문구는 규칙 위반(가운뎃점·줄표·내부 이름·"토큰")만, 말투 전체는 0.38.5.
2. **햅틱은 넣지 않는다** — 상위 계획의 "필요한 곳 햅틱"을 지운다(0.38.2 시안 때 결정과 같다).
3. **음성 파형을 넣는다** — 녹음기에서 소리 크기를 꺼내 입력바에 작은 파형. "애니메이션 제거"면 멈춘 그림.
4. **되돌리기 스낵바는 약 10초**(M3 `SnackbarDuration.Long`) — 4초는 에뮬레이터에서 누르기 전에 사라졌다. 최근 문서의 읽기 권한 반납도 그만큼 늦어진다.
5. **활동 기록 펼침 = 읽을 수 있게 정리 + "원문 보기"** — 모델 응답은 "물은 말·답·쓸 수 있던 도구", 툴 실행은 "결과" 한 줄(성공/실패 + 제목·시각, JSON·ISO·내부 이름 감춤),
   그 아래 "원문 보기" 글자 버튼을 누르면 지금의 기록 원문. AGENTS §4-7 에 "활동 기록의 원문 보기는 예외" 한 줄. 기록 형식(`AuditTrailService`)은 그대로.
6. **오류 기록은 휴대폰 안에만** — 감사 기록은 앱 전용 Room DB, 개발 로그는 logcat(파일 없음), 원격 전송 없음, 구글 백업 꺼짐. 이번 회차에 바꾸지 않는다(사용자 확인용 사실).

## 지금 코드에서 확인한 사실 (2026-10-21)
- `ui/theme/Motion.kt` **없음**(DESIGN.md 가 가리키지만 만들어지지 않았다). 움직임은 입력바 아이콘 Crossfade 200ms·달력 넘김·승인 [취소] 채움·`TwinkleStars`·`OrbPulse` 뿐.
- 화면 전환을 정하지 않아 내비게이션 2.9.8 기본값(페이드 **700ms**)이 쓰인다 — DESIGN "전환 ≤300ms" 의 두 배 이상.
- 승인 [취소] 채움은 `Animatable.animateTo(tween(60s))` — 시스템 애니메이션 배율이 0 이면 즉시 차서 "0초 뒤 자동 취소"로 읽힌다(점검 P2).
- 햅틱 0건. 녹음은 `AudioRecorder` 가 `AudioRecord` 를 직접 읽는다(소리 크기를 꺼낼 수 있다).
- 스플래시 = `OrbPulse`(무한 회전·맥동 3종), 오류 화면만 M3 `Button` 두 개.

- 무한 애니메이션은 상태가 진행 중일 때만(응답 대기·음성 입력·엔진 준비) — 발열에 민감한 앱. 백그라운드에서 돌지 않는다.
- 움직임 수치는 `Motion.kt` 단일 출처 — 화면에서 `tween(…)` 숫자를 직접 쓰지 않는다(예외는 승인 시간 제한처럼 의미가 다른 시간).
- 사용자 표기는 `IsoDateTimeParser`, 색은 토큰, 아이콘은 Phosphor.

## 게이트
전체 게이트(`./gradlew test lintDebug assembleDebug`) + 마일스톤별 Roborazzi 전후 비교 승인 + 움직임은 프레임 띠 승인 + 실기기 체감(스크롤·전환·파형 부드러움 — 에뮬레이터는 PC GPU 대행이라 부드러움 판단 불가, 휴대폰).
