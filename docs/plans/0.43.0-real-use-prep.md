# 0.43.0 실사용 준비

> **상태**: 보류 (2026-11-19 사용자 결정) — 매일 쓸 빌드는 디버그 그대로, 릴리스 전환은 6단계 때. 실사용 준비는 `0.42.10-real-use-start-check.md` 로 줄임.
> 정본 순서: **AGENTS.md > 이 계획서**.
> 전체 흐름(2026-11-18 사용자 승인) 4단계. 2단계(여러 단계 계획)는 0.42.7(둘 다 잡기)·0.42.9(기억 → 알림, 접음)로 끝, 3단계(앱 결함) 몫은 0.42.5 에 합쳐 끝.
> 회차 성격: 새 주제(버전 규칙 가운데 숫자) — 개발이 끝나고 휴대폰에서 매일 쓰기 시작할 수 있게 하는 회차. 기능 추가 없음.

## 지금 상태 (탐색)
- **휴대폰에는 디버그 빌드**가 깔려 있다. 디버그 전용: 디버그 파일로 임베딩·MTP 백엔드 바꾸기(`debug_embed.txt`·`debug_mtp.txt`), 폭주 진단 기록(`diag_runaway.txt`), 벤치마크 수치, 채팅 밖 추론 출력 상한(릴리스는 깨짐 판정만 — 0.42.4).
- **릴리스 빌드는 서명이 없다**(`buildTypes.release` 에 R8 축소·리소스 축소만, `signingConfig` 없음) — 지금은 휴대폰에 깔 수 없다. 마지막 `assembleRelease` 확인은 0.2x 대. R8 keep 규칙은 litertlm 리플렉션용이 있다(CHANGELOG 0.1x).
- 다른 키로 서명한 앱은 덮어 깔리지 않는다 — 지우고 깔면 **앱 데이터와 앱 폴더의 모델 파일(약 3.6GB)이 함께 지워진다**.
- 로그: 채팅 엔진이 시스템 지시·툴 선언·턴 정보를 `Log.d` 로 남긴다(`GemmaModelRunner`). 릴리스에서도 그대로 찍힌다(logcat 은 adb·시스템만 읽음).
- 데이터 초기화(설정, 0.37.1): 대화·할 일·메모·프로필·보관함을 골라 DB 에서 지운다. **안 지우는 것(확인 필요)**: 기기 캘린더에 들어간 시험 일정, 예약돼 있는 알림(AlarmManager), 위젯 표시, 앱 폴더의 디버그 파일·진단 기록.
- 휴대폰 미확인 줄 8개(`device_gate.md` 0.42.x) — 사용자 손이 필요한 것 3(시트 "1/2" 표시, 기억 정리 중 홈 버튼, 백업 복원 뒤 위젯).

## 결정 (승인 때 정할 것)
- **D1 매일 쓸 빌드** —
  (가) **릴리스 빌드를 디버그 키로 서명 (추천)**: 지금 앱 위에 덮어 깔려 데이터·모델이 그대로다. 개발용 기능은 꺼지고 R8 로 작고 빨라진다. 대가: 이 PC 의 디버그 키(`~/.android/debug.keystore`)에 묶인다 — PC 를 바꾸면 다음 설치 때 지우고 다시 깔아야 한다(그 키 파일을 백업해 두면 된다).
  (나) 디버그 빌드 그대로 — 할 일이 없지만 개발용 기능·느린 빌드가 남는다.
  (다) 새 키로 릴리스 서명 — 정식 배포에 맞지만 지금 앱을 지워야 해 모델을 다시 넣어야 한다. 키 파일·비밀번호 관리가 생긴다(저장소에 넣지 않음).
- **D2 릴리스 로그** — **`Log.d`·`Log.v` 를 릴리스에서 R8 로 지운다 (추천)**: 프롬프트·대화 조각이 logcat 에 남지 않게. 경고·오류(`Log.w`·`Log.e`)는 남긴다(문제 생기면 볼 단서).
- **D3 시험 흔적 정리 — 사용자가 실사용 시작 때 직접 (기존 결정)**. 이 회차는 **무엇을 어떻게 지우는지 체크리스트**만 만든다. 초기화가 예약된 알림을 남기면(M3 에서 확인) 그건 결함이라 고친다.
- **D4 휴대폰 확인 몰아서** — 릴리스 덮어 설치 뒤 한 번에(약 20~30분, 미리 묻기). adb 로 되는 것은 Claude 가, 손이 필요한 3개는 사용자가.

## 고정 제약
- 기능·모델 입력 불변 → 회귀 세트·`MEASURED_OVERHEAD` 대상 아님.
- 이 회차 게이트는 `./gradlew test lintDebug assembleDebug` + **`assembleRelease`**.
- 서명 키·비밀번호는 저장소에 넣지 않는다(D1 (다)일 때). 휴대폰에 파일을 남기지 않는다.
- 기존 테스트 단언 불변.

## 마일스톤
### M0 — 버전
- 0.43.0 · 43000, 이 계획서.

### M1 — 릴리스 빌드
- D1 에 따라 `release` 서명 설정, D2 로그 제거 규칙(`proguard-rules.pro`). `assembleRelease` 녹색, APK 크기 기록.
- R8 이 지운 것 때문에 깨질 곳 점검: litertlm 리플렉션(`@Tool`), Hilt·Room·WorkManager·Glance 위젯·kotlinx 직렬화(있으면), JSON 툴 결과.

### M2 — 릴리스 스모크 (에뮬레이터 `my_phone`, CPU)
- 릴리스 APK 로: 시작 → 모델 준비 → 채팅 → 일정 승인 시트(거절) → 메모 저장 시트(거절) → 기억 검색 → 알림 목록 → 보관함 문서 열기 → 위젯 → 설정 화면 전부 열기. 크래시·빈 화면이 있으면 keep 규칙 보강.
- 에뮬레이터 앱 데이터를 쓰는 일(시험 메모 하나 등)은 미리 묻는다.

### M3 — 시험 흔적 정리 체크리스트
- 초기화가 안 지우는 것 확인: 예약된 알림(지운 할 일·알림이 그래도 울리나), 위젯, 기기 캘린더 일정, 앱 폴더 파일. 알림이 남으면 고친다(테스트 포함).
- `docs/checklists/real_use_start.md`: 실사용 시작 순서(백업 → 초기화 대상 → 캘린더 시험 일정 지우기 → 디버그 파일 → 확인).

### M4 — 휴대폰 (D4)
- 릴리스 덮어 설치 → 데이터·모델이 그대로인지 → 스모크(M2 와 같은 순서, 승인 시트는 거절) → 미확인 줄 중 adb 로 되는 것 → 사용자 손 3개 안내.
