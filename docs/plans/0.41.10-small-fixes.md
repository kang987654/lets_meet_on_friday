## 목표
모델 입력(지시·툴 선언·리마인더·툴 결과 문구)을 바꾸지 않는 작은 결함 셋.

1. **저장 물음 판정 누락** — `MemoSaveIntent.SAVE_ASK` 가 `(메모|저장|기억)…(둘까|드릴까|할까)` 만 본다. 모델이 "이 내용을 제가 기억해 두면 좋을까요?"라고
   물으면 물음으로 안 잡혀, 다음 "응"에 앱이 저장 시트를 열지 않는다(0.41.9 회귀 세트 fact 판교 문장에서 발견).
2. **모델 관리 화면이 설치 상태를 모름** — `ModelManagementScreen` 은 다운로드 진행 상태만 보고 "내려받기" 버튼을 늘 그린다.
   설치돼 있어도 누르면 3.6GB 를 처음부터 다시 받는다(0.41.9 휴대폰에서 발견 — 설정은 "준비됨").
3. **채팅 점프가 목표보다 뒤(최신 쪽)에 도착** — 서랍 → 11월 6일 대화 → 채팅에서 보기가 그다음 대화의 긴 답에 내려앉는다.
   `jumpThreshold` 를 뺀 빌드도 같은 자리라 0.41.9 이전부터 있던 어긋남(0.41.9 휴대폰).

## 결정
- 모델 관리 (가): 설치돼 있으면 "설치됨" 표시 + "다시 받기" 버튼, 누르면 확인 창(사용자 결정 2026-11-10). 진행 카드·직접 URL 섹션은 그대로.
- 실기기 확인 없이 완료까지(사용자 지시) — 휴대폰 확인은 `device_gate.md` 에 남긴다.

## 고정 제약
- 기존 테스트 단언 불변(바꿔야 하면 먼저 보이고 확인). E2E 계약 표면 불변.
- 모델 입력 바이트 불변. 단 M1 은 모델 행동 가드라 회귀 세트를 다시 돌린다(AGENTS §2-⑤) — 기준값 갱신은 결과를 보인 뒤.

## 마일스톤

### M0 — 계획서·버전
- 이 계획서, `versionName = "0.41.10"`, `versionCode = 41010`(AGENTS §1 버전 규칙).

### M1 — 저장 물음 판정
- `SAVE_ASK` 에 "(해) 두면 좋을까 / 하면 좋을까" 계열을 넣는다. 단위 테스트: 새 문형 잡힘, "저장하면 안 돼요" 같은 비물음은 안 잡힘.
- 회귀 세트 흉내(`scratch/lab/regression/run.py` 의 `SAVE_ASK`)를 같이 고치고 세트를 다시 돌린다. 판교 문장이 통과로 바뀌면 기준값 갱신은 사용자 확인 뒤.

### M2 — 모델 관리 설치 상태 (가)
- 설치 여부를 런타임 상태(`ModelLoadState` 의 파일 확인)에서 읽어 화면에 넘긴다(기본 인자로 단독 compose 유지).
- 설치됨: 상태 문구 + "다시 받기"(확인 창 → 확인 시 지금과 같은 다운로드). 미설치: 지금 그대로.
- 테스트: 설치됨이면 확인 창을 거쳐야 다운로드가 시작되는지(Compose). 화면 기준 이미지는 기본 상태가 그대로면 불변.

### M3 — 채팅 점프
- 코드 읽기로 좁힌 원인 후보: 정렬을 마친 뒤 아래쪽(더 최신) 자리표시자가 실제 높이로 커지면 LazyColumn 이 바닥의 첫 보이는 항목을 기준으로
  위치를 지켜 목표가 화면 위로 밀려난다 — 목표 하나만 로드되길 기다리는 지금의 대기로는 못 막는다. 인덱스 계산(DB 개수)은 페이지 쿼리와 같은 기준이라 맞다.
- 처방: 정렬 전에 목표와 그 아래 화면을 채울 이웃까지 로드되기를 기다리고, `scrollToItem` 뒤 한 프레임을 기다린 다음 정렬한다. 대기 시간 상한은 둔다.
- 테스트: 자리표시자가 정렬 뒤 커지는 상황을 흉내 낸 Compose 테스트에서 목표 윗변이 화면 안에 남는지.
- 실기기 확인은 `device_gate.md`(같은 11월 6일 대화).
