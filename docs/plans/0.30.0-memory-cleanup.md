# 수동 기억 정리 1차 — 주간 회고 + 기억 중복 병합 (0.30.0)

## Context

expand.md A5 는 "충전 중 야간 배치"였지만, 그 형태는 AGENTS §2-⑥(백그라운드 모델 로드 금지 — onStop 이 3.6GB 를
즉시 해제)과 정면으로 충돌하고 자동 요약 파이프라인과도 경합한다. 사용자 결정(2026-10-01): **설정 탭의 수동
"기억 정리" 버튼**으로 앱 사용 중(엔진 Ready)에 실행한다. 범위는 2회차로 나눠 **1차 = ① 주간 회고 + ② 기억 중복
병합(미리보기 후 적용)**, 2차 = ③ 에피소드 중복 통합. ④ 프로필 후보 백필은 넣지 않는다(0.24.0 부터 요약마다 자동 수행).
"지금 대화 정리"는 하지 않는다.

**현황 (탐색 확정)**:
- 추론 직렬화: `llmDispatcher(limitedParallelism(1))` + 러너 뮤텍스 — 동시에 불러도 모델 상태는 안 깨지고 줄을 선다.
- 자동 요약: `EpisodeSummarizeScheduler`(@Singleton) — `drainMutex` 로 드레인·catch-up 직렬화, 턴 종료·Ready 편승, 발열 시
  `shouldDeferBackgroundInference()` 로 미룸, oneShot 은 `oneShot = true`(ADR-010·014).
- 지식: `KnowledgeNote(id, content, tags, createdAt, updatedAt, source = manual|auto)`, `KnowledgeRepository.getNotes/save/delete`.
- 에피소드: `EpisodeRepository.getByStatus(SUMMARIZED)` — 제목·태그·요약 보유.
- 유사도: `BigramMatcher`(domain/search, 0.25.0 — 한국어 바이그램 점수).

## 사용자 확정 결정 (2026-10-01)
1. 설정 탭 수동 버튼(야간 배치 폐기). 진행률·취소·중단 후 재실행 시 이어서(멱등)·발열 게이트·자동 요약과의 가드.
2. 1차 범위 = 주간 회고 + 기억 중복 병합. 에피소드 통합은 2차. 프로필 백필·"지금 대화 정리" 없음.

## 승인 결정 (2026-10-01 — 전부 제안대로)
- **D1 회고 저장 위치**: 지식 노트(`source=auto`, 태그 `주간 회고`·주차) — `search_memory` 로 회수되고 기억 화면에서 삭제
  가능(확정). 같은 주차를 다시 정리하면 그 주차 회고를 **교체**. 정리 결과 화면에도 본문 표시.
- **D2 병합 대상**: 수동·자동 노트 모두 후보(확정). 병합 결과는 묶음에 수동이 하나라도 있으면 `manual`, 아니면 `auto`.
- **D3 적용 방식**: 미리보기 목록(묶음마다 "원문 N개 → 합친 문장")에서 **항목별 체크 후 일괄 적용**(확정). 되돌리기는 이번 회차 없음
  — 대신 적용 전 확인이 필수이고 삭제는 감사 로그에 원문까지 남긴다.

## 고정 제약
- 모델은 **포그라운드·Ready 일 때만**. 화면을 떠나도 정리는 @Singleton 범위에서 계속, **앱 onStop(엔진 해제) 시 취소** →
  다음 실행에서 처음부터(회고는 주차 키로 교체, 병합은 후보를 새로 계산 — 멱등).
- **자동 요약과의 가드**: 정리 시작 전 `EpisodeSummarizeScheduler` 드레인이 진행 중이면 끝날 때까지 대기(공용
  `BackgroundInferenceGate` 로 drainMutex 와 같은 잠금을 쓴다). 정리 중 드레인은 정리 종료 후로 미룬다.
- 발열 경고 온도면 시작 거부("기기가 뜨거워 잠시 후에 다시 시도해 주세요"), 진행 중 도달하면 현재 단계 후 중단.
- oneShot 전부 `oneShot = true`, 입력은 예산(1,700) 안 — 회고 입력이 넘치면 최신 에피소드부터 자른다.
- 채팅 시스템 지시·툴 선언 무변경 → `MEASURED_OVERHEAD` 무관. 단 **oneShot 프롬프트도 모델 입력이므로 M0 실측 선행**(§2-⑤ 취지).
- 실측 데이터는 **합성 데이터만** 커밋 — 실기기 DB(kosmos_db) 파생물은 커밋 금지.

## M0 — 실험실 실측 (exp42)
- 합성 지식 노트 30개(중복 묶음 6개 — 표현만 다른 같은 사실, 숫자가 다른 비슷한 사실 같은 함정 포함) + 합성 에피소드 7일치.
- (a) 후보 임계: `BigramMatcher` 점수 임계별 묶음 재현율/정밀도 → 임계 결정.
- (b) 병합 판정 프롬프트: "같은 사실인가(예/아니오) + 합친 한 문장" — **숫자·고유명사 보존**, 다른 사실을 합치는 오병합 0 이 게이트.
- (c) 회고 프롬프트: 3~5문장, 사실만(지어내지 않음), 한국어. 문구 원문을 이 계획서에 확정해 적는다.

## M1 — 도메인
- `PlanMemoryMergeUseCase`: 노트 → 바이그램 후보 묶음 → 묶음마다 oneShot 판정 → `MergeProposal(sourceIds, mergedContent, tags, source)`.
- `ApplyMemoryMergeUseCase`: 선택된 제안을 적용(합친 노트 저장 → 원본 삭제, 트랜잭션 성격 — 저장 실패 시 삭제 안 함), 감사 로그.
- `GenerateWeeklyReviewUseCase`: 최근 7일 SUMMARIZED 에피소드 → oneShot → 주차 키 노트 교체 저장.
- 테스트: 후보 묶음(임계 경계), 판정 "아니오"면 제안 없음, 숫자 다른 노트는 묶이지 않음(M0 함정 재현), 적용 시 저장 실패면 원본 보존,
  회고 교체(같은 주차 1개 유지), 에피소드 0개면 모델 호출 0.

## M2 — 실행기와 가드
- `MemoryCleanupRunner`(@Singleton): 상태 `Idle | Running(step, done, total) | Review(proposals, review) | Done(summary) | Blocked(reason)`.
  단계 = 회고 → 병합 계획. 취소, onStop 취소, 발열 게이트, `BackgroundInferenceGate`.
- `EpisodeSummarizeScheduler` 드레인을 같은 게이트로 감싼다(동작 불변 — 기존 테스트가 회귀 감시).
- 테스트: 드레인 중 시작 → 대기 후 실행, 발열 시 Blocked, 취소 시 부분 적용 없음, 재실행 멱등.

## M3 — UI

  + "선택한 N개 적용". 결과 Snackbar(§ 0.27.1 통일). 색 토큰·glass.
