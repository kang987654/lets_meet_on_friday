# 0.41.3 — 기억·지난 대화 검색에 뜻 검색 더하기 (EmbeddingGemma 2, 선택 설치)

## Context
0.41.2 에서 문서 보관함은 EmbeddingGemma 2(선택 설치)로 바꿔 말한 질문을 찾게 됐다. 기억 검색은 아직 어휘만 쓴다.
- `search_memory`(`SearchMemoryToolExecutor`): 낱말별 LIKE(메모 내용·태그, 지난 대화 제목·요약·태그) → 없으면 최근 500건 바이그램 스캔(겹침 0.5 이상) → 그래도 없으면 태그 목록을 주고 다시 부르게 한다. 바이그램 점수로 상위 3.
- 서랍 "지난 대화" 검색(`DrawerViewModel.search`): **질문 전체 문자열**로 LIKE·태그 → 없으면 500건 바이그램 스캔.
- 옛 벡터 경로(ADR-013·026)는 계약만 남아 있다 — `domain/memory/TextEmbedder`(항상 실패하는 `DisabledTextEmbedder`), `knowledge_note.embedding` BLOB(늘 null),
  `searchByVector`(호출자 없음), 이를 고정하는 테스트 3개.

**중요한 전제 — 이미 잘 되는 부분이 있다.** ADR-032(쓰는 시점 상위 개념·동의어 태그)로 `SemanticRecallBenchmarkTest` 동의어·상위 개념 질문이 18/40 → **40/40** 이 됐고,
그때 "한국어 임베더(C3)는 필요 없다"고 기각했다. 그래서 이 회차는 **임베딩이 더해 주는 곳을 먼저 재고, 이득이 있는 곳에만 붙인다.** 이득 후보:
1. **교차 언어** — 한국어로 저장한 메모를 영어로 묻기(그 반대). 지금은 README "알려진 한계". EmbeddingGemma 2 는 다국어 모델이다.
2. **태그가 약한 기억** — 태그 보강은 요약·자동 추출 경로에만 있다(직접 "기억해줘"는 모델이 붙인 태그뿐, 0.41 이전 기억은 보강 전 태그).
3. **바꿔 말한 질문의 어휘 밖 표현** — 태그가 덮지 못한 말("숙소 와이파이 비번" ↔ "호텔 인터넷 암호").
4. **서랍 검색** — 질문 통째 LIKE 라 두 낱말 이상이면 1단계가 거의 비고 바로 스캔으로 간다.
반대로 **위험**: 어휘 검색은 "못 찾음"을 낼 수 있지만 dense 는 늘 뭔가를 1위로 낸다 — 기억에 없는 것을 물으면 무관한 메모가 붙어 환각 재료가 된다(ADR-013 의 원래 실패).
exp78 에서 문서는 코사인 하한으로 관련·무관을 가를 수 없었다. 기억은 "없다"가 정답인 질문이 흔하므로 이것이 이 회차의 핵심 측정이다.

## 고정 제약
- **임베딩은 0.41.2 의 선택 설치를 그대로 쓴다** — 모델이 없으면 지금 동작과 **바이트 단위로 같다**(툴 결과 문구·순위·서랍 결과). 새 다운로드 없음.
- **꺼짐 동작 불변** — 기억 검색은 상시 툴이라 토글이 없다. 모델이 있을 때만 바뀐다. 선언·트리거·시스템 지시는 건드리지 않는 것이 목표(바꾸면 AGENTS §2-⑤ 실측·회귀 세트).
- **결과 문구 불변 우선** — `search_memory` 결과 형식(줄 형식·안내 줄·`RecallConflict`·`HIT_TAIL`)은 그대로 두고 **후보와 순위만** 바꾼다. 문구를 바꿔야 하면 실측 선행.
- **백그라운드 모델 금지**(AGENTS §2-⑥) — 벡터는 앱이 화면에 있을 때만. 에피소드 요약은 이미 "엔진 Ready 편승"이라 그 자리에서 임베딩해도 전경이지만, 임베딩 엔진은 별도
  엔진(GPU, 약 1~2.5초 로드)이라 요약 묶음 뒤 한 번에 올리고 내리는 방식을 M0·M2 에서 정한다. `LibraryEmbedder` 의 채팅 중 멈춤·15초 뒤 재개를 따른다.
- 기존 테스트 단언 불변. 옛 벡터 경로를 지우게 되면 그 테스트 3개(`KnowledgeEmbeddingBlobTest`·`KnowledgeEmbeddingMigrationTest`·`MemoryPipelineIntegrationTest` 의 embedder mock)는
  대상·이유를 먼저 보여 드리고 확인 후에만(AGENTS §2-② 예외).
- 모델 회귀 세트는 모델 입력이 바뀔 때만 의무 — 순위만 바뀌어도 `search_memory` 가 들어간 회귀 케이스(save·fact·overlap·newval·repeat)는 다시 돈다(결과가 모델 입력이므로).

## 결정 (사용자, 2026-11-05)
- **Q2 = (a)** 처음 버튼 한 번 + 이후 새 메모·요약된 대화는 저장 직후 자동.
- **Q3 = C 결합 (M0 뒤 확정, 2026-11-05)** — 아래 "M0 결과".
- **Q4 = (a) 지운다** — 테스트 3개는 지우기 직전에 대상·이유를 다시 보여 드리고 확인.
- **Q1 = (a) 둘 다** — `search_memory` 툴과 서랍 검색. 서랍은 낱말 분리(모델 없어도 이득) + 같은 벡터.
- **영어 확인 추가(사용자 제안)** — 임베더가 다국어라 영어 모드에서도 이득일 것으로 보이지만 0.41.2 실측은 한국어뿐이다. 바이그램은 영어 낱말에 약해(철자 조각만 겹친다) 영어에서 dense 몫이 더 클 수 있다 — M0 에 영어 메모·영어 질문 세트를 넣어 같은 지표로 잰다. 좋으면 README 한계(교차 언어·영어) 문구를 근거와 함께 고친다.

## 계획 단계에서 정할 것 (사용자 확인)
- **Q1. 범위** — (a) `search_memory` 툴 + 서랍 검색 둘 다(추천 — 같은 벡터를 쓴다), (b) 툴만, (c) 서랍만.
- **Q2. 벡터 만들기** — 기억은 문서와 달리 조금씩 계속 생긴다.
  - (a) **추천: 모델을 받은 직후 "기억 뜻 검색 준비" 한 번(버튼 — 문서 보관함 버튼과 같은 자리 또는 설정의 뜻 검색 모델 항목) + 이후 새 메모·요약된 대화는 저장 직후 자동**
    (사용자가 "기억해줘"를 했거나 요약이 전경에서 끝난 순간이라 사용자가 시작한 일의 연장 — 0.41.2 "등록 직후 그 문서만"과 같은 논리).
  - (b) 전부 버튼으로만. (c) 처음부터 자동(버튼 없음) — 기억 수가 적어(수백 건) 일괄 준비도 수십 초.
- **Q3. "없다"를 지키는 방식** — M0 결과로 정하되 후보를 미리 드린다: (a) dense 는 **어휘 후보의 재순위만**(새 후보를 끌어오지 않음 — 안전, 교차 언어 이득 없음),
  (b) 어휘 후보가 없을 때만 dense 상위를 **코사인 하한 이상**일 때 더함(교차 언어·바꿔 말함 이득, 하한이 가를 수 있는지가 관건), (c) 결합 점수로 전부(문서와 같음 — "없다" 위험 큼).
- **Q4. 옛 벡터 경로** — (a) **추천: 지운다**(`domain/memory/TextEmbedder`·`DisabledTextEmbedder`·`searchByVector`·`KnowledgeNote.embedding`·BLOB 열 — 열 제거는 Room 마이그레이션,
  고정 테스트 3개는 확인 후 정리). 새 벡터는 `library_vector` 처럼 모델 id 를 단 별도 표(`memory_vector`). (b) 남겨 둔다(계약만, 해 없음 — 헷갈림은 남음).

## 마일스톤

### M0 — 실측 (코드 수정 0, `scratch/lab/exp80_*`)
- 자료: `SemanticRecallBenchmarkTest` 40문항(표면·동의어·상위 개념, 원래 태그 / 보강 태그 두 판) + exp37 16문항 + **새로**: 교차 언어 10(한국어 메모 ↔ 영어 질문, 반대 5), **영어 메모·영어 질문 20**(표면·바꿔 말함·답 없음 — 영어 모드 사용자),
  태그가 덮지 못한 바꿔 말함 10, **기억에 답이 없는 질문 15**(비슷한 주제지만 저장 안 된 것 — "엄마 생일" 이 있고 "아빠 생일"을 묻기 등). 메모 수는 실기기 규모(수백) 흉내로 잡음 메모를 섞는다.
- 비교: 지금 앱 경로(LIKE → 스캔, 앱과 같은 판정식 이식) / dense 만 / Q3 (a)(b)(c). 지표: @1·@3, **답 없는 질문의 오첨부율**(상위 3 안에 무관 기억이 붙는 비율), 교차 언어 적중.
- 코사인 분포: 관련 최저 vs 무관 최고 — (b) 의 하한이 가를 수 있는지. 문서(exp78)와 달리 기억은 짧아 분포가 다를 수 있다.
- 입력 형식: 모델 카드 질의 `task: search result | query:` / 문서 `title: {태그} | text: {내용}`(메모)·`title: {제목} | text: {요약}`(대화) — 태그를 넣는 판과 빼는 판.
- 가능하면 툴 끝까지(모델이 실제로 부른 `keyword` 로) — 모델 검색어는 짧은 명사라 원문 질문과 dense 성질이 다르다(exp78b 교훈).
- **결과를 보여 드리고 Q3 을 확정한다. 이득이 없으면 이 회차는 서랍 검색 낱말 분리와 옛 경로 정리만 하고 닫는다(그것도 결정 사항).**

#### M0 결과 (2026-11-05, PC — `exp80_memory_dense.py`·`exp80b_memory_e2e.py`)
- **Q3 = C 결합(사용자 확정)** — dense + 0.05 × sparse/최고점(0.41.2 문서와 같은 식), 문서 입력은 `title: {태그} | text: {내용}`(태그 넣은 판이 뺀 판보다 나음).
- 1단계(검색만, 메모 120건, 보강 태그 — @1·@3): 교차 언어 L 0·0 → **C 1·15/15**, 영어 바꿔 말함 L 7·9 → **C 10·19/20**, 순수 상위 개념 L 29·29 → C 26·30/30,
  원판 태그(보강 전)의 상위 개념 L 2·4 → C 10·19/30. 답 없는 질문 오첨부(상위 3 비지 않음) 한국어 L 13/15 → C 15/15, 영어 3/6 → 6/6.
  코사인 하한으로 가를 수 없음(답 없음 최고 0.77 > 정답 하위 0.61) → B(하한) 기각, A(재순위만)는 새 후보가 없어 교차 언어 이득 0 → 기각.
- 2단계(모델 끝까지, 46문항 × L/C, 답 원문 사람 판정): 교차 언어 정답 L 7 → **C 9**/11, 영어 바꿔 말함 L 6 → **C 8**/10,
  **답 없음 지어냄 L 2 = C 2**(같은 두 건 — "부모님 집 와이파이"에 본인 집 값, "아내 신발 사이즈"에 본인 값: 검색이 아니라 모델이 비슷한 메모를 끌어다 쓰는 기존 약점), 무관 주제·영어 0 = 0.
  C 에서만 생긴 실수 1(회사 와이파이 비번 — 영어 메모가 3위 밖이라 와이파이 이름을 비번으로 답함, L 은 "없다"로 정직).
- 결론: 오첨부 증가가 실제 답의 지어내기로 이어지지 않았다 — 모델이 무관한 메모를 거른다. 이득(교차 언어·영어·태그 약한 메모)은 답에서도 확인.
