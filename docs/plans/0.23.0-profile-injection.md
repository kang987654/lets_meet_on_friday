# C′1 프로필 상시 주입 + 드로어 고정 카드 — E-Phase 2 첫 회차 (0.23.0)

## Context

"나를 아는 비서"의 첫 조각 — 이름·호칭·말투 같은 항상-관련 기억을 시스템 지시에 상시
주입해 답변의 톤을 바꾼다(Track C′ 3층 기억 모델의 Profile 층, AC6 정식 배선). 드로어
최상단 프로필 고정 카드(시안 A′-2 마지막 잔여)가 편집 UI. 사용자 확정 결정 2건(2026-08-28):
① 예산 폴백 = **히스토리 동적 차감**(few-shot 제거 불가 시) ② **자유 키-값** 형식.

**현황 (탐색 확정)**: ProfileRepository 는 완전 사문화(호출 0곳·테스트 0건·실기기 데이터
0행) — v8 에서 DROP/CREATE 재설계가 안전. 시스템 지시는 Conversation 생성 시 1회 프리필
되고, `GemmaModelRunner:532` 가 문자열 동등 비교로 변경 시 자동 재생성 — **런타임 무변경으로
편집이 다음 턴에 반영**된다. 드로어 카드 자리는 AppDrawerContent KDoc 이 이미 예약
("검색바 위").

## 토큰 예산 (최상위 제약)
여유 19토큰(실측 1,381 / 예약 1,400), `1400+300=1700` 바닥 맞물림 — 예약 상향 불가.
**재원 후보 = few-shot 104토큰 제거**: 도입 진단(ADR-010)은 ADR-017 이 철회했고(진짜 원인은
지침 거리 → 턴 리마인더가 해결, 6/6), few-shot 의 예시 숫자가 조회 턴에 새는 실해 기록까지
있다("8282 에코"). 제거 가능성은 재실측된 적 없음 — M0 이 판정한다.
- **성공 경로**: few-shot 제거 → 기반 실측 ~1,277 + 프로필 상한 100 + 래퍼 ≈ 1,387 ≤ 1,400.
  예산 상수 전부 무변경, `PROFILE_MAX_TOKENS = 100`.
- **폴백 경로**(사용자 승인): 프로필 있을 때만 히스토리에서 동적 차감
  (`historyBudget -= profileTokens`, 300→최저 ~220), 상한 80. 빈 프로필이면 손해 0.

## M1 — 스키마 v8 + 저장소 재설계

- `ProfileEntity` → 키-값 행 구조로 교체: `profile(key TEXT PK, value TEXT NOT NULL,
  source TEXT NOT NULL, updatedAt INTEGER NOT NULL)` — `source` 는 "manual"(이번 회차),
  C′2 자동 추출이 "auto" 를 쓴다(관리 장치 스펙 expand.md:84 — v9 재마이그레이션 회피).
- `MIGRATION_7_8`: `DROP TABLE profile` + CREATE — 실기기 포함 데이터 0행(호출 0곳)이라
  무손실 [WHY]. 8.json, version=8, sqlite_master 대조 테스트(ReminderMigrationTest 패턴).
- `ProfileRepository` 재설계: `observeEntries(): Flow<List<ProfileEntry>>`,
  `getEntries(): AppResult<List<ProfileEntry>>`(주입용 suspend), `upsert(key, value)`,
  `delete(key)`. 구 `UserProfile`/`getProfile`/`saveProfile` 은 **삭제**(사용처 0 —
  style↔responseStyle 오매핑·null 미방출 결함째 정리). 도메인 모델 `ProfileEntry`.
- 백업: DB 통째 방식이라 자동 포함. **알려진 한계 기록**: v8 백업을 v7 앱에 복원하면
  다운그레이드 파괴 삭제(manifest 에 schemaVersion 없음 — 기존 조건, 이번 범위 밖).

## M2 — 주입 배선

- 신규 top-level 순수 함수 `renderProfileBlock(entries): String` (assistant/context) —
  `[User Profile]` + `- 키: 값` 줄, **키 사전순 정렬**(바이트-안정 [WHY]), 빈 목록이면 "".
- `ContextBuilder`: 생성자에 ProfileRepository, `build()` 에서 매 턴 로드(responseStyle
  전례 — try/catch 폴백 ""), `Context.profileText: String = ""`(기본값 — 기존 생성부 호환).
  폴백 경로일 때만: `applyTokenSlidingWindow` 에 profileTokens 차감.
- `PromptAssembler`: `buildProfileBlock` 을 **[System] 과 [System Data] 사이**에 삽입 —
  [System Data]→[Tool Usage Guidelines] 의 "above" 포인터와 날짜 블록 위치(ADR-010)를
  보존하는 자리. 빈 프로필 = 블록 생략(비용 0).
- few-shot 제거(M0 성공 시): `GemmaModelRunner.fewShotToolExample`·`initialMessages` 배선
  제거, [WHY] 는 "ADR-017 철회 + exp35 재실측"으로 교체. `Constants`/`ContextBuilder` 의
  낡은 합계 주석 갱신.
- `Constants.PROFILE_MAX_TOKENS = 100`(성공 경로; 폴백이면 80).
  `TokenBudgetInvariantTest`: `MEASURED_OVERHEAD` 를 exp35 실측으로 갱신 + **신규 단언**
  `PREFILL_OVERHEAD >= MEASURED_OVERHEAD + PROFILE_MAX_TOKENS`(추가는 허용).
- `PromptFixtureExportTest`: 빈 프로필이 정본 픽스처(블록 부재 단언) + profileText 지정 시
  블록 존재·정렬 단언 추가. `renderProfileBlockTest`(정렬·바이트 안정·빈 목록·특수문자).
- ContextBuilderTest 등 생성부 갱신.
