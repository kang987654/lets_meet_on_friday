## 현재 여건 (계획에 영향을 주는 것)
- **에뮬레이터로는 채팅 화면을 볼 수 없다** — 2026-10-14 엔진 초기화가 15분 넘게 끝나지 않았다(스플래시에서 멈춤). 모델이 필요 없는 화면 확인도
  스플래시를 못 지나 막힌다. → 화면 캡처는 **Robolectric 렌더링**(0.36.2·0.37.1 에서 할 일 행·초기화 대화상자를 라이트·다크로 찍어 검증한 방식,
  `@GraphicsMode(NATIVE)` + `captureToImage`)과 **실기기**로 한다.
- **Robolectric 렌더링 ≠ Roborazzi** — 렌더링은 PNG 를 찍을 뿐이고, Roborazzi 는 그 위에 기준 이미지 기록·비교·차이 이미지·실패 판정을 얹는다.
  현재 모습 한 번 보기(0.38.0)는 렌더링으로, 회귀 감시(0.38.1~)는 Roborazzi 로.
- **둘 다 못 보는 것** — 시스템 바·인셋(Robolectric 은 0), 키보드, 실제 기기 글꼴 차이 → 실기기 게이트.
- **실기기 규칙**(0.36.0~ 사용자 결정): 앱 밖에 흔적 없음(`exec-out` 캡처·덤프), 기존 데이터 변경 금지, 다른 앱·알림 읽지 않음(앱이 맨 앞일 때만),
  권한·시스템 설정은 사용자가 탭, PC 사본은 분석 후 삭제. 캡처 전에 0.37.1 데이터 초기화로 개발 데이터를 지우면 화면에 개인 기록이 남지 않는다.
- **프롬프트 여유** — `MEASURED_OVERHEAD` 1,250 + 프로필 100 ≤ 예약 1,400, 여유 50(0.37.0 이후 그대로). 말투를 시스템 지시로 바꾸면 이 안에서.
- **기억 충돌은 데이터 쪽이 먼저 고쳐졌다** — 0.37.2 가 메모와 다른 값을 적은 요약을 압축한다. 0.38.2 의 기억 답 카드(근거 표시)는 보완이다.

## 고정 제약
- **기준은 사람이, 실행은 AI 가** — 디자인 스킬·생성 도구는 후보와 진단만 낸다. 매 단계 선택은 사용자.
- **토큰만 사용(§4-6)** — 스킬이 색을 직접 쓰라고 해도 토큰이 우선. 새 토큰은 `Color.kt`·`Type.kt`·(신설) 모양·간격·움직임 토큰에만.
- **E2E 계약 불변(§2-②)** — `"Attach"`·`"Send"`(contentDescription), `"Document Attached"`, `ChatScreen` 신규 파라미터 기본값.
- **프롬프트 표면(§2-⑤)** — 브리핑·비서 답 말투는 모델 입력이다. 바꾸면 실험실 실측 선행, 화면 문구 회차와 분리(0.38.4).
- **한 회차에 한 층** — 기반(토큰·바) → 구조 → 디테일 → 말투 순. 기능 변경은 0.38.2 M2(리마인더 수정)만, 별도 마일스톤·테스트로.
- **디자인 스킬은 디자인 회차에만, 프로젝트 범위로** 켠다. 전부 제3자 제작이고 이 환경에 아직 설치돼 있지 않다 — 설치 전 SKILL.md·스크립트를 읽고
  사용자 확인 후 설치한다.
