# 문서 뷰어 3차 — hwp(한글 5.0) 읽기 모드 확인 실험 (0.36.0)

## Context

국내 문서는 아직 hwp(한글 97/5.0 바이너리)가 가장 흔하다. hwpx·docx(0.35.0)와 달리 hwp 는 **OLE 복합 파일(CFB) 안의 zlib 압축 바이너리 레코드**라
XML 파서로 읽을 수 없다. 형식 명세("한글 문서 파일 형식 5.0")는 한컴이 공개했지만 파서가 크고, 기존 자바 라이브러리가 안드로이드에서 그대로
도는지·용량이 얼마인지 **확인되지 않았다**. 사용자 결정(2026-10-02): **확인 실험부터** 하고 결과로 구현 여부를 정한다.

**목표 범위(구현 시)**: 0.35.0 읽기 모드와 같은 수준 — 문단 텍스트·표·(가능하면) 이미지. 서식은 굵게 정도까지, 쪽·글꼴 배치는 하지 않는다.

**지원하지 않는 것(구현해도)**: 배포용 문서(`ViewText` 암호화 스트림), 암호 문서, hwp 3.0 이하 — 안내 문구로 처리.

## 승인 결정 (2026-10-02 — 전부 제안대로)
- **D1 후보 두 가지를 M0 에서 비교**:
  - (a) **기존 자바 라이브러리**(hwplib 등): 라이선스·전이 의존성(Apache POI 를 끌어오는지)·안드로이드 호환(`java.awt`·`javax.xml.stream` 등
    안드로이드에 없는 API 사용 여부)·APK 증가량·텍스트 추출 정확도.
  - (b) **최소 자체 파서**: CFB 읽기(MS-CFB: 헤더·FAT·디렉터리·미니 스트림) + `FileHeader`(압축·암호·배포용 플래그) + `BodyText/SectionN`
    raw deflate(`Inflater(nowrap = true)`) + 레코드 헤더(태그 10비트·레벨 10비트·크기 12비트, 0xFFF 이면 확장 4바이트) + `HWPTAG_PARA_TEXT`
    UTF-16LE(제어 문자: 문자형 1칸, 인라인·확장 제어 8칸 건너뜀) + 표 컨트롤(`tbl `)의 셀 문단 묶음. 이미지(`BinData`)는 2단계.
- **D2 판정 게이트 (M0)**: 사용자 실파일 10개(공문서·보고서·표 많은 문서 섞어서, **커밋하지 않음**)에서
  - 본문 텍스트 누락 없이 추출 ≥ 9/10(한글 오피스 "텍스트로 저장" 결과와 비교), 표 셀 순서 유지 ≥ 8/10
  - APK 증가 ≤ 1MB, 10쪽 문서 첫 화면 ≤ 1초(에뮬레이터)
  - 둘 다 통과하면 작은 쪽, (a)가 실패 요인(호환·용량)이면 (b). **둘 다 미달이면 보류** — CHANGELOG 에 사유·수치를 남기고 0.35.0 의 "hwp 첨부 거부
    안내"를 "PC 에서 hwpx 로 저장해 열어 주세요"로 다듬는 것만 한다.

## 고정 제약
- 0.34.0·0.35.0 의 뷰어 제약(모델·DB 미사용, IO 파싱, 첫 화면 우선, 크기 상한) 그대로. 결과는 0.35.0 `FlowDocument` 로 내서 화면·채팅 보내기를
  재사용한다(새 화면 없음).
- 압축 해제·레코드 크기에 상한 — 손상·악성 파일에서 무한 루프·메모리 폭주가 없어야 한다(레코드 크기 > 남은 바이트면 그 섹션 중단).
- 실파일은 커밋 금지. 테스트 픽스처는 **테스트 코드가 조립**한다 — 최소 CFB 작성기(테스트 전용)로 `FileHeader` + 섹션 1개를 만들어
  레코드 파싱·압축·제어 문자·표·배포용 플래그 감지를 검증한다.
