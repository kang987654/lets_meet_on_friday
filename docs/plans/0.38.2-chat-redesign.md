# 0.38.2 — 채팅 재설계 (결과 카드·칩·시트, 스키마 ①②)

## 목표
비서 답을 **카드**(문장 + 결과 행)로 바꾸고, 결과 행이 대상의 **현재 상태**(울리기 전·미룸·취소함·울렸음)를 보여 주며, 누르면 시트에서 고친다.
승인은 채팅 안 떠 있는 카드를 없애고 **공통 승인 시트 하나**로. 상단에 요약 타일, 마지막 답 아래 상황 칩.

## 지금 코드에서 확인한 사실 (2026-10-16 탐색)
- 툴 실행기는 만든 대상의 id 를 버린다 — `AddReminderToolExecutor`(TaskItem id 로 알람만 예약), `AddScheduleToolExecutor`(task id 반환값 무시, 기기 캘린더 이벤트 id 없음),
  `AddMemoryToolExecutor`(note id 무시). 결과는 `ToolResultJson` 문자열(`meta` 는 모델에 보내기 전에 떼어 냄, `BaseAgent.kt:206`).
- `BaseAgent.executeToolLoop` 는 도구 이름·결과를 루프 밖으로 들고 나오지 않고, `AssistantMessageWriter.save` 는 글·검색 여부·회수 칩 id 만 저장한다.
  `ChatViewModel.handleAgentResult` 는 낙관적 메시지를 **다른 UUID** 로 붙인다(DB 행 id 와 다름).
- DB 는 9판(`KosmosDatabase.SCHEMA_VERSION`), 마이그레이션은 `KosmosMigrations` + 손 DDL 비교 테스트(`ReminderMigrationTest` 등, MigrationTestHelper 아님).
- 승인 UI 는 `ApprovalRequest.calendarDraft != null` 이면 떠 있는 `CalendarDraftCard`, 아니면 `ApprovalSheet`. 승인 E2E(`ToolApprovalE2ETest`)는 ViewModel 을 직접 부르고
  버튼 글자를 셀렉터로 쓰지 않는다 → 시트 통일로 단언이 깨지지 않는다.
- 기억 답의 근거(어느 메모·충돌 값)는 모델 입력에만 있고 화면에는 `recallEpisodeIds`(회수 칩)만 온다.

## 설계
### 스키마 ① 메시지 → 결과 (9 → 10)
`conversation` 에 nullable 칸 3개: `resultKind TEXT`(REMINDER / SCHEDULE / MEMORY_NOTE / MEMORY_RECALL), `resultRef TEXT`(대상 id — task id·note id),
`resultMeta TEXT`(작은 JSON — 기억 답의 근거: 근거 메모 id·날짜, 충돌 건수·다른 값). 옛 메시지는 셋 다 NULL → 글만 보인다. 본문 파싱 없음.
### 스키마 ② 할 일 취소 (같은 10판)
`task_item.cancelledAt INTEGER`(nullable). 취소 = 알람 취소 + `cancelledAt` 기록(행 유지 — 카드가 "취소함"을 보일 근거). 할 일 탭에서는 숨긴다(결정 1).
### 결과가 메시지까지 오는 길
실행기 → `ToolResultJson` 의 `meta.ref`(kind·id·근거) → `BaseAgent` 가 **마지막 성공 결과**를 들고 나와 `AssistantMessageWriter.save(result=…)` 와 `AgentResult.Text.result` 로.
모델 입력은 그대로(`meta` 는 지금처럼 떼어 냄) — **프롬프트 표면 무변경**, `MEASURED_OVERHEAD` 무관.
### 화면
- 비서 카드(`surface`+`border`) 안 문장 + 결과 행(`surfaceSunk`, Duotone 아이콘 + 종류·상태 + 이름 + 값 + ›). 결과 행은 대상을 **조회해 현재 상태**로 그린다
  (리마인더: 울리기 전 / 울렸음 / 완료 / 취소함(취소선) / 지움(행 없음 → "지운 알림") — 일정: 로컬 기록 / 기억: 메모 현재 내용 + 근거 줄).
- 읽기 버튼은 카드 밖 아래 왼쪽, 칩은 그 아래(마지막 비서 답에만, 새 턴이 시작되면 사라짐).
- 상단 요약 타일 3칸: 다음 알림(가장 이른 미발화 리마인더 시각) · 오늘 일정 수 · 남은 할 일 수, 누르면 할 일 탭·일정 화면(결정 2).
- 시트: 리마인더 수정(10분 미루기 / 시간 바꾸기 / 알림 취소 / 닫기), 일정·기억 결과 행은 보기 시트(원문·메모로 이동), 공통 승인 시트.
### D8 — 수정 결과를 대화에 남김
미루기·시간 변경·취소 시 코드가 만든 비서 한 줄("알림을 오후 2:06으로 미뤘어요")을 `resultKind=REMINDER` 로 저장 — 모델 히스토리에도 들어간다. 추론 없음.
### 칩 (코드 규칙만, 추론 없음)
답 칩: 마지막 비서 문장이 "A … , B … ?" 양자택일 꼴이면 정규식으로 두 칩(누르면 그 글자로 한 턴). 행동 칩: 기억 답에 충돌이 있으면 [N 기록 정리](충돌 요약이 든 기억 아카이브),
[메모 보기](메모 화면), 일정 결과면 [캘린더에서 보기](일정 화면). 규칙에 안 걸리면 칩 없음.

## 결정 (2026-10-16 사용자)
1. **취소한 리마인더는 할 일 탭에서 숨긴다** — 남은 할 일·완료됨 어디에도 없다. 채팅 카드에서만 "취소함"(취소선). 행은 남아 카드 근거가 된다.
   (할 일 목록·개수·위젯 조회가 `cancelledAt IS NULL` 을 거르게 — M1/M4.)
2. **요약 타일을 누르면 해당 화면** — 다음 알림·남은 할 일 → 할 일 탭, 오늘 일정 → 일정 화면. 고정 바로가기 줄은 없다.
3. **취소한 알림 되살리기는 이번에 넣지 않는다** — 다시 필요하면 비서에게 새로 부탁.
