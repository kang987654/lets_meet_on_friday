# 0.39.6 — 기억 검색 보강 (의미 검색 실측 · 결과 잡음)

## 목표
유의어·상위 개념 질문("내가 좋아하는 음료가 뭐지?" ↔ 메모 "커피보다 녹차를 선호함")을 지금 기억 검색(`SearchMemoryToolExecutor`)이 얼마나 놓치는지 재고, 가벼운 것부터 보강한다. 0.39.3 M4c 실기기에서 확인된 결과 잡음(`RecallConflict` 가 요약 전체의 무관한 숫자를 긁는 문제)도 함께 고친다.

## 미리 정한 결정
1. 0.39.5(음성 인식 비교)는 이번 0.39.x 에서 제외(닫기)하고 0.39.6 으로 바로 넘어간다(2026-11-01 사용자 결정).
2. 보강 순서: ① M0 질의 세트(JVM 결정적 테스트)로 기준 적중률 고정 ② M1 `RecallConflict` 결과 잡음 제거(질의·메모 대상 근처 숫자만) ③ M2 쓰기 시점 태그 보강(메모·에피소드 요약 태그에 상위 개념, 실험실 실측 선행) ④ M3 읽기 시점 질의 확장(+1~2초 비용 결정 — STOP).
3. 한국어 임베더(C3)는 이 회차에서 하지 않는다(부족이 기록되면 새 ADR 과 함께 별도 회차).

## 마일스톤 (각각: 게이트 → 커밋)
- **M0 질의 세트 (JVM, 결정적)** — 유의어·상위 개념·붙여쓰기·표현 변형 20쌍(40질의)을 메모리 안 저장소(`KnowledgeRepository`·`EpisodeRepository`)로 `SearchMemoryToolExecutor` 에 돌려,
  ① 본문 명사 태그만 있을 때 적중률 ② 상위 개념·유의어 태그가 있을 때 적중률을 측정하고 테스트(`SemanticRecallBenchmarkTest`)로 커밋해 이후 보강의 기준으로 삼는다.
  - **M0 결과 (`c97910b`)**: 20쌍 × 2질의 = 40질의(표면 변형 8 · 부분 겹침 10 · 순수 의미·상위 개념 22). 본문 명사 태그만 있을 때 전체 18/40 적중(표면 변형 8/8, 부분 겹침 10/10, 순수 의미 0/22). 쓰기 시점 상위 개념 태그가 붙어 있으면 순수 의미 22/22, 전체 40/40 적중.
- **M1 결과 잡음 (`RecallConflict`)** — 0.39.3 M4c 실기기 원문: `- (과거 대화) 2건에는 다른 값이 적혀 있습니다: 5, 214, 6043, 1122, 9087)` — 질문("자전거 비밀번호")과 무관한 사물함(214)·송장번호(6043 1122 9087)·층수(5)까지 긁혔다.
  원인: `RecallConflict.valuesIn` 이 요약 전체에서 날짜·시각 단위만 빼고 모든 숫자를 긁는다. 다중 주제 에피소드 요약이나 범용 낱말("비밀번호", "번호")로 함께 걸린 다른 주제 요약에서 무관한 숫자가 들어간다.
  고침: `RecallConflict` 가 메모에서 숫자와 범용 명사(`비밀번호|번호|암호|코드|숫자`)를 뺀 핵심 주제 두 글자 묶음을 뽑아, 요약에 핵심 주제가 전혀 없으면(`(과거 대화)` 요약) 충돌에서 빼고, 여러 문장으로 된 요약에서는 핵심 주제가 들어 있는 문장의 값 숫자만 추린다.
  - **M1 결과 (`8d78938`)**: `exp70_recall_conflict.py` 실측(충돌 답 S1 3/3·무관 숫자 불언급 3/3, 방금 대화 우선 S2 3/3). `RecallConflictTest`·`SearchMemoryToolExecutorTest` 에 다중 주제·무관 주제 요약 단언 추가, 기존 단언 수정 0건.
- **M2 쓰기 시점 태그 보강** — ① 에피소드 요약(`SummarizeEpisodeUseCase.SYSTEM_INSTRUCTION`)의 태그 지시에 상위 개념 예시(`예: 커피→음료, 치과→병원, 강아지→반려동물, 러닝→운동`)를 명시하고, ② 자동 추출(`ExtractFactsUseCase.SYSTEM_INSTRUCTION`)의 지식 줄 끝에 `[상위 분류·동의어 태그 2~3개]`를 함께 출력하게 해 `ExtractFactsUseCase.parse` 가 본문과 태그(`knowledgeTags`)를 분리하고 `EpisodeFactExtractor` 가 본문 일치 태그(`tagsFor`)와 합쳐 저장한다(다중 주제 에피소드의 다른 사실 태그가 섞이는 0.36.0 결함 ⑦b 는 그대로 방어).
  - **M2 결과**: `exp71_tag_enrichment.py` 실측 — 순수 의미 11사례에서 에피소드 요약 상위 개념 태그 적중 9/11 → **11/11**(형식 11/11), 자동 추출 상위 개념 태그 적중 0/11 → **11/11**(형식 11/11), 기존 `exp36` 합성 에피소드 6개 무손상 대조(형식 6/6·사실 회수 8/8·잡담 오추출 0). 두 지시 모두 `oneShot = true` 부수 추론이라 채팅 프리필 오버헤드 증가 **0 토큰**(`MEASURED_OVERHEAD = 1,257` 불변).
- **M3 읽기 시점 질의 확장 (STOP)** — 검색마다 +1~2초(exp37: 11/16 → 13/16). M2 결과와 함께 사용자에게 비용 대 이득을 제시하고 진행 여부를 묻는다.
- **M4 마무리** — CHANGELOG · 계획서 상태 · 로드맵.
