# 0.40.8 — 첨부 문서가 모델에 전달되지 않는 결함

## Context
argon 의 0.41.0 계획서 검토(2026-11-03)에서 나온 결함을 코드로 확인했다.

- `AssistantOrchestrator.processRequest` 는 질문을 USER 로 저장한 뒤 문서 블록(`AttachedDocumentBlock.wrap`)을 **두 번째 USER** 로 저장한다.
- `KosmosAgent.execute` 는 문서 턴에 대화를 무효화하지 않는다. 캐시된 대화가 재사용(`ConversationDecision.Reuse`)되면 런너는
  `ChatPrompt.currentInput`(문서 턴 리마인더 + 질문)만 보낸다 — **DB 기록에 있는 문서 블록은 모델에 가지 않는다.**
- 대화 미리 준비(0.39.2·0.40.7)로 재사용이 기본 경로가 됐다 — 지금 대부분의 문서 턴은 문서 없이 답할 것으로 본다(근거: 코드 정적 분석, M0 에서 재현).
- `MultimodalChatE2ETest` 는 가짜 러너가 받은 `prompt.history` 에 문서가 있는지만 봐서 이 경로를 못 잡았다.

## 결정 (계획 단계)
- **고치는 것은 "문서 턴에 대화를 다시 만든다" 하나** — `KosmosAgent.execute` 가 `request.documentText != null` 이면 `modelRunner.invalidateConversation()`
  (같은 함수의 `repeatDropped` 전례). 다시 만들면 히스토리(질문 + 문서 블록)가 `initialMessages` 로 프리필된다.
- **히스토리의 질문 중복은 그대로 둔다** — argon 안은 `PromptAssembler` 에서 질문을 빼려 했지만, 문서 턴 리마인더(ADR-028)를 정한 exp46b 는
  바로 그 배치(히스토리 [질문, 문서] + 현재 [리마인더 + 질문])로 쟀다(`scratch/lab/exp46b_doc_turn_tools.py` `ask`). 배치를 바꾸면 모델 입력이 바뀌어
  실측이 선행돼야 한다(AGENTS §2-⑤) — 문서 보관함 회차(0.41.x)에서 함께 잰다.
- 대가: 문서 턴마다 대화 재생성 프리필(기기 약 5~7초). 문서 턴은 드물고, 사용자가 답을 기다리는 시점이라 0.40.7 의 입력 경합과 무관하다.
