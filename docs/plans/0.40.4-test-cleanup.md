# 0.40.4 — 테스트 스위트 정리 (모듈 경계 · 진짜 중복 · 벽시계)

## Context
0.40.3 뒤 "불필요한 단위 테스트가 없는가"를 점검했다. 처음 초안은 중복 후보 30여 곳을 줄 번호로 들었지만, 주 개발 세션이 **본문을 하나씩 대조**해 보니
상당수는 줄 번호가 다른 테스트를 가리키거나, 하위 순수 함수와 겹쳐 보여도 실제로는 **상위 클래스가 그 함수에 올바른 재료를 넘기는지(배선)**를
검사하는 테스트였다. 이 계획서는 대조를 통과한 것만 담는다.

- **기대 효과는 속도가 아니라 유지 비용**이다. 대상 테스트는 대부분 수 밀리초짜리라 지워도 게이트 시간은 거의 줄지 않는다.
  (Robolectric 클래스의 "10초 이상"은 대개 그 JVM 의 첫 클래스가 떠안는 준비 비용이다 — 지워도 다음 클래스로 옮겨갈 뿐.)
- **이 회차는 제품 코드(`*/src/main/**`)를 바꾸지 않는다.** 바꾸는 것은 테스트 파일, `domain/build.gradle.kts`, `gradle/libs.versions.toml` 뿐이다.

## 먼저 읽을 것
1. `AGENTS.md` — 특히 §1(게이트·커밋), §2-②(테스트 단언과 예외 절차), §2-④(벽시계 금지), §3(주석).
2. `docs/plans/0.40.3-structure-cleanup.md` — 직전 회차 계획서 형식.

## 고정 제약
- **대상은 테스트 *이름*으로 지정한다** — 줄 번호는 참고용(`b5ce824` 기준)이고, 앞 마일스톤에서 파일이 바뀌면 어긋난다. 작업 직전에 이름으로 찾아 본문이
  아래 설명과 같은지 확인하고, 다르면 STOP.
- **단언 변경은 아래 "승인된 단언 변경 목록"(U1~U7)만** — 사용자 승인 후. 그 밖의 단언은 한 글자도 바꾸지 않는다.
- **옮기기(V)는 본문·단언 불변** — 패키지 선언·import·클래스 이름·`@RunWith` 등 생성부만 바뀐다.
- 스크린샷 기준 이미지 재기록 금지(화면 불변). 차이가 나면 STOP.
- 주석은 §3 — `[WHY]` 한두 문장 + 참조. 파일은 UTF-8(No BOM).

## 게이트 (매 마일스톤)
```bash
./gradlew test lintDebug assembleDebug :app:verifyRoborazziDebug
```
- 마일스톤마다 테스트 수를 센다(`app/build/test-results/testDebugUnitTest/*.xml` + `domain/build/test-results/test/*.xml`). 예상과 다르면 STOP.
- 커밋: master 직접, 한 줄 제목(예: `test: move pure domain tests to :domain (0.40.4 M1)`) + 시스템이 요구하는 공동 작성자 줄. 푸시는 사용자가 요청할 때만.
