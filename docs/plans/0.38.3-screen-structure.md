# 0.38.3 — 전 화면 구조 (0.38.2 부품으로)

## 목표
채팅 밖 모든 화면을 0.38.2 와 같은 문법으로 맞춘다 — **목록은 카드 더미가 아니라 한 묶음 안의 행**, 섹션 제목은 eyebrow 가 아니라 `subtitle`, 빈 화면은 아이콘 + 한 줄 + 행동,
삭제는 조용한 휴지통 + 되돌리기, 내부 이름·원문 시각을 보이지 않는다. 일정 화면 첫 탭을 Things 3 식 **"오늘"** 로.

## 정한 것 (2026-10-20 사용자)
1. **"오늘"은 일정 화면 첫 탭** — [오늘][월]. 오늘 탭 = 오늘 일정 + 오늘 울릴 알림 + 남은 할 일, 그 아래 "다가오는 일정"(지금 목록 탭의 이번 주를 흡수). 두 겹 분할 버튼이 사라진다. 화면 수는 그대로.
2. **행 삭제 = 옅은 휴지통(`textMuted`) + 바로 삭제 + 스낵바 "되돌리기"** — 확인 창을 없앤다(메모·할 일·프로필 항목). 일괄 삭제("완료 항목 모두 지우기")·데이터 초기화는 확인 창 유지.
3. **0.38.2 이월 채팅 수정 3건은 M0 에** — 입력바 아이콘 누르는 영역 48dp, 큰 글자에서 승인 시트 큰 시각을 제목 아래로, 위로 올려 둔 채 보내면 새 답으로 내려가기.
4. **컴포넌트 문법은 유지** — 0.38.2 컴포넌트 방향 시안(면 단계·M3 톤·묶음)은 쓰지 않기로 했다(흰 면 + hairline, 모서리 12, 주 버튼 brandSoft 그대로).

## 지금 코드에서 확인한 사실 (2026-10-20 탐색)
- 일정: [월][목록] 탭 + 목록 탭 안 [오늘][이번 주] 두 번째 분할 버튼, 일정 카드는 행마다 `kosmosSurface` + 왼쪽 색 띠, 빈 문구가 탭마다 다름("일정이 없어요."/"일정이 없습니다."),
  목록 탭 일정 색이 순번으로 돌아감(월 탭은 출처 색). `CalendarViewModel` 은 일정 유스케이스만 주입.
- 메모·할 일: 행마다 카드 + `dangerText` ✕(확인 창), 빈 화면 없음, 백업 섹션 eyebrow. 할 일 추가 줄만 `.border`(카드 문법 밖).
- 설정: 11개 `SectionBox` 가 모두 같은 톱니 아이콘(`SectionBox` 안에 고정) + 자간 넓힌 eyebrow, "(GEMMA)" 대문자, 모델 경로 원문.
- 활동 기록: M3 `Card` + 손 테두리, `event.type.name`(MODEL_RUN·TOOL_CALL…)·`yyyy-MM-dd HH:mm:ss`·영어 "Session: …" 그대로.
- 드로어: 에피소드마다 카드, "기억 아카이브" eyebrow, 아래 메뉴 2줄 + 타일 3개(캘린더·활동 기록·설정).
- 모델 관리: URL 내려받기 버튼만 손으로 만든 면(`KosmosButton` 아님). 문서 뷰어 시트 탭은 자체 칩(분할 버튼 아님).
- 기억 정리: 내부 `Card` 함수가 M3 `Card` 이름을 가림, 제안 "→ 합친 내용" 글자(테스트 셀렉터).
- 프로필 시트: 행마다 빨간 ✕, "N/MAX토큰"(기술 용어), 글자 버튼 비우기/저장. 에피소드 시트: 삭제가 맨 왼쪽 첫 자리.
- 카탈로그에 없는 화면: 모델 관리·문서 뷰어(점검·비교 대상에서 빠짐). 위젯은 Glance 라 카탈로그 밖(실기기).

## 공통 부품 (M0 에서 만들고 모든 묶음이 쓴다)
- `KosmosListGroup` — 흰 면 + hairline 한 묶음, 안의 행은 들여쓴 hairline 으로 나눈다(DESIGN Layout "목록은 행"). `KosmosListRow`(앞 아이콘·제목·보조 줄·끝 동작, 높이 ≥48).
- `SectionHeader` — `subtitle` 단계 제목(eyebrow 금지), 필요하면 오른쪽 글자 버튼.
- `EmptyState` — Phosphor Light 아이콘 32 + 한 줄 + (있으면) 행동 버튼(DESIGN "빈 화면").
- 삭제: `ic_ph_trash`(새로 받음, Phosphor Regular) `textMuted` 48dp 아이콘 버튼 + `SnackbarHost` "○○을 지웠어요 · 되돌리기"(되돌리면 같은 객체를 다시 저장 — 할 일 알림은 재예약).
- 카탈로그: 모델 관리·문서 뷰어 장면 추가(전 화면이 점검 대상이 되게).

## 디자인 스킬 쓰는 법 (마일스톤마다 — 0.38.2 에서 "끝에만 몰아 둔다"는 지적을 두 번 받았다)
시안 단계를 네 걸음으로 한다. 결과(어느 스킬에서 무엇을 가져왔고 무엇을 걸렀나)는 마일스톤 결과에 한 줄씩 남긴다.
1. **기준 잡기(시안 전)** — `mobile-android-design`(M3 목록 행·탭·바텀시트·빈 화면 관례), `awesome-design-md`(받아 둔 Apple·Notion·Intercom DESIGN.md 에서 해당 화면 패턴 —
   예: 설정 목록 묶음, 활동 기록 타임라인; 필요하면 다른 브랜드 문서를 더 받되 텍스트만·사용자 승인), `ui-ux-pro-max`(그 화면의 UX 규칙 조회 — 되돌리기·빈 화면·터치 영역 등).
2. **시안 2~3개 렌더**(Compose 장면, 지금 화면과 나란히).
3. **보여 주기 전 자체 점검** — `taste-skill` AI 티 목록(1px 상자 더미·같은 모서리·가운뎃점 줄·eyebrow·장식 점)과 `impeccable` critique 로 시안을 한 번 거르고, 걸린 점은 고치거나 함께 적어 보인다.
4. **사용자 선택 → 구현.**
M6 은 전 화면 최종 점검(impeccable critique + audit.native). `emil-*`(움직임)은 0.38.4 몫 — 이번에 생기는 움직임(되돌리기 스낵바·탭 전환)은 0.38.4 점검 목록에 올린다.

  위젯: 새 토큰·글자 단계·Phosphor 확인, "오늘" 탭과 같은 정보 순서(실기기 확인).
- **M6 점검·마무리** — impeccable(critique + audit.native) 전 화면, P1 은 이번에 고치고 나머지는 0.38.4 로. CHANGELOG 0.38.3, DESIGN.md(공통 부품·오늘 화면), 실기기 확인 목록 Q 절.
