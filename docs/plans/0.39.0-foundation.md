# 0.39.0 — 바닥 다지기 1: 모델 회귀 세트 · 체감 지연 실측 · 에뮬레이터 생성 복구

## 목표
새 기능이 아니라, 이후 판단을 믿을 수 있게 하는 장치를 만든다 — 모델 행동이 나빠졌는지 한 번에 아는 회귀 세트, 어디가 느린지의 실측 표,
휴대폰 없이 답 생성까지 확인되는 에뮬레이터, 끊기지 않는 실기기 확인 스크립트.

## 정한 것 (2026-10-29 사용자)
1. **회귀 세트는 AGENTS §2-⑤ "기록된 실험은 다시 돌리지 않는다"의 예외** — 저장소에 고정하고, 모델 입력(툴 선언·지시·리마인더·툴 결과 문구)이나
   모델 행동 가드를 바꾸는 회차마다 다시 돌린다. 일회성 실험은 지금처럼 그때그때 새로 짠다.
2. **M1 체감 지연에서 음성은 뺀다** — 음성은 0.39.4(음성 비교) 회차의 M0 에서 잰다.
3. **에뮬레이터는 A(PC GPU + 비전만 CPU) 먼저, 안 되면 B(엔진 전체 CPU)** — 둘 다 안 되면 "PC 모델 서버를 부르는 개발용 우회"는 후보로만 남긴다.

## 지금 알고 있는 것
- 0.20.2: AVD `-gpu swiftshader_indirect` 면 GPU 초기화 실패 → CPU(XNNPack)로 종단 동작, 0.2 t/s(15토큰 75초), 첫 캐시 약 3분, 앱 RAM 6.2GB.
  `-gpu auto` 면 PC GPU 로 초기화는 되지만 샘플러가 OpenCL 을 요구해 생성에서 실패. 앱의 CPU 폴백은 초기화 실패에만 걸린다.
- 0.38.2(런타임 0.18.0): 에뮬레이터에서 GPU 경로로 가 비전 인코더가 GPU 최대 할당(약 300MB)을 넘어 매번 `RESOURCE_EXHAUSTED`, 첫 커널 컴파일 약 30분.
  그때 AVD 의 GPU 모드는 기록에 없다.
- 엔진 설정은 `buildEngineConfig`(GemmaModelRunner.kt) — `backend`·`visionBackend` 는 같은 값, `audioBackend` 는 CPU 고정(ADR-016), GPU 면 FP32.
- AVD `my_phone`(x86_64, API 35, RAM 12GB)에 모델 파일이 이미 있다.
- 실기기 확인 도우미(`ui.py`·`turn.py`·`hitch.py`)는 세션 임시 폴더에만 있었다 — 기기 일련번호가 박혀 있고 승인 대기·타임아웃이 없다(0.38.9 M6: adb 멈춤·승인 시간 초과로 결과가 뒤집힘).

## 마일스톤 (각각: 게이트 → 커밋)
- **M0 모델 회귀 세트** — `scratch/lab/regression/`에 고정 세트 하나(케이스를 파일 안에 직접 둠 — 일회성 exp 스크립트에 기대지 않는다):
  툴 선택 스모크 · 저장 요청(목록 안·밖) · 사실만 말하기(앞 기록 0쌍·3쌍, 실기기 대화 모양) · "메모해 둘까요?" 뒤 긍정 · 거절 따라 하기(거절 쌍 있음/뺌) ·
  거절 되묻기 · 새 값 vs 옛 값 · 되묻기("다시 알려줘") · ISO 노출. 핵심 문장에는 표현을 바꾼 변형. 앱 가드(`RepeatRequest`·`MemoSaveIntent`·`RefusalTurns`)는
  실험실에서 같은 판정을 흉내 낸다. 결과는 세트별 점수 표 + 지난 기준값(`baseline.json`)과의 차이. 오늘 값을 첫 기준으로 커밋.
  AGENTS §2-⑤ 에 예외 규칙(결정 1) 추가.
  - **M0 결과(2026-10-29)**: 9개 세트, 첫 기준 13/13·12/12·18/18·12/12·10/12·8/8·4/4·3/4·5/6. 갈린 점 — 같은 날에도 ±1 흔들림이라 점수가 아니라 새로 깨진 항목을 읽어 판정.
- **M1 체감 지연 실측(휴대폰 — 사용자 일정에 맞춰 따로)** — 첫 실행 · 다른 앱 복귀 · 30분 쉰 뒤 첫 턴 + 바로 이은 질문 · 대화 정리 직후 · 대화 재생성 턴(거절·고친 답·앱이 연 저장·거절 되묻기) · 발열.
  측정용 임시 로그는 커밋하지 않는다. 최적화 빌드로도 한 번(0.38.9 M5).
  - **M1 결과(2026-10-29)**: 평소 첫 글자 0.7~1.9초, 대화 재생성 턴 +6~7초, 에피소드 경계 직후 질문은 요약에 막혀 17.1초. 30분 시나리오·최적화 빌드는 생략(사용자 결정).
- **M2 에뮬레이터 생성 복구** — 에뮬레이터 판별(순수 함수 + 테스트) → A: AVD GPU `host`/`auto` + 에뮬레이터면 비전만 CPU, 생성까지 되는지·속도.
  안 되면 B: 에뮬레이터면 엔진 전체 CPU(AVD `swiftshader_indirect`). 실기기 동작은 바뀌지 않는다(`EngineConfigTest` 그대로 + 에뮬레이터 분기 테스트).
  결과로 사용 안내(한·영) 에뮬레이터 절과 메모리 갱신.
  - **M2 결과(2026-10-29)**: A 실패 — 비전 문제는 풀렸지만 샘플러가 OpenCL 을 찾다 생성 실패(설정으로 못 바꿈). **B 채택** — 에뮬레이터면 처음부터 CPU, 답·툴 호출·승인 시트까지(짧은 답 20~40초).
- **M3 실기기 확인 스크립트** — 도우미를 `scratch/lab/device/`로 옮겨 저장소에 둔다(코드만 — 캡처·DB 는 커밋 안 함). 일련번호는 인자·환경 변수,
  adb 호출마다 타임아웃·재시도, 승인 시트 대기·결과 판정, "앞 화면이 우리 앱일 때만" 규칙 유지.
  - **M3 결과(2026-10-29)**: 계획대로. 휴대폰 실사용 확인은 M1 때.
- **M4 마무리** — CHANGELOG, 계획서 상태, 로드맵 갱신. 독립 리뷰는 사용자가 다른 세션에서.

## 예산·실측 수칙
이번 회차는 모델 입력을 바꾸지 않는다 — `MEASURED_OVERHEAD` 변동 없음. 회귀 세트는 앱 픽스처(`scratch/lab/fixtures/`)를 읽어 앱과 같은 프롬프트로 잰다.
