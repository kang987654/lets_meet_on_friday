# 0.41.14 앱 견고성

> **상태**: 승인 (2026-11-16) — 계획·구현·검증 Claude 한 세션.
> 정본 순서: **AGENTS.md > 이 계획서**.
> 근거: 외부 분석(2026-11-12 사용자 붙여 넣음)을 0.41.12 코드와 대조한 결과 중 "맞음"으로 판정한 것(대화 기록). 모델 입력 변경 없음 → 회귀 세트 불필요.

## 목표 (대조에서 맞다고 확인한 결함만)
1. **타임라인 중간이 사라짐** — 한 화면 세션에서 메시지가 30개를 넘은 뒤 음성을 보내거나 브리핑이 도착하면 `ChatViewModel.loadMessages()`(405줄)가
   최근 30건으로 목록을 덮어써, 앵커 뒤 ~ 최근 30건 앞이 화면에서 빠진다(앱 재시작 전까지).
2. **백그라운드에서 임베딩 엔진을 다시 올림** — `MemoryEmbedder.prepareNewNow()`(101줄)가 관리 `job` 밖(요약 스케줄러 코루틴)에서 `drain()` 을 돌려
   `onBackground()` 가 멈추지 못하고, 다음 배치의 `EmbeddingGemmaRunner.embed` 가 `engine ?: load()` 로 다시 올린다(AGENTS §2-⑥ 위반).
3. **정리 적용 중 백그라운드로 가면 결과가 틀리게 보임** — `MemoryCleanupRunner.apply()`(165줄)가 `job` 밖이라 `cancel()` 이 상태만 바꾸고, 엔진이 내려가 실패한
   에피소드 합치기가 "합치지 않음(skipped)"으로 `Done` 에 표시된다.
4. **이미지를 크기 확인 전에 통째로 읽음** — `ChatViewModel.extractImageBytes`(427줄)가 `readBytes()` 로 전부 읽은 뒤에야 관문(`ImageInputAdapter`)이 10MB 를 본다.
   파일 피커 경로(`AttachmentReader.readImage`)는 크기 검사가 없고, 공유 경로는 크기 칸이 없으면 0 으로 통과.
5. **색인 중 문서를 지우면 조각이 되살아남** — `LibraryIndexer.remove`(87줄)가 잠금·취소 없이 지우고, 파싱을 끝낸 `index` 의 `replaceChunks` 가 지운 문서의 조각·FTS 를 다시 넣는다
   (결과 화면에는 문서 이름 표로 걸러져 안 보이지만 후보 자리·희소도 점수를 차지하고 지울 방법이 없다).
6. **서랍 검색 계산이 메인 스레드** — `DrawerViewModel.searchResults`(82줄)에 `flowOn` 이 없어 바이그램 점수·500건 내적이 메인에서 돈다(체감 작음, 한 줄).

## 결정 (사용자 승인 2026-11-16)
- **D1 (3번) 중단 안내 (나)**: 적용 중 앱이 백그라운드로 가 멈추면 결과 화면 대신 "중단됨 — n건만 합침, 다시 정리하면 나머지를 볼 수 있음" 안내(새 상태·한/영 문구).
  이어 하기는 없다(다시 정리하면 계획부터 새로) — 이미 합친 것은 남는다(하나씩 저장되는지 테스트로 확인).
- **D2 복원 뒤 위젯**: 복원 직후 `widgetRefresher.refresh()` 는 같은 프로세스의 옛 DB 연결로 읽어 효과가 없다. 복원 성공 때 "다음 시작 때 위젯 갱신" 표시를 남기고,
  재시작한 앱이 시작할 때 그 표시를 보고 한 번 갱신·표시 삭제. 효과 없는 호출 자리는 이 표시로 바뀐다(`MemoryBackupStateTest` 의 단언이 걸리면 대상을 보여 드리고 확인).
- **D3 요약 타일 (가)**: 채팅 화면이 새로 그려질 때(앱 시작, 할 일·캘린더·설정에서 돌아옴) 두 갱신이 겹친다 → 새 갱신이 앞 갱신을 취소.

## 제외 (대조에서 틀렸거나 일부러 그런 것·낮은 가치)
모델 URL 경로 이탈(성립 안 함), 디버그 빌드 프롬프트 로그(의도), 정리 적용 중 채팅 대기(의도 — KDoc), 첨부 동기 읽기(E2E 계약 비용),
감사 기록 마스킹(같은 원문이 기억 테이블에 평문 — 일관성 문제, 거절 판정 결합이라 별도), 메모 수정 중 옛 벡터(한 배치 몇 초 창), 검색 쿼리 횟수·`Map` 리컴포지션(데이터 작음).

## 고정 제약
- 기존 테스트 단언 불변(AGENTS §2-②). 새 테스트로 각 결함을 먼저 재현(실패 확인) → 고침.

## 마일스톤
### M0 — 버전·계획서
- `versionName = "0.41.14"`, `versionCode = 41014`. 이 계획서.

### M1 — 타임라인(1)
- `loadMessages()` 가 이 화면 세션의 앵커 뒤 메시지를 **전부** 되읽게(개수 제한 없는 "세션·앵커 이후" 조회 — 없으면 DAO 에 추가). 30건 상한의 이유가 있는지 먼저 확인.
- 테스트: 앵커 뒤 31건 이상 + 음성 턴 뒤 목록이 전부 남는지.

### M2 — 백그라운드 경계(2·3)
- `prepareNewNow()` 를 `job` 으로 띄우고 기다린다 → `onBackground()`·`onUserActivity()` 가 멈출 수 있게. 자동 준비가 돌고 있으면 그대로 맡김(현행).
- `MemoryCleanupRunner.apply()` 도 취소 가능한 작업으로, 취소되면 `Done` 으로 덮지 않음(D1).
- 테스트: 준비 중 `onBackground()` 뒤 임베딩 호출이 더 없음 · 적용 중 `cancel()` 뒤 상태가 `Done` 이 아님.

### M3 — 입력·색인(4·5·6)
- 이미지: 상한+1 바이트까지만 읽고 넘으면 `ImageTooLarge`(보관함 `DocumentOpener.readBytesUpTo` 와 같은 방식 — 있으면 재사용).
- 색인: `replaceChunks` 트랜잭션 안에서 문서 행이 없으면 아무것도 넣지 않음(지운 뒤 끝난 색인은 버림). 뜻 벡터 준비도 문서가 없으면 건너뜀.
- 서랍: `.flowOn(Dispatchers.Default)` (테스트 디스패처 주입 방식은 testing-notes 확인).
- 테스트: 10MB+1 스트림 거부 · 지운 문서의 `replaceChunks` 가 0행.

### M4 — 마무리
- CHANGELOG 0.41.14, D2 주석, 계획서 완료. 사용 안내는 사용자가 보는 동작 변화 없음 → 그대로(이미지 너무 큼 안내가 피커 경로에도 생기면 한 줄 확인).
- 에뮬레이터 확인(선택): 30개 넘긴 뒤 음성 — 녹음이 에뮬레이터에서 안 되면 JVM 테스트로 갈음.
