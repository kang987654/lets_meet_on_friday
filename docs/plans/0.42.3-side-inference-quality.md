# 0.42.3 부수 추론 품질

> **상태**: 완료 (CHANGELOG 0.42.3). D1 (나) · D2 기각 · D3 적용(문턱 0.90).
> 정본 순서: **AGENTS.md > 이 계획서**.
> 0.42 Agentic 보강 묶음 C(0.42.0 계획서). 부수 추론 = 채팅 밖에서 도는 oneShot(대화 요약 · 사실 추출 · 대화 합치기 판정 · 메모 합치기 판정 · 주간 회고).

## 근거 (지금 무엇이 틀리나)
1. **거절을 실패로 적는다** — 승인 시트에서 사용자가 취소하면 비서 답은 평범한 문장("일정을 추가하지 않았어요.", `BaseAgent.rejectionReply`)으로만 남는다.
   요약 입력(`buildEpisodeTranscript`)은 이를 그대로 "비서: 일정을 추가하지 않았어요"로 넘겨, 요약이 "비서가 추가하지 않았다"(실패)로 쓰고 주간 회고는 그 요약을 읽어
   "제가 일정을 추가하지 못해서 아쉬우셨을 것"이 됐다(0.42.1 휴대폰 확인). 저장 거절도 같아 요약에 "사용자가 메모 저장을 요청했어요"만 남아 저장된 것처럼 들린다(0.41.7 관찰).
2. **요약과 추출이 같은 원문을 두 번 읽는다** — 요약(`SummarizeEpisodeUseCase`)과 사실 추출(`ExtractFactsUseCase`)이 같은 전사로 oneShot 을 따로 돌린다. 원문 프리필이 두 번이라
   정리 대기열(드레인)이 길고 조용한 창을 오래 쓴다(0.39.3 M4 "드레인이 요약 → 자동 추출을 연달아 돌아 조용한 창이 길다").
3. **메모 합치기 후보가 글자로만 잡힌다** — `MemoryMergeGuard.candidatePairs` 는 숫자 일치 + 본문 겹침 ≥ 0.3. 숫자가 없거나 바꿔 말한 중복("커피 대신 녹차" / "아침엔 녹차를 마셔")은 후보에 안 오른다.

## 목표
- G1 거절이 요약·추출·회고에서 "사용자가 취소함"으로 읽히게 한다(실패·요청 성공으로 쓰지 않게).
- G2 요약 + 추출을 한 번의 추론으로 합칠 수 있는지 **실측으로 정한다** — 품질이 같거나 나을 때만 바꾼다.
- G3 뜻 검색 모델이 있으면 메모 합치기 후보를 뜻으로도 잡는다(없으면 지금 그대로).

## 결정 (승인 때 정할 것)
- **D1 거절 표시 방식** — 전사에서 거절 답을 알아보고 표시를 붙인다. 후보:
  (가) 줄 앞 표지 `비서: (사용자가 승인 창에서 취소함) 일정을 추가하지 않았어요.` /
  (나) 줄을 바꿔 쓰기 `사용자: (승인 창에서 일정 추가를 취소함)` — 비서 줄 대신.
  거절 문구는 지금 `BaseAgent` 안에만 있어, 도메인 상수(`RejectionReplies`)로 옮겨 답 만들기와 전사가 같은 목록을 본다. 어느 쪽인지는 exp96 으로(추천은 실측 뒤).
- **D2 요약 + 추출 합치기** — exp97 결과로: 형식 준수·요약 보존·사실 회수·잡담 오추출이 지금 두 번 돌린 것 이상이면 합친다(한 번의 추론, 출력은 지금 두 형식을 이어 붙인 라벨 형식 또는 JSON 중 실측이 나은 것).
  못 미치면 기각하고 CHANGELOG 에 수치만. 합치면 추출 끔 설정·발열 게이트·재시도 계상은 지금 동작을 지킨다(테스트로 고정).
- **D3 뜻 후보** — 뜻 검색 모델이 설치·준비됐을 때만, 기존 후보에 코사인 상위 쌍을 **더한다**(빼지 않음). 문턱은 exp98 로(바꿔 말한 중복 회수 vs 다른 사실 오후보). 최종 판정은 지금처럼 oneShot + 숫자 보존 가드.
- **D4 휴대폰** — 회차 끝 짧은 확인(정리 한 번 돌려 회고 문장·시간) 약 10분, 미리 묻기.

## 고정 제약
- oneShot 지시를 바꾸면 실험실 실측 선행(AGENTS §2-⑤ 정신 — 채팅 앞부분이 아니라 `MEASURED_OVERHEAD` 는 불변). 실험 `exp96`~`exp98` 은 새로 짜고 출력은 커밋하지 않는다.
  입력 대화는 실제 대화 파생 데이터를 쓰지 않는다(합성 + 픽스처, `.gitignore` 규칙).
- `oneShot = true` 유지(ADR-010·014). 백그라운드 모델 로드 금지(§2-⑥) — 드레인·정리 시작 조건 불변.
- 회귀 세트: 채팅 모델 입력은 안 바꾸므로 대상 아님 — 단 거절 문구를 상수로 옮길 때 바이트가 같아야 한다(테스트로 고정).
- 기존 테스트 단언 불변(요약·추출 파서 테스트가 형식을 고정하고 있으면 D2 에서 바꿔야 할 단언을 먼저 보여 드리고 확인).

## 마일스톤
### M0 — 버전
- 0.42.3 · 42003, 이 계획서.

### M1 — 거절 표시 실측 (exp96) → 구현 (D1)
- 합성 대화 8개(일정·알림·메모 거절 / 승인 섞임 / 거절 뒤 다시 부탁해 승인), 조건 지금·(가)·(나) × 2회 → 요약이 거절을 "취소"로 쓴 수 · "실패/추가하지 못함"으로 쓴 수 · 저장된 것처럼 쓴 수, 그 요약으로 주간 회고를 만들어 같은 판정.
- 고른 방식으로 `RejectionReplies`(도메인) + `buildEpisodeTranscript` 표시. 한/영. 테스트: 전사 표시, 거절 문구 바이트 불변.

### M2 — 요약 + 추출 한 번에 (exp97, D2)
- 지금(두 번) vs 합친 프롬프트(라벨 / JSON) — exp33·exp36 의 판정 축(형식 준수, 다중 주제 분리, 사실 회수, 잡담 오추출, 상위 개념 태그) + 걸린 시간(PC 프리필·생성 토큰).
- 통과하면 `SummarizeEpisodeUseCase`·`ExtractFactsUseCase` 를 한 oneShot 으로 묶고 스케줄러(`EpisodeSummarizeScheduler`)·추출기(`EpisodeFactExtractor`) 배선 조정. 기각이면 CHANGELOG 기록만.

### M3 — 메모 합치기 뜻 후보 (exp98, D3)
- 합성 메모 40개(바꿔 말한 중복 10쌍 + 비슷하지만 다른 사실 10쌍 + 잡음) → 코사인 문턱별 회수/오후보. `MemoryMergeGuard` 에 뜻 후보 더하기(모델 없으면 지금 그대로). 테스트.

### M4 — 문서·게이트
