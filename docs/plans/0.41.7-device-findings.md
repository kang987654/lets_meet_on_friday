- **oneShot 뒤 복원 = 미리 준비로 통일** — 복원하지 않고 대화를 비운 뒤 미리 준비(입력 양보)에 맡긴다(브리핑은 0.40.6 부터 이렇게 한다).

### M2 — 앱 시작 단계 (스플래시)
엔진 Ready 뒤 바로 채팅으로 가지 않고 시작 일을 차례로: ① catch-up 으로 닫힌 **가장 최근** 앞 에피소드 요약(있을 때만, 그 요약의 기억 벡터까지), ② 오늘 브리핑(없을 때만),

- 엔진 상태가 흔들려도 앞 실행을 끊지 않는다(엔진 안 추론 취소는 0.38.6 결함 경로) — 세대 번호로 낡은 실행의 표시만 막는다.
- 시작 단계 요약은 **끝난 지 30분 넘은** 에피소드만 — 대화 예산 리셋으로 방금 닫힌 것까지 하면 잠깐 나갔다 와도 7초를 기다렸다.
- 각자 Ready 를 구독하던 테스트 3건(미리 준비·브리핑·catch-up)은 사용자 승인으로 `StartupCoordinatorTest` 로 옮겼다(동작 동일, 트리거만 이동).

### M3 — 조용한 일 정리 (복원 통일 · 요약 뒤 벡터 · 입력 양보)
- oneShot 뒤 채팅 대화 복원을 없애고 대화를 비운 뒤 미리 준비에 맡긴다(deferRestore 묶음 포함 — `EpisodeSummarizeScheduler`·`MemoryCleanupRunner`).
- 요약이 성공하면 그 요약의 기억 벡터를 같은 흐름에서 만든다(`MemoryEmbedder` 에 대상 지정 준비).
- 공용 입력 판정(`ConversationPrewarmer.onTyping` 의 신호를 앱 범위 하나로 — 예 `UserInputActivity`)을 사실 추출·밀린 요약·기억 벡터·문서 벡터(묶음 사이)가 본다. 순수 판정 `now` 주입.
테스트: 입력 직후 시작 안 함·입력이 멈추고 기다린 뒤 시작·신호 없으면 지금 동작, 복원 대신 비우기, 요약 뒤 벡터 1회.

**M3 구현에서 갈린 점 (CHANGELOG 에 옮김)**
- 복원 신호는 엔진(`ModelRunner.conversationRestoreNeeded`)이 내고 시작 단계 코디네이터가 받아 미리 준비를 건다 — 요약 드레인·기억 정리의 생성자를
  건드리지 않고 한 곳에서. `deferRestore` 묶음은 그대로 두되 묶음 끝의 일이 "복원" 에서 "신호 한 번" 으로 바뀌었다(정리 테스트 단언 무수정).
- 채팅 턴이 먼저 오면 그 턴의 첫 send 가 대화 상태를 올리므로 표시를 지운다(같은 복원 두 번 방지).
- `InputActivity.awaitQuiet` 를 250ms 씩 끊어 다시 본다 — 남은 시간을 한 번에 자면 녹음처럼 미래 시각을 넣었다가 일찍 끝날 때 수십 초 더 기다렸다(테스트가 잡음).
- 실기기 확인 목록: "대화 복원(미리 준비)" 로그가 입력이 멎은 뒤에 찍히는지(네이티브 경로라 JVM 테스트 밖).

### M4 — 간격 뒤 지난 대화 구성 (앱, M1 결정대로)
`ContextBuilder` — 지금 에피소드보다 앞이고 **마지막 메시지가 지금 기준 30분 넘게 지난** 에피소드의 원문은 지난 대화에서 빼고, **가장 최근** 그런 에피소드의 요약 한 줄
`(과거 대화) 제목: 요약` 을 시스템 지시 끝에 덧붙인다(M1 — SYS 자리, 요약 줄 토큰을 대화 예산에서 먼저 뺀다). 요약이 없으면 원문 유지(F1). 판정은 순수 함수(`now` 주입, 경계값 테스트). `RepeatedQuestions`·`RefusalTurns` 와의 순서 고정, 한·영 꼬리표.
실험실 미러 함께, 회귀 세트 실행. 테스트: 30분 경계 앞뒤, 요약 있음/없음, 간격 없음 불변, 예산에 요약 줄 포함.

### M6 — 임베딩 엔진 정밀도 (C1)
1. PC 실험실(파이썬 `EmbeddingEngine`, GPU)에서 같은 문장 세트를 정밀도 미지정 / FP32 / CPU 로 — 백엔드 간 코사인, exp76·78 계열 @1·@3. 휴대폰은 같은 몇 문장의 GPU·CPU 코사인만.
2. 차이가 있으면 GPU 일 때 `FLOAT32` 명시 + **모델 id 변경**으로 저장된 벡터 폐기·재준비(ADR-038). 속도·메모리 대가 보고. 차이가 없으면 바꾸지 않고 ADR-037 보충만.

**M6 결과 (CHANGELOG 에 옮김)** — exp83(PC, exp80 기억 세트 95질의, 파이썬 API 가 정밀도 인자를 버려 네이티브 설정 함수를 끼워 부름):
CPU @1 63·@3 92 / GPU 미지정 코사인(대 CPU) 최소 0.9823·평균 0.9973, @1 61·@3 91 / GPU FP32 0.9944·0.9995, @1 64·@3 92 / GPU FP16 = 미지정과 같은 숫자, NaN 0.
→ 미지정은 FP16 이고 조용히 조금 깎는다. GPU 에 FP32 명시 + 모델 표지 `embeddinggemma-2-740m-fp32` 로 옛 벡터 폐기·새로 준비(사용자 결정 2026-11-09 — 쓰는 사람이 한 명뿐).
PC GPU 는 WebGPU(휴대폰 OpenCL) — 휴대폰 FP32 속도·메모리는 M7.
