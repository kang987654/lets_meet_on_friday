1. 기준선: 백그라운드 일이 없을 때 입력란에 adb 로 한 글자씩 넣으며 `dumpsys gfxinfo com.kosmos.app framestats` — 느린 프레임(16ms 초과) 수·분포.

   로그 시각(`GemmaModelRunner`·`EmbeddingGemmaRunner`·요약 스케줄러)과 느린 프레임 구간을 맞춘다.

마지막에 사용자가 원인으로 지목된 상황에서 실제 키보드로 한 번 쳐 보고 느낌이 같은지 확인. 앱 프레임이 멀쩡하면 "앱 밖(키보드·시스템)" 이 결론 — 고치지 않는다.

### M1 — 실측: 간격 뒤 지난 대화 구성 (PC 실험실, GPU·FP32·litert-lm 0.19.0, 앱 프롬프트 픽스처)
합성 대화로 세 묶음을 잰다. 각 묶음을 지금(원문 그대로)·D(요약 줄)·F2·F3 으로:
1. **새 말** — 앞 에피소드가 물음으로 끝남(메모 제안·검색 결과 없음 등) + 간격 뒤 뜻 없는 말("아아 테스트", "음")·새 주제 → 앞 물음을 이어받지 않아야(툴 재호출·같은 답 없음).

### M2 — 간격 뒤 지난 대화 구성 (앱, M1 결정대로)
`ContextBuilder` — 지난 대화 후보 중 지금 에피소드보다 앞이고 **마지막 메시지가 지금 기준 30분 넘게 지난** 에피소드의 원문을, 요약이 있으면 `(과거 대화)` 요약 한 줄로 바꾼다
(같은 에피소드는 한 줄로, 여러 개면 최근 것부터 예산 안에서). 요약이 없으면 M1 에서 정한 대체(F1~F4 — F4 면 오케스트레이터가 그 에피소드 요약을 먼저 돌리고 진행 표시). 판정은 순수 함수로 분리(`now` 주입, 경계값 테스트).

실험실 미러(`kosmos_lab.py`/`run.py` 의 지난 대화 구성) 함께. 회귀 세트 실행.
테스트: 30분 경계 앞뒤, 요약 있음/없음, 이어진 대화(간격 없음) 불변, 예산 계산에 요약 줄 포함.

### M4 — 임베딩 엔진 정밀도 (C1)
1. 실측 — PC 실험실(파이썬 `EmbeddingEngine`, GPU)에서 같은 문장 세트(법령 질의·조각, 기억 문장 한·영)를 활성 정밀도 미지정 / FP32 / CPU 로 임베딩해
   코사인(같은 입력의 백엔드 간)과 exp76·78 계열 검색 점수(@1·@3)를 비교. 휴대폰은 디버그 로그로 같은 몇 문장의 GPU·CPU 벡터 코사인만.
2. 차이가 있으면 `EmbeddingEngineConfig` 에 GPU 일 때 `FLOAT32` 명시(채팅 엔진과 같은 결) — 벡터가 달라지므로 **모델 id 를 바꿔** 저장된 벡터를 자동 폐기·재준비(ADR-038 의 모델 id 규칙).
   속도·메모리 대가(FP32)를 함께 재서 보고. 차이가 없으면 바꾸지 않고 측정 결과만 ADR-037 보충에.
테스트: 설정에 정밀도가 들어가는지(GPU만), 모델 id 변경 시 벡터 폐기(기존 테스트가 있으면 재사용).
