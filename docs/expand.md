## 0. 고정 전제가 만드는 설계 원칙

모든 확장 기능은 아래 실측 제약 안에서 설계한다. 이 표의 수치는 희망이 아니라 측정값이다.

| 제약 | 값 | 근거 | 확장 설계에 주는 영향 |
|---|---|---|---|
| 대화 프리필 예산 | **1,700 토큰** (KV 4,096) | GPU FP16 숫자 깨짐 발병점 1,854~2,122 실측 (exp30, ADR-021) | 긴 문맥을 요구하는 기능은 **단일 턴에 넣지 말고 쪼개서**(청크·계층 요약·일회성 대화) 설계 |
| 일회성(oneShot) 대화 | 대화 KV 와 분리 | 전사 파이프라인으로 검증됨 (ADR-014) | **부작업은 oneShot 으로 밖에서 돌리고 결과만 대화에 넣는 것**이 확장의 기본 패턴 |
| 오디오 입력 | 최대 30초, CPU 백엔드 고정 | 공식 문서 + exp23 | 긴 녹음 기능은 30초 단위 분할 전사가 상한 |
| 이미지 입력 | 턴당 1장 (`maxNumImages=1`) | 0.14.0 명시 설정 | 다중 이미지는 순차 oneShot 처리 후 종합 |
| 발열 | 43°C 경고 / 48°C 차단 | NFR3 | 배치·백그라운드 추론은 **충전 중 + 유휴** 조건(WorkManager)이 기본 |
| 저장 공간 | 모델 3.6GB 상주 | — | 추가 모델(임베더 등)은 수백 MB 단위까지만 현실적 |
| 예산 회복 가능성 | 1,700 → 3,328 | 상류 수정(activationDataType AAR 노출 또는 FP16 수정) 대기 | 긴 문맥 의존 기능은 **E4(전제 해소 후)로 격리** — 지금 짓지 않는다 |

**정책 원칙은 유지한다** (PRD Goals — 확장에서도 불변):
오프라인 우선(G1) · 개인정보 기기 밖 반출 금지(G2) · 쓰기 작업 승인 기반(G3) · 감사 기록.

## 1. 현재 위치 (PRD 대비)

- **v0(MVP) AC1~AC8**: 전부 구현·실기기 검증 완료.
- **v1**: 웹 검색 토글(F7), Export/Import(F8), 공유 인텐트(F9), Knowledge/Task 스키마, 전체 감사, 스트리밍 응답 — 구현 완료.
- **v2 항목 중 이 로드맵에서 제외되는 것**: Windows 앱(기기 고정), 상위 모델 26B(모델 고정), 클라우드 연동(정책), 항상 듣기(정책 — §5 참조).
- 남는 v2 항목: **벡터 DB / 고도화 RAG** → Track C 로 흡수.

즉 이 문서는 "PRD 의 다음 버전"이 아니라, **v0+v1 완성 이후 S25U + Gemma 4 조합에서 갈 수 있는 모든 방향의 지도**다.

## 2. 확장 트랙 (전체 지도)

### Track A — 비서 경험 완성 (모델 능력 추가 없이 UX 로 얻는 것)

| # | 기능 | 해소하는 것 | 기술 경로 | 크기 |
|---|---|---|---|---|
| A1 | **세션 관리 UI** — 새 대화 시작·이전 대화 목록·이어가기 | 현재 "하나의 활성 세션"뿐(PRD 8-2-1). 예산 1,700 에서 대화가 금방 차므로 **의도적 새 세션**이 품질 관리 수단이 됨 | 기존 sessionId 구조 재사용, 세션 목록 화면 + 제목 자동 생성(첫 턴 요약, oneShot) | M |
| A2 | **TTS 음성 출력** — 전사→응답→낭독 왕복 대화 | P6(손 사용 어려운 상황)의 나머지 반쪽. v0 범위 초과였을 뿐 정책 비목표가 아님 | Android 온디바이스 TTS(`TextToSpeech`, 삼성 엔진) — 네트워크 불요, NFR1 유지. 응답 스트림 완료 후 자동 낭독 토글 | S~M |
| A3 | **홈 위젯 / 빠른 설정 타일** | 진입 마찰 — 비서는 여는 비용이 낮을수록 쓰게 됨 | Glance 위젯(오늘 일정 + 입력 바로가기), QS 타일(PTT 즉시 시작) | S |
| A4 | **프로액티브 아침 브리핑** | P3(분절) — 매일 아침 일정+미완료 작업+어제 메모 요약을 알림으로 | WorkManager 주기 작업(충전/유휴 불요 — 읽기 1회 추론), oneShot 요약, 알림 탭 시 해당 대화로 진입. **쓰기 없음 = 승인 불요**, 감사 기록 | M |

### Track B — 도구 확장 (function calling 표면 늘리기)

현재 툴 5종. 툴 선언은 오버헤드 실측 652토큰(5종)이므로 **툴 1종 추가 ≈ 100~150토큰** — 무한히 늘릴 수 없다. 추가는 아래 우선순위로, 총 선언 예산 **1,000토큰 이내** 유지.

| # | 툴 | 해소하는 것 | 정책 | 크기 |
|---|---|---|---|---|
| B1 | **AddReminder / ListReminders** | Task Memory(v1 스키마)의 실사용처. "3시에 알려줘" | AlarmManager + 알림. 쓰기지만 영향 반경이 앱 내부 → 승인 카드 경량화 검토 | M |
| B2 | **UpdateSchedule / DeleteSchedule** | 현재 일정은 생성만 가능 — 수정하려면 캘린더 앱으로 이동(P3 재발) | 승인 필수 + 변경 전/후 diff 를 승인 카드에 표시. 삭제는 PRD "추후 검토" 항목의 재검토 — **승인+감사 전제로 허용** 제안 | M |
| B3 | **SaveNote / SearchNote 강화** | Knowledge Memory 의 쓰기 경로가 대화에서 자연스럽지 않음 | 기존 SearchMemory 와 통합 설계 (Track C 와 연동) | S |
| B4 | **알림 요약 (ReadNotifications)** | 쌓인 알림을 "요약해줘" 한 마디로 | NotificationListenerService — **민감 권한**: 설정에서 명시 활성 + 원문 로그 금지(F9 선례) + 읽기 전용 | L |

### Track C — 기억 고도화 (v2 "벡터 RAG"의 현실적 경로)

전제 사실: 현재 mediapipe 임베더는 **영어 전용**(ADR-013)이고 APK 52MB 를 차지하는 죽은 경로에 가깝다. 이 트랙은 **mediapipe 제거와 한 몸**이다.

| 단계 | 내용 | 근거 |
|---|---|---|
| C1 | **SQLite FTS5 어휘 검색** — Knowledge/Conversation 전체를 토크나이즈(바이그램)해 색인 | 임베딩 없이 한국어 검색 품질을 즉시 올림. 추가 모델 0MB. 벡터 RAG 의 **대조군**이 되어 "임베딩이 정말 필요한가"를 측정으로 판단 가능하게 함 |
| C2 | **mediapipe 제거** | APK 152→~100MB. C1 이 대체 검색을 제공하므로 안전 |
| C3 | **한국어 임베딩 도입 (측정 후)** — C1 로 부족함이 **기록으로 확인될 때만** | 다국어 소형 임베더(예: TFLite 변환 multilingual-MiniLM 계열, 100~400MB) + sqlite-vec. 실험실(파이썬)에서 한국어 검색 품질 A/B 후 채택 |
| C4 | **대화 자동 지식화** — 세션 종료 시 oneShot 요약을 Knowledge 로 승격(태그 자동) | P2(맥락 기억)의 장기 기억 경로. 예산 1,700 에서 히스토리가 짧아진 것을 **검색 가능한 장기 기억**으로 보상 |

### Track D — 입력 확장

| # | 기능 | 기술 경로 | 제약 준수 |
|---|---|---|---|
| D1 | **문서 파일 직접 파싱** (PRD v0 제외 항목) | PDF: `PdfRenderer` 로 페이지→이미지→비전 oneShot 요약(페이지당 1장 제약 준수) → 계층 요약. 텍스트/마크다운: 그대로 청크 요약 | 페이지 수 × 추론이므로 **진행률 UI + 발열 게이트(EC7) 필수**, 대형 문서는 충전 중 권장 안내 |
| D2 | **다중 이미지 질의** | 순차 oneShot(장당 설명 추출) → 종합 턴 | `maxNumImages=1` 유지 |
| D3 | **긴 녹음 회의록** | 30초 분할 전사 → 이어붙이기 → 계층 요약 → Knowledge 저장 | 오디오 30초 상한 준수. 발열: 10분 녹음 ≈ 전사 20회 — EC7 쿨다운 경로 실측 필요 |

### Track E — 신뢰·보안

| # | 기능 | 근거 |
|---|---|---|
| E1 | **앱 잠금 (BiometricPrompt)** | 기기를 건네는 순간 대화·일정·메모가 노출 — 로컬 저장의 마지막 구멍 |
| E2 | **Export 암호화 옵션** | v1 "암호화 없음"은 의도적 결정이었으나(F8) 백업 파일이 기기 밖으로 나가는 유일한 경로임 — 옵션으로 제공 |
| E3 | **감사 뷰 고도화** | P4(통제권) — 검색·툴 호출·승인 이력을 사람이 읽는 타임라인으로 |

## 3. 단계별 로드맵

순서 원칙: **① 지금 예산(1,700) 안에서 성립하는 것 먼저 ② 측정이 설계를 결정하는 것은 측정 먼저 ③ 긴 문맥 의존은 상류 해소 뒤로.**

### E-Phase 1 — 마찰 제거 (저위험·즉시 착수 가능)

> A1 세션 관리 UI → A3 위젯/타일 → B1 리마인더 → C1 FTS5 검색

- 모두 모델 능력 추가 없음, 기존 구조 재사용, 실기기 검증 부담 낮음.
- A1 이 첫 순서인 이유: 예산 1,700 체제에서 "대화를 끊고 새로 시작"이 품질 수단인데 그 수단이 UI 에 없다 (2026-08-14 사용자 관측 — 새 세션 개념 부재).

### E-Phase 2 — 비서다움 (왕복 경험)

> A2 TTS 왕복 대화 → A4 아침 브리핑 → B2 일정 수정/삭제 → B3 메모 툴

- A2+기존 PTT = 눈 없이 쓰는 왕복 대화 완성 (P6 완결).
- B2 는 삭제 정책 재검토가 선행 — 승인 카드에 diff 표시 + 감사 기록을 조건으로 허용 제안.

### E-Phase 3 — 기억과 문서 (측정 주도)

> C2 mediapipe 제거 → C4 대화 자동 지식화 → D1 문서 파싱 → C3 임베딩(조건부) → D3 회의록

- C1(Phase 1)의 검색 품질 기록이 C3 채택 여부를 결정한다 — **"임베딩 도입"은 결론이 아니라 가설**.
- D1/D3 는 발열 실측(EC7 경로)이 설계의 일부: 몇 페이지/몇 분부터 쿨다운이 걸리는지 재고 UI 에 반영.

### E-Phase 4 — 전제 해소 대기 (지금 짓지 않는다)

> 긴 문서 단일 컨텍스트 질의, 멀티스텝 계획 에이전트(툴 루프 상한 완화), 히스토리 예산 복원

- 전부 **프리필 예산 회복(1,700→3,328)이 전제** — 상류 수정(activationDataType 노출 또는 GPU 변형에 오디오·비전 포함) 없이는 어떤 설계도 발병점 아래로 우겨넣는 편법이 된다.
- litertlm 새 릴리스가 나오면: FP16 수정 여부 확인 → exp30 재실측 → 예산 상향 → 이 페이즈 해금. **이 확인이 모든 릴리스 감시의 1순위 목적이다.**

### 의존 관계 요약

```text
C1 (FTS5) ──측정──▶ C3 (임베딩 여부 판정)
C1 ──────────────▶ C2 (mediapipe 제거 안전)
상류 수정 ─────────▶ E-Phase 4 전체
B2 ◀── 삭제 정책 재검토 (승인+감사 전제)
D1/D3 ◀── 발열 실측 (EC7 경로)
```

## 4. 명시적 제외 (이 로드맵에서 다루지 않음)

| 항목 | 이유 |
|---|---|
| Windows 앱, 로컬 네트워크 동기화 | 기기 고정(S25U) 전제 위반 |
| 상위 모델(26B)·모델 교체·파인튜닝(LoRA) | 모델 고정(Gemma 4 E4B) 전제 위반 — litertlm 도 어댑터 로딩을 노출하지 않음 |
| 클라우드 LLM 연동 | 정책 비목표 유지 (G2) |
| 완전 자율 실행 | 정책 비목표 유지 (G3) |
| 항상 듣기 (Always-on/웨이크워드) | 정책 비목표 **유지하되**, A2·A3 완성 후에도 진입 마찰이 문제로 남으면 그때 별도 재검토 문서로 — 배터리·마이크 상시 점유의 실측 없이 열지 않는다 |

## 5. 공통 완료 기준 (모든 확장 기능에 적용)

1. **토큰 회계 선행** — 기능이 추가하는 프리필(툴 선언·데이터 주입)을 설계 단계에서 산정하고, 필요 시 실험실(`scratch/lab`) `engine.tokenize` 로 실측. `TokenBudgetInvariantTest` 에 관계 고정.
2. **실기기 게이트** — 기능별 1줄 검증 시나리오를 CHANGELOG [QA/Test] 에 명시하고 통과 후 릴리스 (0.15~0.17 관례 유지).
3. **발열 경로 확인** — 추론 횟수를 늘리는 기능(D1·D3·A4)은 EC7 임계 동작을 실기기에서 관측.
4. **정책 3종 자동 점검** — 오프라인 우선 / 쓰기 승인 / 감사 기록. 새 툴은 BaseAgent allowlist + 감사 이벤트가 함께 추가되어야 한다 (F7 이중 방어 선례).
5. **기존 테스트 단언 수정 0건** 원칙 유지 — 계약 변경은 CHANGELOG 에 의도 명기.
