# QA Plan: 프로필 메모리(Profile Memory) 연동 및 프롬프트 주입

`docs/agent/implementation_plan.md`의 구현 계획을 기반으로, 기능 적용 후 안정성과 요구사항 충족 여부를 검증하기 위한 QA 계획입니다.

## 1. 검증 목표
- `SettingsDataStore`에 저장된 사용자 선호 응답 스타일(Response Style)이 LLM의 시스템 프롬프트에 정확히 주입되는지 확인합니다.
- 동적으로 주입된 프롬프트 지시문이 모델의 응답 톤앤매너에 즉각적으로 반영되는지 확인합니다.
- 기존의 대화 히스토리 및 컨텍스트 파싱 로직에 부작용(Side-effect)이 없는지 확인합니다.

## 2. 테스트 환경 및 대상
- **대상 모듈**: `ContextBuilder`, `PromptAssembler`, `SettingsDataStore`
- **테스트 환경**: 로컬 에뮬레이터 또는 디바이스 (수동 QA), 단위/통합 테스트 환경 (자동화 QA)

## 3. 상세 QA 시나리오 (Test Cases)

### TC 1: 기본 응답 스타일 (DEFAULT) 검증
- **사전 조건**: 앱 설정에서 응답 스타일이 지정되지 않았거나 기본값(`DEFAULT`)으로 설정되어 있음.
- **테스트 절차**:
  1. 채팅 화면에서 "오늘 날씨 어때?" 라고 질문을 입력합니다.
  2. 모델의 응답을 확인합니다.
  3. Logcat을 통해 최종 `ChatPrompt`의 `systemInstruction`을 확인합니다.
- **기대 결과**:
  - 모델이 기본 페르소나에 맞춰 평이하게 답변해야 합니다.
  - `systemInstruction`에 "User's preferred response style..." 문구가 **포함되지 않아야** 합니다.

### TC 2: 특정 응답 스타일 동적 주입 및 즉각 반영 검증
- **사전 조건**: 앱 설정 화면에서 응답 스타일을 "친절하게 이모지 많이 써줘"로 변경함.
- **테스트 절차**:
  1. 설정 화면에서 채팅 화면으로 복귀합니다.
  2. "오늘 날씨 어때?" 라고 질문을 입력합니다.
  3. 모델의 응답을 확인합니다.
  4. Logcat을 통해 최종 `ChatPrompt`의 `systemInstruction`을 확인합니다.
- **기대 결과**:
  - 모델의 답변에 이모지가 다수 포함되며 친절한 톤으로 작성되어야 합니다.
  - `systemInstruction` 하단에 `User's preferred response style...` 문구가 **정확히 포함**되어야 합니다.

### TC 3: 세션 도중 응답 스타일 변경 검증 (상태 동기화)
- **사전 조건**: 현재 진행 중인 채팅 세션이 존재함.
- **테스트 절차**:
  1. 채팅 도중 설정 화면으로 이동하여 응답 스타일을 "Very concise and professional" (극도로 간결하고 전문적인 톤)로 변경합니다.
  2. 기존 채팅 세션 화면으로 돌아와 추가 질문을 입력합니다.
  3. 모델의 응답을 확인합니다.
- **기대 결과**:
  - 앱 재시작 없이도 즉각적으로 변경된 톤앤매너(간결/전문적)가 새로운 답변에 반영되어야 합니다.
  - `ContextBuilder`가 매 턴마다 상태를 새로 읽으므로 즉각 반영되는 것이 정상입니다.

### TC 4: 토큰 최적화 및 Clean Architecture 의존성 점검
- **사전 조건**: 개발자 모드 또는 로그 디버깅 환경.
- **테스트 절차**:
  1. 코드 리뷰를 통해 `ContextBuilder`가 상태만 읽기 전용으로 구독하는지 점검합니다.
- **기대 결과**:
  - 불필요한 의존성이 추가되지 않아야 하며, 프롬프트 문자열만 깔끔하게 주입되어야 합니다.
