# 모델이 툴을 한 번도 부르지 않던 문제 — 자체 규약을 버리고 네이티브 함수 호출로

> 원문: **ADR-008**(0.8.0~0.8.2), CHANGELOG 0.8.x · 시기: 2026-08-06

## 한 문장
프롬프트로 가르친 자체 XML 툴 규약(`<tool_call>…`)을 모델이 **한 번도** 쓰지 않았고, 의도 분류 라우터가 "치과 예약"을 일정으로 못 알아봐 툴 자체가 사라졌다.
규약과 라우터를 모두 버리고 런타임의 **네이티브 함수 호출**(모델 채팅 템플릿에 들어 있는 정식 형식)로 바꿨다. 첫 실기기 확인은 다시 실패했고,
런타임 바이트코드와 렌더된 프롬프트를 직접 열어 남은 원인 넷을 찾아 고쳤다.

## 1. 증상 (실기기 감사 로그)
- 모델이 `<tool_call>` 을 **한 번도** 만들지 않았다. "내 자전거 비밀번호는 1234야, 기억해줘"에 평문으로 답하며
  *"저는 이 정보를 영구적으로 저장하지 않고 대화 세션 내에서 기억"* — 모델은 자기에게 툴이 있다는 것을 몰랐다.
- "치과 예약 잡아줘"는 일정 등록이 조용히 실패했다.

## 2. 원인
| 원인 | 설명 |
|---|---|
| 자체 규약 | `<tool_call>` 형식은 Gemma 의 채팅 템플릿에 없다. 4B 모델이 프롬프트만 보고 처음 보는 형식을 지키기를 기대한 설계였다 |
| 라우터 | `IntentClassifier` 가 "쓰기 키워드 + 캘린더 문맥 키워드" 둘 다 있어야 일정 에이전트로 보냈는데, 목록에 `약속`은 있고 `예약`은 없었다. 다른 에이전트로 간 요청에는 일정 툴이 선언되지 않아 **툴이 프롬프트에서 사라졌다** |
| 테스트의 한계 | 기존 테스트는 가짜 모델이 툴 호출을 "대본대로" 내므로 배관만 검증했다 — 실제 모델이 호출을 만드는지는 아무도 확인하지 않았다. 결함이 오래 숨은 이유 |

## 3. 결정 (0.8.0)
- LiteRT-LM 의 `@Tool`/`ToolSet` 선언을 대화 설정에 넘겨 **모델의 정식 함수 호출 템플릿**을 쓴다. 라우터와 에이전트 셋을 `KosmosAgent` 하나로 합치고,
  어떤 입력이든 모든 툴을 선언한다(테스트로 고정 — "일정 툴은 입력 표현과 무관하게 항상 노출된다").
- **`automaticToolCalling = false`** — 런타임이 툴을 스스로 실행하지 않게 한다. 일정·메모 쓰기는 사용자 승인 시트를 거쳐야 하므로 호출을 앱이 받아 실행한다.
- 숫자·날짜 인자의 정확성을 위해 temperature 0.8 → 0.3(실기기에서 "1234"가 342·4213·2143 으로 바뀌었다).

## 4. 첫 확인은 다시 실패 → 남은 원인 넷 (0.8.1~0.8.2)
실기기에서 `toolCalls=[]`. 문서 대신 **런타임(AAR) 바이트코드와 공식 예제 앱 소스**를 대조해 배관이 정상임을 확인하고, 렌더된 프롬프트를 로그로 열었다.

| 원인 | 고침 |
|---|---|
| 툴 스키마로 출력 문법을 강제하는 전역 플래그(`enableConversationConstrainedDecoding`)를 안 켰다 — 대화 설정 필드가 아니라 생성 시점 전역이라 옮길 때 빠졌다 | 대화 생성 직전에 켠다 |
| 파라미터 이름 `description` 이 스키마의 툴 설명 키와 충돌 — 렌더된 선언에서 **사라지고 필수 목록에만 남은** 깨진 스키마 | 이름 변경 |
| 런타임은 파라미터를 `start_time` 처럼 snake_case 로 선언하는데 앱은 `startTime` 을 읽었다 — 호출이 와도 인자가 통째로 유실될 상태 | 이름 매핑 |
| 툴 선언을 리플렉션으로 찾는데 R8 이 이름을 바꾸면 **예외 없이 빈 툴 목록** — release 빌드에서만 조용히 죽는다 | keep 규칙 |

그 뒤 툴 호출이 살아났다. 긴 대화에서 다시 안 부르는 문제는 따로 풀었다 → [04 지침의 위치](04-tool-reminder-position.md).

## 5. 대가와 남긴 것
- 런타임의 실험적 API 와 리플렉션에 기대게 됐다 — 그래서 툴 선언 조립과 엔진 설정을 순수 함수로 꺼내 단위 테스트로 고정하고, 실험실(PC)이 앱이 내보낸 프롬프트 그대로를 읽게 했다(ADR-009·017).
- 교훈을 규칙으로: 공식 예제 앱(gallery)의 주석은 다른 모델(Gemma 3n) 이야기일 수 있다 — 근거가 아니라 가설의 출처로만 쓴다(`.agents/04_MODEL_EVIDENCE.md`).

## 면접 예상 질문
- **왜 처음엔 자체 규약이었나?** — 런타임의 함수 호출 API 를 모를 때 프롬프트로 형식을 가르치는 것이 가장 쉬웠다. 실기기 로그가 모델이 그 형식을 전혀 쓰지 않는다는 걸 보여 줬다.
- **라우터를 왜 없앴나?** — 키워드 분류는 표현 하나("예약" vs "약속")에 무너지고, 틀리면 툴이 프롬프트에서 사라져 모델이 할 수 있는 일이 없다. 툴 선택은 모델에게 맡기고 실행 전에 앱이 승인으로 막는 쪽이 안전하다.
- **테스트는 왜 못 잡았나?** — 가짜 모델이 정답을 내는 테스트는 배관만 본다. 그래서 실제 모델로 재는 PC 실험실을 따로 만들었다.
