# 검색 결과가 대화 예산을 넘치게 하던 문제 — 툴 결과 500토큰·문장 단위 절단

> 원문: **ADR-020** 「코드 감사 — 맞는 예산이 잘못 집행되는 구멍 3개」·「환각 — 툴 결과 옆 근거 고정」, ADR-029(천장 산식) · 실험 exp17·exp25·exp26
> 시기: 2026-08-13 (0.15.0) — [숫자 깨짐 조사](01-gpu-digit-corruption.md) 중 코드 감사에서 발견

## 한 문장
대화 예산은 턴 시작에만 검사되는데, 위키 검색 결과는 **툴 결과로 턴 중간에** 5,000자(약 2,500토큰)까지 들어와 보호 장치 없이 모델 문맥을 키우고 있었다.
결과를 **토큰 기준 500 이하, 문장 경계에서 자르도록** 바꾸고, 한국어·숫자를 과소평가하던 토큰 추정도 실측으로 보정했다.

## 1. 발견 — "맞는 예산이 잘못 집행되는 구멍" 3개
숫자 깨짐의 원인 후보(용량 초과)를 조사하며 예산이 **실제로 집행되는 계층**을 감사했다.

| # | 구멍 | 실측 |
|---|---|---|
| (a) | 토큰 수를 `글자 수 / 3 + 1` 로 추정 — 한국어·숫자를 과소평가 | exp26: 한국어 채팅 1.48~1.70자/토큰(추정이 실제의 0.52~0.60배), **ISO 시각은 1자 = 1토큰**(`2026-08-17T10:00:00` = 19토큰) |
| (b) | 위키 결과를 한국어 **5,000자**에서 자름(예산이 6,000~8,000 이던 시절의 유물). 이 결과는 **턴 중간**에 들어온다 — 대화 정리(슬라이딩 윈도우·재설정)는 턴 시작에만 검사하고, 툴 결과를 받는 턴은 대화를 다시 만들 수 없는 턴이라 막을 장치가 없다 | 5,000자 ≈ 약 2,500토큰 — 생성 여유(768)의 3배가 예산 없이 들어감 |
| (c) | 툴 호출을 한 턴에 최대 3번 반복 → (b)를 증폭 | 최악 3 × 약 2,500토큰 |

재설정 임계값 근처의 대화 + 위키 결과 하나로 엔진 용량(4,096)을 넘는 시나리오가 성립했다. 실험실 파이썬 런타임은 용량 초과를 오류로 거부하지만(exp17),
앱 런타임은 조용히 진행하는 쪽이라 **실험실에서는 보이지 않는 구멍**이었다.

## 2. 처방 (0.15.0)
| 대상 | 처방 |
|---|---|
| (b) 결과 크기 | `TOOL_RESULT_MAX_TOKENS = 500` — 글자 수가 아니라 **토큰 수**로 자른다 |
| (b) 자르는 위치 | `SentenceTruncator` — 단어 중간이 아니라 **문장 경계**에서. 잘린 조각("…1969년에 발")은 사실처럼 읽혀 환각의 재료가 된다 |
| (c) 반복 | (b)의 상한이 자동으로 최악치를 3 × 500 으로 낮춤. 반복 상한을 넘으면 무반응 대신 말풍선을 남긴다 |
| (a) 토큰 추정 | 글자 종류 3가지로 나눠 보정(영문·공백 / 숫자·기호 / 한글 등) — 14개 표본에서 **과소평가 0건**, 과대는 최악 1.46배 |
| 관측 | 턴 종료·툴 결과 직전에 실제 토큰 수를 로그로, 4,096 을 넘으면 경고 — 넘침과 증상의 관계를 실기기에서 확인할 증거 |

함께 넣은 것 — **데이터 바로 옆의 지침**: 위키 요약에 답이 없을 때 모델이 지어내지 않게, 결과 끝에 "요약에 없으면 없다고 답하라"는 문장을 붙였다.
툴 결과 턴은 시스템 지시에서 가장 먼 턴이라 지침을 데이터 옆에 둔다. exp25: 명확한 "요약에 없다" 답이 1/3 → 3/3, 지어냄 0/3 유지
(같은 효과의 일반 정직성 규칙은 추가 효과가 측정되지 않아 넣지 않았다).

## 3. 재발 방지
- `TokenBudgetInvariantTest` — "툴 결과 예산이 생성 여유를 넘지 않는다", "툴 결과 예산에서 래퍼 예약을 빼도 본문이 남는다",
  "예산 상한에 툴 결과를 얹어도 프리필 천장을 넘지 않는다"(ADR-029: 예산 상한 2,800 + 툴 결과 500 ≤ 천장 3,328).
- `SentenceTruncatorTest` — 문장 경계 절단.

## 4. 정직한 한계
툴 결과 턴은 대화를 다시 만들 수 없는 턴이라(턴 중간에 문맥을 바꾸면 결과가 엉뚱한 대화로 간다) **완전한 예산 보장은 구조적으로 불가능**하다.
이 처방은 최악의 넘침 폭을 약 5배 줄이고, 넘침을 **관측할 수 있게** 만든 것이다.

## 면접 예상 질문
- **왜 500 인가?** — 생성 여유(그때 768) 안에 들어와야 하고, 지금은 예산 상한 2,800 에 얹어도 천장 3,328 을 넘지 않아야 한다. 둘 다 테스트가 지킨다.
- **왜 문장 단위로 자르나?** — 잘린 조각이 사실처럼 읽히면 모델이 그 조각을 근거로 지어낸다. 정보를 덜 주는 편이 틀린 정보를 주는 것보다 낫다.
- **어떻게 발견했나?** — 다른 문제(숫자 깨짐)의 가설(용량 초과)을 확인하려고 예산이 집행되는 경로를 감사하다가. 그 가설은 기각됐지만 구멍은 실재했다.
