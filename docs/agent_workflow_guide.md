# 개인(Solo) 개발자를 위한 AI 에이전트 분업 워크플로 가이드
> **문서 버전**: v2.0 | **최종 수정일**: 2026-09-02 | **상태**: Approved (승인)
> **관련 모듈**: 프로젝트 전 영역 (개발 프로세스 지침)
> v1.0(2026-07-31)의 "3-Phase 세션 분리"는 그대로 유효한 핵심 원칙이고, v2.0 은 그 위에
> **에이전트 분업**(계획=Claude, 구현=Antigravity/Gemini)을 얹은 것이다. 이전 판은 git 이력에 있다.

## 핵심 원칙 (v1.0 계승)
LLM 에이전트는 대화가 길어질수록 과거 지시를 잊는다(주의력 희석). 그래서 목적별로 **새 세션**을
열고, **저장소 안의 마크다운 문서**를 매개로 인수인계한다. 지침의 정본은 루트 `AGENTS.md` 하나다.

## 분업 (2026-09-02 결정)
| 단계 | 에이전트 | 산출물 | 근거 |
|---|---|---|---|
| ① 계획 | Claude Code (plan 모드) | `docs/plans/<버전>-<회차>.md` — 탐색·설계·결정 질문·마일스톤·게이트 | 탐색 서브에이전트 병렬 + 결정 질문에 강함. 팀 계정 주간 한도를 계획에 집중 |
| ② 구현 | Antigravity (Gemini) | 마일스톤별 커밋 + CHANGELOG | 계획서가 파일·함수·문구까지 못박혀 있어 실행 위주 |
| ③ 검수 | Claude Code (짧은 세션) | 계획 대비 diff 검토, 갈린 지점·미완 항목 지적 | 구현보다 토큰이 훨씬 싸다 |

**전제 3가지** — 이게 없으면 분업이 표류한다:
1. 계획서는 **저장소 파일**이어야 한다(Claude 의 plan 파일은 `~/.claude/plans` 에만 있어 다른 에이전트가 못 본다).
2. 프롬프트 표면을 건드리면 **실측이 계획 단계(M0)에 포함**되고 문구가 원문 그대로 계획서에 적힌다 —
   구현 에이전트가 문구를 "개선"하면 실측이 무효가 된다(`AGENTS.md` §2-⑤).
3. 구현 에이전트도 `AGENTS.md` 의 게이트(마일스톤마다 `test lintDebug assembleDebug` 녹색·한 줄 커밋·
   기존 단언 수정 0건)를 그대로 진다. `.agents/00_README.md` 가 정본을 가리킨다.

## 추천 프롬프트

### ① 계획 (Claude Code)
> "expand.md 로드맵의 다음 항목 `[C′2 …]` 회차 plan 세워줘. 결정이 갈리는 지점은 질문하고, 승인되면
> `docs/plans/<버전>-<회차>.md` 로 저장해줘."

### ② 구현 (Antigravity — 반드시 새 대화)
> "`AGENTS.md` 와 `.agents/04_MODEL_EVIDENCE.md` 를 먼저 읽어. 그다음 `docs/plans/<파일>.md` 를 읽고
> **M1 부터 마일스톤 순서대로** 구현해. 각 마일스톤마다 `./gradlew test lintDebug assembleDebug` 가
> 녹색이면 한 줄 제목 커밋(본문 없음). 계획과 갈리는 발견은 `[WHY]` 주석과 CHANGELOG 에 적고 조용히
> 바꾸지 마. 기존 테스트 단언은 수정 금지(생성부만 허용). 마지막 마일스톤은 CHANGELOG·expand.md 갱신."

한 마일스톤씩 시키는 것도 좋다 — "M2 까지 했어, M3 진행해" 처럼. 실기기 게이트는 사람 몫으로 남긴다.

### ③ 검수 (Claude Code — 짧게)
> "`docs/plans/<파일>.md` 대비 `git diff <계획 승인 커밋>..HEAD` 를 검토해줘. 계획과 갈린 지점, 빠진
> 마일스톤, 게이트 미통과, [WHY] 누락만 짚어줘."

## 요약: Context Handover
- 계획 → 구현: `docs/plans/*.md` (승인 상태)
- 구현 → 검수: 커밋 이력 + CHANGELOG 회차 항목
- 회차 종료: 계획서 상태 줄을 `완료 (CHANGELOG x.y.z)` 로 — 결정의 진실은 CHANGELOG 로 옮겨진다
