## 원칙

**세션은 저장 개념이지 UX 개념이 아니다.**

자비스·프라이데이 같은 비서상(像)과 상호작용할 때 "새 세션"이라고 말하지 않는다. 사용자에게는
하나의 연속 대화만 보이고, 뒤에서 대화가 도메인(주제) 에피소드로 자동 분절되어 각각이 검색
가능한 문서(요약)가 된다 — 과거는 히스토리 윈도우가 아니라 **검색으로** 돌아온다.

이 원칙은 예산 1,700 토큰 체제(ADR-021)와 맞물린다: 살아있는 KV 에는 현재 에피소드 꼬리만
있으면 되고, 짧은 KV 는 약점이 아니라 이 구조의 전제가 된다.

## 화면 구성 (목업 3장)

| 화면 | 내용 |
|---|---|
| A′-1 대화 | 연속 타임라인(날짜 구분선으로 과거 무한 스크롤) + 아침 브리핑이 비서 카드로 **대화에 도착** + 회수 칩 |
| A′-2 드로어 | 기억 검색바 · **프로필 고정 카드**(C′ 상시 주입 기억) · 기억 아카이브(자동 생성 에피소드 문서) · 하단 타일(캘린더/활동 기록/설정 — 아이콘 크게, 라벨 작게) |
| A′-3 에피소드 시트 | 제목/태그/요약 열람 + 수정/삭제 + 원문 대화로 이동 |

## 핵심 결정 4개

1. **세션 목록 → 기억 아카이브.** 드로어의 목록은 사용자가 만든 세션이 아니라 시스템이 자동
   분절·요약한 에피소드 문서다. 관리 대상이 아니라 열람 대상 — 단, 삭제·수정은 가능(P4 통제권).
2. **"새 대화" 버튼 없음.** 경계는 무활동 간격(30분) + 예산 리셋이 자동으로 만든다(exp33 ①이
   자연스러움을 검증). 사용자는 리셋을 의식할 필요가 없다.
3. **회수 칩(🧠)이 신뢰 장치.** 과거를 참조한 답변에는 어느 에피소드에서 왔는지 표시하고, 탭하면
   에피소드 시트를 연다. 위키 뱃지(🌐)와 같은 문법 — 단일 타임라인에서 검색 미스가 "비서가
   까먹었다"로 느껴지는 실패 모드의 완화책이다.
4. **브리핑이 대화로 도착.** 허브(오늘 탭, 기각된 시안 B)의 내용을 별도 화면이 아니라 아침마다
   타임라인에 도착하는 비서 카드로 흡수한다. "비서의 본체는 대화" 원칙과 허브 아이디어의 합집합.

## 동작 규칙

- **타임라인**: 무한 스크롤로 과거 열람(기존 날짜 구분선 재사용). 화면에 보이는 과거와 모델
  문맥은 별개다 — 모델 KV 에는 현재 에피소드만 있고, 필요하면 SearchMemory 가 회수한다.
- **분절**: 30분 무활동 또는 예산 리셋 → 에피소드 닫힘 → oneShot 요약(제목/태그/요약 3~5문장,
  날짜·숫자 원문 보존) → 아카이브 저장. 요약이 실패해도 원문 대화는 남으므로 데이터 손실 없음.
  분절 오류는 요약자가 사후 교정한다("주제가 2개면 문서 2개로").
- **검색**: 드로어 검색바와 SearchMemory 툴이 같은 색인을 쓴다 — FTS5(어휘) + 모델 양끝 정규화
  (쓰기 시점 태그·요약, 읽기 시점 검색어 확장). 임베딩은 쓰지 않는다(exp33·C3 게이트).
- **프로필(C′)**: 드로어 최상단 고정 카드. 항상 주입되는 소량 기억(상한 ~150토큰, 키-값 강제,
  오버헤드 계상). 탭하면 편집.
- **웹 검색 토글**: 입력바 안(🌐) — 질문을 쓰는 맥락 옆. 헤더 겹침 문제 원천 해소.
- **상태 표시**: 헤더 캡슐 1개(🌡·tok/s), 탭하면 상세 시트. 상시 스트립의 세로 1줄 회수.

## exp33 근거 요약

실기기 대화 픽스처 79개(메시지)로 판정 (2026-08-15, `scratch/lab/exp33_episodic_memory.py`):

| 단계 | 결과 |
|---|---|
| ① 분절 (30분 간격) | 에피소드 9개, 전부 주제 일관 (육안) |
| ② 요약 (oneShot) | 형식 준수 9/9 |
| ③ 회수 (검색어 확장 + 바이그램) | **recall@1 = 16/16** (자물쇠↔비밀번호 등 바꿔 말하기 포함) |

주의: 코퍼스 9문서라 recall@3 은 무의미(의미 있는 숫자는 @1). 질문 셋은 내용을 아는 사람이
작성. 그래도 판정에는 충분 — 개인 1인 규모에서 임베딩 없이 회수가 성립한다.

## 기각된 대안 (요지)

- **시안 A (세션 드로어)**: 세션이 UX 에 노출됨 — 원칙과 충돌해 A′로 대체.
- **시안 B (오늘 탭 허브)**: 브리핑·리마인더의 집으로는 좋으나 화면 수 최다 + 세션 목록 전제.
  허브 아이디어만 "브리핑 카드가 대화로 도착"으로 흡수.
- **시안 C (현행 골격 유지)**: 가장 싸지만 확장(브리핑·리마인더) 때 재논의 확정 — 두 번 일하게 됨.
